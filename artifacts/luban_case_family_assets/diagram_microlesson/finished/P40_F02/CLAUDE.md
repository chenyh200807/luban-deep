## 讲解页 STAGE 排版铁律（避免文字被挡 / 不按设计意图）

舞台固定 `390×462`，全部绝对定位。每个 beat 收尾（全 opacity）时**人工过一遍叠压**，重点：

1. **文字标签绝不压在深色领域对象上。** 卷材条 `#3a5168/#46627e`、深色 band 都是深底；灰字 `#5c6469`、红字 `#cf4436` 压上去＝低对比＝"被挡"。标签要么放在浅底 `#f4f3ec` 区，要么改成对象内部的白字。
   - 教训实例：`屋脊·高` 压在右侧卷材条上、`✗别写1/2幅宽` 压在深 band 上、`收头…` 长串压在女儿墙上——全部要移到浅底空白区。
2. **同一行的左右标签**（如 `错开≥1/3幅宽` / `✗别写1/2幅宽`）统一 `top`，放在对象**下方**留白带，别一个压对象一个不压。
3. **环/点状标记**（落水口、泛水根 ring）与卷材条至少留 4px 间隙，`ring.top + 18 < strip.top`，否则视觉粘连。
4. **长说明句**（>16 字）起点尽量靠左、确保整句落在浅底；箭头 `⟶` 指向对象即可，不要让句子本体压到对象。
5. **角标/坐标标签**（檐口·低 / 屋脊·高）放在对象**上方** `top` 比对象顶再小 ~18px 的位置，别和对象同高。

## 采分点覆盖矩阵（防漏铁律 · 写 beat 前必做）

> 根因复盘：F02 第一版动画漏了条件维（满粘/坡度>25%钉压/热熔阈值 R5-5/R5-6）、平行屋脊(R5-3b)、檐口800满粘(R5-10一项)。原因是**把数据 `teaching_spine` 的"四关链"当成了采分点全集**，又把"进了练习"误当"动画已覆盖"。

1. **写白板 storyboard 前，先列覆盖矩阵**：把数据 §5 R5 的**每一条 point_id（R5-1…R5-11+N1）逐行**填进表，每条标"映射到哪个 beat / 哪个 QA"。**任何一条不允许空白**，除非数据自己用 Option B 显式 curate 掉（且要照抄它给的省略理由）。
2. **`teaching_spine`（叙事主线）≠ 采分点全集。** 主线只负责组织顺序；数据 §0 的"五维/N 维"命中的每一维都得在动画里出现。标题写"四关"没关系，但条件维等采分点必须有自己的画面。
3. **beat 数按覆盖定，不按默认。** DS 允许 5–8 主讲 beat、5 分钟内可长；先数采分点、再定 beat 数，别拿"6 beat / less is more"当上限把采分点挤掉。
4. **练习覆盖 ≠ 动画覆盖。** 用户要"动画讲知识"，条件维进了 practice Q 不算讲解页已讲；两份产物各自过一遍矩阵。
5. **覆盖矩阵是 gate 的一部分**：截图/冒烟之前先核矩阵无空格，再核叠压。

## 练习防套路铁律（选项设计 · 防"按规律答对"）

> 根因复盘：F02 第一版随堂练每题正确项恒在 A 且恒为最长完整采分句——两个 tell 叠加，学生"选 A / 选最长"就能全对，根本不用理解。

1. **正确项位置必须打散**：不能恒在某一位（尤其别恒 A）。做法——源数据正确项可写在 index0，但在 `componentDidMount` 里用**固定 per-question 置换**重排 `q.opts`（评分靠 `o.ok` 标志、不靠索引，重排后反馈/解析/薄弱点自动跟着走）。整套分布要杂（如 C/D/B/A/C/D），A 出现但不主导。
2. **选项长度必须拉平**：正确项通常是"最全的采分句"、天生最长——必须把干扰项也写成**等长的完整句**（每题四项行数相当），让"选最长=正确"失效。至少有一题的某个干扰项比正确项更长。
3. **干扰项是完整采分动作、不是关键词标签**，每项配三段解析（为什么容易选/为什么扣分+错因码/正确补哪句）。
4. 验收：过一遍"只按位置 / 只按长度 能不能全对"——能就是没打散/没拉平，回炉。

## 动画原则（已验证可行，照抄）
- 动画**不用 @keyframes**；用 RAF 时间轴 + `renderVals()` 每帧算 opacity/translate/scale/width，绑到 inline style 的 `{{ hole }}`。静态位置写死在模板里。
- 每 beat 一个对象级动作，进入下一相位前用 `(1-W(后段))` 把上一对象淡出，**禁止画面累积**。
- 领域对象用纯 div（rotate/border/渐变）拼，**不画 SVG**（DC 模板编译对 raw SVG 有风险）。

## 调试坑
- `dc_html_str_replace` 改**静态位置**后，运行中的预览可能不重挂载、DOM 仍是旧坐标（`eval_js` 读到旧 top/left）。**改完务必 `show_html` 重新加载**再截图核验，别信第一帧。
- 截图前 `input[type=range]` 派发 `input` 事件驱动到目标 beat；首帧可能 stale，必要时 `delay≥600`。

## 自查为什么会失败 · 双轴验收（防"渲染成功≠正确"）

> 根因复盘：条件维漏、beat0/beat1 压字、顺逆流水两边雷同——四次都是同一病根：**自查在验"渲染成功/对象出现"，没验"正确/能读懂/真能分清 A 与 B"**；且作者与裁判同一双眼、同源盲点。

1. **建每个领域对象前，先写一句"验收判据"**：`这个对象正确当且仅当 ___`，点名它必须画出的**判别特征**。例：顺流水≠逆流水的判别量＝"搭接台阶相对水流的朝向（顺＝台阶顺流而下、水盖过；逆＝迎水唇、水钻进）"。自查只查这一句，不查"渲染了没"。
2. **对比类视觉做"证伪式"自查**：不问"它对吗"，问"一个啥都不懂的学生，能不能只看图就分清这两个？区分二者的**唯一特征**是什么、画出来了吗？"——主动去证明"这俩看着一样 / 这标签压在深底上"，证伪不了才算过。
3. **以"陌生学生"的眼睛读，且必须重载后截那个 beat**：作者的眼会自动脑补屏幕上没有的意图。改完 `show_html` 重载、截**问题所在的那个 beat**、当成第一次看。
4. **gate 两条轴都要过**：① 覆盖轴＝采分点覆盖矩阵（每条 R5 present）；② **正确轴＝逐对象判据 + 可读性**（几何/语义对不对、每个标签是否在浅底、每组对比的判别特征是否可辨）。两轴任一缺口都不进 finished。
5. **把判据喂给独立 verifier**：fork 的核验 agent 若只被告知"看看渲染"，它也只能查渲染。要把上面每个对象的判据列给它，它才可能查到语义错，而不是又一次"看着没事"。
6. 用户每抓到一个问题，先归类"哪一类自查会拦住它"，把那一类补进本清单——而不是只修当前这一处。
