## 2. 原理因果层 (L2)

> 来源谱系：镜头 A(DeepSeek) 主写；汇编层把镜头 A 的散文链收成「四段因果链 + 每段挂 point_id」，**删除/降级镜头 A 里无编译锚的力学/公式外推**(TF=LS−ES 是合理解释但无 point_id，保留为 🔵 讲解性，不充判分；2015案例1「C总时差1月延误2月」的虚构数值删除，见 §8 C2)。

**核心因果链(讲懂层骨架)：**

```
读双代号网络图(节点+箭线+紧前紧后逻辑)   kc:LEC_1A433000_P0018_001:0  🟢
   │  逻辑不全先补虚工作/调节点(2015:3—4间加虚工作)
   ▼
算时间参数 → 得每条路径长度 / 每个工作总时差   (TF 机理 🔵, 判据 kc:1A433000_056_0085:1 🟢)
   │
   ▼
判关键工作 = 总时差最小;关键线路 = 全部关键工作组成、工期=计算工期   kc:1A433000_056_0085:1  🟢
   │  多条路径并列最长 → 多条关键线路(2015/2020 印证) 🟢
   ▼
应用判读:
   ├ 延误影响判断 → 延误 ≤ 该工作总时差 ⇒ 不影响总工期(2018:电缆3月时差延误1月不影响) 🟢
   ├ 工期索赔判读 → 影响关键线路才谈工期索赔(2024:影响成立/不影响不成立) 🟢
   └ 进度调整 → 救工期只能压缩关键工作(关键工作调整为重点)  kc:1A433000_061_0092:0  🟢
   ▼
效果 = 用「关键线路 + 时差」把「该不该救/救哪条/赔不赔工期」算清楚
```

**为什么判据成立(讲解性，🔵 不充判分)：**
- **关键线路 = 最长路径 = 计算工期**：总工期由最长路径决定，所以最长路径上的工作没有机动余地(总时差最小)。
- **总时差最小 ⇔ 关键**：当计划工期 = 计算工期时，关键工作 TF=0；非关键工作 TF>0，可在自身时差内浮动而不拖总工期。
- **延误 vs 时差**：延误吃掉的是该工作的时差储备；只要延误 ≤ 总时差，最长路径不变，总工期不动 —— 这是「不影响总工期 / 工期索赔不成立」的算理。
- **压缩只压关键线路**：压缩非关键工作只增大其自身时差，对最长路径(总工期)零贡献。

> 三色提醒：因果链的**判据结论**(关键工作=总时差最小、关键线路=计算工期、延误≤时差不影响)全部 🟢 锚定(教材锚或真题锚)；链条里的**公式机理**(TF=LS−ES、FF≤TF)是讲懂用语，标 🔵，**不得作为采分点的独立 point_id 输出**。

## 3. R2 不变量 (L3)

**不变量(一句话)：**
> 凡给出双代号网络图，案例判读主链**通常**是「**算对最长路径(关键线路) → 算对时差 → 用时差判出某事件影不影响总工期**」。考的不是工艺本身，而是「**关键线路识别 + 时差计算 + 判读表达**」三件套；任一环错(线路漏一条 / 时差算错 / 判读结论与时差不符)即丢分。

换言之：判分核心 = **关键线路是否完整正确(多条要全列) + 总工期/时差是否算对 + 延误/索赔判读是否与时差一致**。三者缺一即「不妥」。

## 7. R8 动画分镜 (L7)

> 来源谱系：镜头 D(Qwen) 主写视觉隐喻 + Reveal 顺序 + Aha;汇编层**把 Aha 锚定按内容精确挂**,Reveal 顺序重排为「先读图建逻辑 → 算关键线路 → 算时差 → 判读」,对接闭环渲染器约定见尾注。

### 视觉隐喻
- **双代号网络图**：节点(圆圈带编号)+ 箭线(工作,标工作名/持续时间)+ 虚箭线(只表逻辑,虚线)。
- **关键线路**：最长路径**红色高亮**;多条并列关键线路同时高亮成两条红线。
- **总时差**：每个工作下方一根**机动条**(灰色),关键工作机动条长度为 0。
- **延误判读**：某工作延误,延误量与其机动条对比 —— 吃不光(灰条还剩)→ 绿勾「不影响」;吃光超出(红色溢出)→ 红叉「影响总工期」。
- **进度调整**：压缩红色关键线路上的工作 → 总工期标尺缩短。

### Reveal 顺序(读图 → 判读)
1. **读图建逻辑**：节点 + 箭线亮起;遇紧前不全,虚线虚工作补入(3—4 间)。(锚 `kc:LEC_1A433000_P0018_001:0`、`{2015,案例1}`)
2. **算关键线路**：各路径长度逐条算出,最长路径红色高亮(若两条并列,两条都亮)。(锚 `kc:1A433000_056_0085:1`)
3. **算总工期**：红线上工作持续时间逐项相加,算式 + 单位浮出。(锚 `{2015,案例1}`、`{2017,案例一}`)
4. **算时差**：每个工作机动条亮起,关键工作机动条=0、非关键 TF/FF>0。(锚 `{2018,案例分析(二)}`、`{2024,案例题(二)}`)
5. **延误判读**：延误量 vs 机动条对比,绿勾/红叉,联动索赔结论。(锚 `{2018,案例分析(二)}`、`{2020,案例二问题3}`)
6. **进度调整**：压关键线路工作 → 工期标尺缩短;非关键工作压缩标尺不动。(锚 `kc:1A433000_061_0092:0`)

### Aha 时刻(锚已按内容精确化)
- 学生只圈了一条红线,镜头亮出**第二条等长红线** → 「关键线路可能不止一条,要全列」。锚 `{2015,案例1}`、`{2020,案例二问题2}`
- 甲方延误工作的灰色机动条**没被吃光** → 「延误≤时差,不影响总工期,工期索赔不成立」。锚 `{2018,案例分析(二)}`
- 同一题两个事件:一个吃光红线(红叉成立)、一个没吃光(绿勾不成立) → 「影不影响关键线路才是索赔分水岭」。锚 `{2024,案例题(二)}`
- 学生想压一条非关键(灰)工作救工期,标尺纹丝不动;改压红线工作,标尺缩短 → 「救工期只能压关键工作」。锚 `kc:1A433000_061_0092:0`
