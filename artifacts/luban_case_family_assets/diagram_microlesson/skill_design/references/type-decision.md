# type-decision · ④ 判断/分支原型

- **何时选**:考点本质是"条件→分支→结论"的判断,不是顺序也不是空间。
- **代表考点**:索赔成立条件、合同价款调整、事故等级判定、危大工程专项方案审批、责任链。
- **展现形式**:判断树 / 条件卡逐条点亮(角色责任流也归此)。
- **语义色**(引用 style-guide):分支中性灰、命中分支 `--correct` 绿、被淘汰分支变暗;不成立条件 `--wrong` 红。
- **交互**:选分支作答 / 条件逐条点亮 → 结论分叉。
- **祖师爷参照**:**临床决策路径**(MedDM 临床指引树、yWorks 交互决策树)。**关键纪律(来自 COVID 决策工具 RCT)**:**决策空间小时,静态流程图 ≈ 交互式,且更透明更省**——简单考点(如"索赔成立条件")用条件卡逐条点亮即可,别过度做交互;只有分支多、路径深的才上对话式逐步。
- **schema body**:`decision[]`(待定:`conditions[]` + `branches[]` + `conclusions[]` + `role_path?`)+ 脊柱。
- **验收点(原型专属)**:角色权限/顺序不错;条件↔结论映射正确;简单题用静态、不强加交互;每分支可溯依据。
- **现状**:⚠️ **待建**。先做 1 个静态条件卡样板(索赔成立),验"先讲后选"。
