# F16 图解母题卡 · 3-5 人学员验证包

> 给创始人/运营直接拿去做小样本验证。不是技术文档。
> 一句话：**别问"觉得好不好看"，要看学员是否更快看懂、是否知道自己为什么丢分、是否愿意再看一张。**

## 0. 怎么把卡给学员看（本轮还没进小程序）

这张卡现在是一个**自包含 HTML 文件**：
`artifacts/luban_case_family_assets/diagram_microlesson/F16_qigu.rendered.html`

3-5 人测试**不必等小程序**，按易到难选一种：

- **最简单（推荐真机）**：把该 HTML AirDrop 到 iPhone，用 **Safari** 打开（Safari 能开本地文件，体验=真手机）。
- **电脑演示**：Chrome 打开该文件，按 F12 → 手机图标 → 选 390px 宽。
- 进小程序真机看属于"正式接入"，本轮不做（见 `F16_qigu_wechat_webview_eval.md`）。

测试前自查：图能看清、点"听老师讲"会自动走、点错因会跳、复测能选。可对照同目录 5 张截图。

## 1. 验证目标

1. 学员是否**更快看懂**"起鼓割补闭环"。
2. 学员是否**知道自己为什么丢分**（不是只知道"答得不对"）。
3. 是否觉得**比普通文字解析更有帮助**。
4. 是否**愿意继续看**第二张同类图解卡。

## 2. 被试对象

- 3-5 名**一建·建筑实务**备考学员。
- 尽量覆盖三型：**基础弱 / 中等 / 冲刺刷题型**各至少 1 人。
- 不要全找已经会做这道题的人（会掩盖问题）。

## 3. 测试流程（每人 8-10 分钟，单独进行）

| 时间 | 动作 | 主持人只观察不提示 |
|---|---|---|
| 第 1 分钟 | 先给纯文字版题干/解析，问"这道屋面起鼓你会怎么答" | 记学员**原始答法**（之后做对照） |
| 第 2-5 分钟 | 打开 F16 图解卡，要求：**点一次"听老师讲"、点一次错因卡、做一次复测** | 看他卡在哪、哪步突然懂、是否乱点 |
| 第 6-8 分钟 | 合上卡，让他**复述**"起鼓割补怎么写才像得分答案" | 数他能说出几个关键动作 |
| 最后 1-2 分钟 | 问反馈（见第 5 节） | 不诱导、不补救式解释 |

主持人脚本红线：不要替学员讲解、不要说"是不是觉得很清楚"、不要在复述时提词。

## 4. 观察指标（边看边记，客观）

- [ ] 能说出 **≥4 个关键动作**（放气 / 干燥 / 基层处理 / 嵌填 / 附加层 / 封严 / 检验，命中 4 个即可）。
- [ ] 能说出"**不能直接重铺**"的原因（气/水汽没排、基层没干）。
- [ ] 能理解 **附加层要盖过病害边缘 / 搭接封严 / 检验闭环** 这三件至少两件。
- [ ] 对**字幕节奏**的反应：太快 / 正好 / 太慢。
- [ ] 是否觉得**图够具体**（能对上"哪层是什么"）。
- [ ] 是否**主动**提到"错因/复测有用"。
- [ ] 是否愿意**每天 3 分钟**看这种卡。

## 5. 访谈问题（≥10，直接、不诱导）

1. 你刚才**哪一步突然看懂了**？
2. 如果没有这张图、只看文字解析，你**会不会漏掉**什么？漏哪个？
3. 你觉得这个**像老师在讲，还是像系统说明书**？为什么？
4. 那条"听老师讲"的旁白，节奏**太快、正好、还是太慢**？
5. 你点的那个错因，旁白说的"为什么丢分"**说到你心里去了吗**？还是没说清？
6. 复测做错/做对之后跳的那一下，**对你有没有用**？还是多余？
7. 图里哪一层/哪个动作你**还是没看明白**？
8. 哪里**啰嗦**、哪里**想快进**？
9. 如果这是你做错题之后弹出来的讲解，你**会不会继续做复测**，还是直接关掉？
10. 你**愿不愿意每天看 1 张**这种卡？为什么？
11. 跟你现在用的解析/网课比，这张卡**多了什么、少了什么**？
12. 如果只能改一个地方让它更有用，你想改哪？

## 7. 通过标准（硬门槛，不靠"感觉不错"）

进入量产需**同时**满足：

1. **≥3/5** 学员能复述 **4 个以上**关键步骤；
2. **≥3/5** 学员明确说**比普通解析更清楚**；
3. **≥2/5** 学员**主动**提到"错因/复测有帮助"；
4. "愿意继续使用"**平均 ≥4**；
5. "相比普通解析的提升感"**平均 ≥3.5**。

任一项不达标 → **先修体验，不量产**。

## 8. 失败分流（按症状定优先级）

| 症状 | 先改什么 |
|---|---|
| 图不够具体、对不上层 | 改 SVG 与施工构造表达（`render_card.py` 的 `roof_svg()` + 图例） |
| 旁白不像老师、像念稿 | 改 `F16_qigu.json` 的 `narration` 脚本文案（唯一旁白数据源） |
| 流程太长、想快进 | 把整段压到 45-60 秒（缩 `seconds`，砍冗余句） |
| 学员不愿点"听老师讲"/错因 | 改入口与触发方式（如默认先放 opening、错因卡更显眼） |
| 只觉得新鲜但学不会 | 回到采分点/错因结构本身，先把"得分逻辑"讲对再谈形式 |

> 所有修改仍在**同一个 `diagram_microlesson` 入口**内：JSON 改文案、render_card 改渲染。不新建第二张卡、不接 TTS、不接评分、不写 learner state，直到本验证通过。

## 9. 验证结束后的判断

- 全部达标 → 进 A 轨"正式接入方式"（发布 HTTPS + 配 web-view 业务域名 + 复用 `pages/text`），再灰度。
- 部分达标 → 按第 8 节先修，重测同一批或新一批。
- 普遍不达标 → 这条"图解微课卡"形态需要重新立题，不要硬铺 40 张。
