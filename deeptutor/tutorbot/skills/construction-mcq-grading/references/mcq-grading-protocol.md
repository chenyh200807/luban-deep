# 选择题判分协议

## 硬规则

1. 有标准答案时先判定对错，再解释。
2. 没有标准答案时不冒充正式判分。
3. 多选题必须区分漏选和错选。
4. 不展示置信度。
5. 解释必须围绕选项，不写成泛知识讲义。
6. 涉及精确规范数字、时限、比例、强度、间距时，优先使用题库解析或 RAG；证据不足不编造。

## 答案归一化

常见输入：

- `A`
- `我选A`
- `选 A 和 C`
- `ACD`
- `A、C、D`
- `正确`
- `错误`

归一化为：

```json
{
  "user_answer": ["A", "C", "D"]
}
```

## 结果状态

| 状态 | 含义 |
| --- | --- |
| `correct` | 用户答案与标准答案完全一致 |
| `wrong` | 用户答案错误 |
| `partial` | 多选题部分命中，但存在漏选或错选 |
| `explain_only` | 标准答案缺失，只能讲解诊断 |

## 边界场景

| 场景 | 处理 |
| --- | --- |
| 用户只发“我选 A”且没有 active question | 请用户补题干或重新进入题目 |
| 用户只问“这题选什么” | 使用选择题讲解，不进入阅卷 |
| 多选题评分规则缺失 | 给命中/漏选/错选，不编造精确分 |
| 用户追问“为什么 B 不对” | 回到 B 选项，解释它违反的题干条件或考点 |
| 题库解析与标准答案冲突 | 以标准答案为判定，标记内部需要复核；用户侧不展示置信度 |

## 输出示例

```text
判定结果：错误。

你选了 C，正确答案是 B。

你错在：把“专项施工方案审批”误当成“施工组织设计审批”。这类题看责任主体和程序节点，不看“谁职位高”。

B 对：专项施工方案应按规定履行审核、审批程序。
C 不对：施工组织设计不能替代专项施工方案的审批程序。

下次判断抓手：看到“危大工程/专项方案”，先想“编制 -> 审核审批 -> 专家论证 -> 交底 -> 实施验收”这条程序链。
```
