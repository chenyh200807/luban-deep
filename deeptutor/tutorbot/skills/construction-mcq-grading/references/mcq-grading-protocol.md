# 选择题判分协议

## 硬规则

1. 有标准答案时先判定对错，再解释。
2. 标准答案三路兜底（`grading_key` → `questions_bank` → 恢复失败）全部落空时，必须转入 RAG-grounded 开放裁决；禁止以“缺少标准答案”拒答。
3. `grading_source=llm_judge` 的 `is_correct=false / score=0` 是占位值，进入开放裁决前必须清空，禁止当判定输出。
4. 多选题必须区分漏选和错选。
5. 不展示置信度。
6. 解释必须围绕选项，不写成泛知识讲义。
7. 涉及精确规范数字、时限、比例、强度、间距时，优先使用题库解析或 RAG；证据不足不编造。
8. 错因只用 canonical M 系列代码（错因注册表是单一 authority），禁止发明新标签。

## 答案归一化

常见输入：

- `A` / `我选A` / `选 A 和 C` / `ACD` / `A、C、D` / `(A)` / `A.`
- `正确` / `错误` / `对` / `不对` / `√` / `×`
- 中文序号：“我选甲”“第一个”“第三个选项”
- 批量："q1 A, q3 C, q5 B""1A 2BD 3C"

归一化为：

```json
{"user_answer": ["A", "C", "D"]}
```

### OCR / 手写噪声答案

拍照或手写作答经 OCR 后常见噪声及处理：

| 噪声 | 处理 |
| --- | --- |
| 全角字母 `Ａ`、小写 `a` | 归一为大写半角 |
| 易混字符：`B/8`、`D/0`、`C/(` | 结合该题选项集合消歧；该题只有 A-D 时 `8`→`B`、`0`→`D` |
| 涂改痕迹、两个答案叠写 | 不猜最终意图，复述两个候选请用户确认 |
| 勾选/圈选符号落在选项行 | 按落点行的选项字母识别 |
| 识别结果超出选项范围（如选了 `E` 但只有 A-D） | 视为归一化失败，请用户重述 |

归一化结果存在任何歧义时，先复述确认再判分；确认成本远低于错判后的错因污染。

## 结果状态

| 状态 | 含义 |
| --- | --- |
| `correct` | 用户答案与标准答案完全一致 |
| `wrong` | 用户答案错误 |
| `partial` | 多选题部分命中，但存在漏选或错选 |
| `open_world_adjudicated` | 标准答案缺失，按 RAG 证据开放裁决，输出口径“按教材依据裁决” |

## 多选题部分得分语义

判分优先级：

1. **题库自带评分规则**（题目行或 grading_key 携带分值/规则）：严格执行。
2. **全国一二级建造师通行规则**（题库无规则、但题目明确是真题/标准考试场景时可引用并注明）：每题 2 分；全部选对得满分；**错选（选入错误项）整题不得分**；漏选时每个选对的选项得 0.5 分。
3. **规则不明**：只报命中/漏选/错选清单，不编造精确分。

部分得分判定要点：

- 先查错选：只要 `extra_options` 非空，按通行规则整题 0 分，此时不再谈“部分得分”。
- 无错选有漏选：`partial`，按 0.5 分/个计；输出时明确“漏选 X，按规则每个选对项得 0.5 分”。
- 用户问“我多选漏一个扣多少”：按上面口径回答，并注明实际批次以题库规则为准。

## 组合选项题

题干给出编号陈述（①②③④），选项是组合（如 A.①② B.①③④）：

- 判定单位是**选项字母**，不是编号——用户答 `B` 就和 `correct_answer` 比对字母。
- 讲解单位是**编号陈述**：逐条说明 ①②③④ 哪些成立、哪些不成立，再回扣为什么正确组合唯一。
- 用户直接回答编号（“我觉得①③对”）时，先映射到对应组合选项；映射不唯一时请用户选字母。
- 错因诊断绑定到错判的那条编号陈述，不笼统说“组合选错”。

## 批量判分协议

用户一次提交多题（active question 含 `items[]` 或自由文本批量作答）：

1. 逐题独立走标准兜底链；某一题缺标准答案不影响其他题的确定性判定。
2. 缺 authority 的条目单独清为待裁决状态（`is_correct=null`），随批进入开放裁决。
3. 需要 LLM 逐项裁决时，**键名必须用短序号 `idx`（1..n）**，由程序维护 `idx → 真实 question_id` 映射；禁止让 LLM 回填长复合 ID（截断错配会静默判 0）。
4. **非全覆盖即降级**：LLM 回填的 idx 集合不等于派发集合时，缺失条目不许默认判 0，整批降级重裁或对缺失条目单独重试。
5. 汇总输出按用户提交顺序排列，每题给独立判定和错因。

## 边界场景

| 场景 | 处理 |
| --- | --- |
| 用户只发“我选 A”且没有 active question | 请用户补题干或重新进入题目 |
| 用户只问“这题选什么” | 使用选择题讲解，不进入阅卷 |
| 空答 / “这题我不会，跳过” | 不判 wrong；标记未作答，给一个最小切入点（先排除明显错误项），不写回错因 event |
| 答非所问（提交内容与题目无关，如对选择题回了一段案例分析） | 不硬判对错；指出作答与题型不匹配，请确认是否答错题号 |
| 多选题评分规则缺失 | 给命中/漏选/错选 + 通行规则口径，不编造题库精确分 |
| 用户追问“为什么 B 不对” | 回到 B 选项，解释它违反的题干条件或考点 |
| 题库解析与标准答案冲突 | 以标准答案为判定 authority；内部标记需要复核（`needs_review`），用户侧不展示置信度、不渲染冲突细节 |
| 用户质疑标准答案（“这题答案有争议/官方答案错了”） | 不改判。以题库标准答案为准给判定，同时用 RAG 证据如实呈现争议点；内部记 `needs_review` 信号供题库复核，不当场推翻 authority |
| 题干明显有误（缺选项、题干截断、选项重复） | 不硬判；说明题面缺陷，请用户补全或换题，内部记题目质量信号 |
| 判断题 | 先定位题眼（“必须/不得/宜/不应/超过/不超过”），归一 `true/false` 后按单选逻辑判定 |
| 纯数字/计算型选择题 | 先用确定性计算或题库解析核对数值，再判选项；不能让自由推理直接断言数值 |

## 开放世界裁决协议（标准答案缺失）

1. 触发条件：三路兜底全部落空（active_object 无隐藏答案、grading_key 无、questions_bank 无命中）。
2. 证据先行：先按 `references/mcq-source-grounding.md` 的开放裁决证据链检索教材/讲义/规范，逐选项找支持或否证证据。
3. 逐选项裁决：每个选项给“成立/不成立 + 依据出处”；依据不足的选项如实说“现有教材证据不足以裁决”。
4. 输出口径：“本次按教材依据裁决，非题库标准答案”；不冒充正式判分，不展示置信度。
5. 写回降级：开放裁决只产生轻量诊断 event，不更新 mastery（见错因 taxonomy 写回口径）。

## 输出示例

```text
判定结果：错误。

你选了 C，正确答案是 B。

你错在：把"专项施工方案审批"误当成"施工组织设计审批"（错因：概念混淆）。这类题看责任主体和程序节点，不看"谁职位高"。

B 对：专项施工方案应按规定履行审核、审批程序。
C 不对：施工组织设计不能替代专项施工方案的审批程序。

下次判断抓手：看到"危大工程/专项方案"，先想"编制 -> 审核审批 -> 专家论证 -> 交底 -> 实施验收"这条程序链。
```

多选部分得分示例：

```text
判定结果：部分正确。

正确答案 ABD，你选了 AB：命中 A、B，漏选 D，无错选。
按通行规则本题得 1 分（每个选对项 0.5 分）；实际批次以题库评分规则为准。

你漏在：D 对应"方案实施前进行安全技术交底"这个程序环节——你记住了编制和论证，漏了交底。
```
