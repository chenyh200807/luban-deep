# 案例题讲解

适用于：案例题、实务题、简答题、背景资料题。

如果用户提交了自己的答案，并要求批改、判分、估分、漏分诊断、采分点命中或得分表达改写，应切换到 `construction-case-grading` skill；本 reference 只负责讲解答题思路，不负责结构化阅卷。

## 目标

- 先把答案骨架搭出来
- 再强化采分点与丢分风险
- 最后给迁移规则

## 输出要求

- 先给完整作答框架，不要先铺理论
- 明确区分：
  - 答题骨架
  - 必拿分 / 采分点
  - 易丢分
  - 迁移规则
- 如果题干包含背景资料，优先按“题干事实 + 规范要求 + 结论”组织
- 不要把“易错点”拆散到正文里，集中写一次

## 按问法类型组织答案

案例题问法决定答题结构，先识别问法再套结构：

| 问法 | 答题结构 |
| --- | --- |
| 指出不妥之处并说明理由 | 逐条"不妥之处：…；理由：…"，一事一条，不合并 |
| 分析原因 | 按"直接原因 → 管理原因"分层，每层 2-3 条 |
| 补充/完善做法 | 按标准流程顺序补，缺哪步写哪步 |
| 应如何处理/处置 | 按"先停止/报告 → 再整改 → 后验收"时序写 |
| 计算类 | 先列公式与依据，再代入，最后写结论句 |

## 背景资料映射法

- 背景资料里的每个异常细节（数字、做法、人物动作）几乎都对应一个采分点；讲解时逐个点名"这句话埋的是什么考点"
- 没有被问到的背景细节不要展开，避免讲成整章讲义
- 涉及规范要求时标注来源；检索不到时按"通用考点口径"声明降级，不编条文号

## 应试取向

- 用阅卷语言写“采分点”
- 若存在标准流程，优先按流程顺序作答
- 若存在多个问点，按问点逐条对应，不要混答
- 提醒学员：阅卷按点给分，宁可分条多写判断句，不写大段散文
