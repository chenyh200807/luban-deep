# 阅卷协议

## 评分硬规则

1. 每个 full / partial 必须能引用用户答案原文。
2. 没有证据句，不给 full。
3. 口号化表达不能替代程序性采分点。
4. `curated_rubric` 不得新增 Rubric 之外的给分项。
5. `projected_rubric` 必须说明采分点来自标准答案/解析/关键词推演，且每个采分点带 `source_fields` 溯源。
6. `open_skill` 不硬装标准分，只做提分诊断；但仍要抽采分点、给漏点和改写，不许拒答。
7. 计算题没有确定性计算或标准解时，不把 LLM 计算当最终 authority。
8. 采分点、关键词、关键数字必须能溯源到题库/教材/讲义/规范原文；模型常识不构成采分依据。
9. 错因只用 canonical E 系列代码，禁止发明新标签。

## 用户答案证据句

把用户答案拆成短 span：

```json
[
  {
    "span_id": "s1",
    "text": "施工单位未编制专项方案",
    "possible_concepts": ["专项施工方案", "危大工程"]
  },
  {
    "span_id": "s2",
    "text": "应加强现场安全检查",
    "possible_concepts": ["安全检查", "口号化表达"]
  }
]
```

OCR / 手写答案的切分补充：

- 先按问号/序号/换行归位到子问，再切证据句；OCR 把两个子问答案串成一段时按语义重新断句。
- 同义词、错别字、OCR 形近字（如“监理”识别成“管理”）不直接判 miss：含义可辨认时按实际含义匹配，并在 reason 中注明按上下文恢复；无法辨认时如实说该句无法识别，不猜。
- 专业关键词被 OCR 拆碎（“专项 施工方 案”）时合并后匹配。
- 整段 OCR 质量过差无法切出证据句时，不硬判，请用户重拍或打字补充，本轮只给可见部分的诊断。

## 采分点匹配状态

- `full`：核心含义和关键词完整命中。
- `partial`：方向正确，但缺少关键词、程序环节或理由。
- `miss`：未表达该采分点。
- `wrong`：表达与采分点相反。
- `irrelevant`：答案内容与该采分点无关。

写入结构化结果（`CaseRubricItemResult.status`）时收敛为 `full | partial | miss`；`wrong` / `irrelevant` 归入 `miss`，差异写进错因 `diagnosis`（`wrong` 通常配 E07/E10，`irrelevant` 配 E05/E01）。

## 逐采分点 LLM 裁决协议

需要 LLM 批量逐项裁决（采分点多、答案长）时：

1. 派发键必须是短序号 `idx`（1..n），程序维护 `idx → rubric item` 映射；禁止用长复合 ID（如 `case_2021_q2::sub3::r07_v2`）当回填键——截断错配会静默判 0。
2. **非全覆盖即降级**：回填 idx 集合不等于派发集合时，缺失项不许默认 miss/0 分，整批降级重裁或对缺失项单独重试。
3. 每个回填裁决必须带用户原文证据片段；无证据的 full/partial 一律拒收降为 miss 待复核。
4. 裁决结果回填后仍由确定性规则做最终聚合（分数求和、penalty rule），LLM 不直接产出总分。

## 产品话术

不要说：

- “低置信度”“AI 不确定”“可能不准，你自己判断”

应改为：

- “本次按采分点推演阅卷。”
- “这题缺少完整标准采分表，因此不硬估标准分，先给提分诊断。”
- “这个分数区间适合训练使用，正式标准分以后续校准 Rubric 为准。”

每一档的口径声明（与 SKILL.md 降级阶梯对应）：

| 模式 | 必须出现的声明 |
| --- | --- |
| `curated_rubric` | “按标准采分点评分”；给明确得分 |
| `projected_rubric` | “本次按采分点推演阅卷”；给预计分或得分区间，并说明采分点来源字段 |
| `open_skill` | “本次按提分诊断处理”“本次不硬估标准分” |

## 边界场景

| 场景 | 处理 |
| --- | --- |
| 用户只发答案 | 不硬打分；请补题干，可先给表达诊断 |
| 用户发完整题干和答案 | `projected_rubric` 或 `open_skill` |
| 题库题但缺 Rubric | 从答案/解析/关键词生成投影 |
| 空答 / “这题我不会” | 不判 0 分污染错因画像；标记未作答，给该题的最小作答框架（先答问法、再列程序链），不写正式错因 event |
| 答非所问（答案明显回答的是另一道题/另一个子问） | 不逐采分点硬扣；先指出作答与问法不匹配（错因 E05），确认题号后再判 |
| 一题多个子问 | 先把答案归位到各子问，逐子问独立选档、独立判分；禁止用子问 B 的采分点扣子问 A，也禁止把整段背景当一个问题判 |
| 跨章节综合案例（如质量+安全+合同混合） | 采分框架按子问各自的考点检索证据，分别溯源；错因按子问分别归因，不汇总成一个标签 |
| 题目是网络计划/费用索赔/流水节拍计算 | 优先标准解或确定性算法；核对用户的过程量（工期、时差、费率）而不只对最终数；没有标准解时只给过程诊断（错因 E09 只在确有计算错误证据时记） |
| 题干有误或存在争议（背景数据自相矛盾、官方答案有争议） | 不硬judge；按题库标准口径判分，同时如实呈现争议点，内部记需复核信号，不当场推翻题库 authority |
| 用户追问某一句为什么不给分 | 回到对应采分点，解释缺失含义和得分写法 |
| 用户要求下一题 | 优先题库同错因同考点题，生成题需 validator |
| 用户对得分不满要求改分 | 不因施压改分；重新核对证据句，确有漏判则修正并说明，否则维持并解释 |

## 得分表达改写标准

- 分点作答。
- 关键词前置。
- 少写空话。
- 先回答题目问法，再补理由。
- 对程序类考点按流程顺序写：识别 -> 编制 -> 审核/审批 -> 论证 -> 交底 -> 实施 -> 检查/验收 -> 整改闭环。
- 改写里出现的每个关键词都应来自采分框架或溯源证据，不引入新的未溯源知识点。
