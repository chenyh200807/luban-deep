**五方收敛（强共识）**：① **都判"非一个病"**（3 个机制不同的病）；② R3+R4=内容真相/编造残留、R6=展示层（全一致）；③ **R2 最危险**——DeepSeek 与 Qwen **各自独立**点名 R2（"答非所评的根本性背叛，无法靠用户自查纠正"）。

**两条异源增量洞见（两个同厂 Claude 窗口都没拆出来的，这就是多模型评审的价值）**：
- **DeepSeek**：R1+R2+R5 共享同一第一性事实——**判分/检索/统计必须锚到学生当前会话的"正确实体 + 当前题面"**（正确题目ID/版本/顺序/选项面）。它们是窗口A 已收口的"是否判分（触发维度）"的**姊妹维度（判哪道题的哪个面）**，同一单一权威病的不同维度，应作一族协同修。
- **Qwen3-max**：进一步把 **R2 从对象绑定里拆出来**——R2 的根在**上游意图层**：系统把"判我粘的简答题"误读成"生成一道新题"（**判分 request → 生成 request 的意图误路由**），**先于**也**区别于** R1/R5 的对象/题面绑定。Qwen 的"意图-题面-判分三元一致性"比 DeepSeek 的二元"实体绑定"更细。R2 这条恰是窗口A 收口（"是否提交作答"）的**意图维度姊妹**，连到既有 memory `mcq-grading-routing-gap`（orchestrator 能力选择：判分 vs 生成）。

## 2. 综合根因图：3 个病，不是一个；但 R1/R2/R5 是同族

```
病① 判分单一权威碎片化（fast-path-as-authority）—— 路由病；四维(Qwen+DeepSeek 揭示)
   ├─ 触发维度「是否进入判分」      …… ✅ 窗口A Steps 1-5 已 live GO
   ├─ 意图维度「判分 vs 生成 vs 答疑」 …… ❌ 残留 R2 上游(简答判分被误路由成生成)  ← Qwen 拆出
   ├─ 对象维度「判哪道题」          …… ❌ 残留 R2 下游 / R5(回指串题+统计漏计)
   └─ 题面维度「哪个选项面」        …… ❌ 残留 R1(选项重排用题库字母)
病② 内容真相病（fabrication / 系统没有正确内容）—— 内容病
   ├─ 硬事实数值「4000万/罚款比例」 …… ✅ 窗口B 闸-4 已修
   └─ 残留:sycophancy 附和臆造叙事(R3) + 无答案仍编采分点(R4)  …… ❌（升级"事实-叙事双闸"）
病③ 展示层病（内部标记/脚手架泄露,R6）—— 与判分 authority 正交,低优先 …… ❌
```

**五方一致结论:不是一个病,是 3 个机制不同的病。** 但病①残留高度集中在「判分锚定单一权威」一族(意图/对象/题面三维),是窗口A 已收口的"触发维度"的姊妹——应作**同一族协同修**(同一第一性:判分永远锚到学生**真实指认的题**的**当前题面**),即使落点机制不同,避免逐个打补丁后又冒第四个锚定 bug(whack-a-mole)。**修序由上游到下游**:先意图(R2:别把判分误成生成)→ 再对象(R2下游/R5:锚真实题)→ 再题面(R1:投影到当前面)。

## 3. 联合修复计划（按 信任伤害 × 独立性 × 已覆盖度）

### P0-a 病①锚定维度·题面（R1 选项重排）— **窗口B 主修，最独立单点**
- **one fact**：MCQ"哪个选项正确"在**学生当前题面**上的字母是判分比对唯一面。
- **修法（less-is-more，接通 dormant island）**：判分 `answers_match`（question_followup.py:705/750）前，把 `correct_answer`（题库面）与学生作答**都投影到当前题面**——**消费已存在的** `_project_to_query_option_surface`（historical_questions.py:262），不新建识别层、不加"选项重排"探测正则。
- **why P0**：确定性复现 + 把答对判错=倒诬学生（信任摧毁性最强）+ 独立单点 + 收权没碰它。

### P0-b 病①意图+对象维度（R2 简答被MCQ抢占 + R5 串题/统计）— **窗口A 主修（收口姊妹维度）**

> **✅ R2 意图维度 DONE + live GO 3/3（2026-06-24，commit 1206e1a9c）**：专家团(5区域/47decider)+指挥官定根因=`intent-fast-path-as-authority`（过宽练题检测器无对手"一票定生成"，缺"作答在场→判分优先"门）。收口=复用已存在判分单一权威（submission 收口的同款谓词）+放宽 `_looks_like_free_text_case_grading` 的 `CONTEXT AND ACTION` 硬门为"案例壳 ∨ 作答payload在场"正向并集。live：R2 简答求判分→真判分 3/3，"再出3题"→生成 3/3（零误伤）。
>
> **✅ R5（对象维度·回指串题/批次统计）= 已被先前合并工作收口，live 验证不复现（2026-06-24）**：按铁律先复现再修，发现 R5 在当前 test2 **已正确**——回指"最开始那道题"3/3 正确召回第1题（无串题/无编造）、带题号批量作答全判分且汇总计数对（无漏计）、多题单答无题号→诚实 ambiguous 守卫（不凭空判分）。这是 memory `single-authority-collapse-playbook` 记录的 E1（召回错题）/E8（批量塌缩）/task#14（序数 review）已合并 object-continuity 收口的功效。eval 的 g1 T9/g3 T14 系更早 base 或非确定性实例。**R5 不需新代码,标 verified-fixed。**
- **one fact**：用户粘贴/指认的真实题是唯一判分对象与判分意图；"判我这道题"不得被系统改写成"生成一道新题"，bot 为练习生成的题进**练习槽**不得进**判分目标槽**；回指/统计锚到真实活跃题。
- **修法（Qwen 的两层，从上游到下游）**：
  - **意图层（Qwen 拆出，先修）**：用户显式求批改一道真实题时，意图必须锁定 `route_to_grading`，**禁止**被改写成 `route_to_generation`——连到既有 `mcq-grading-routing-gap`（orchestrator 能力选择）+ 窗口A 收口的意图维度（判分 request 单一权威）。生成与判分路径解耦。
  - **对象层（下游）**：判分对象 `active_object` 的 **writer 收口**（窗口A Step5 已对"是否判分"单一 chokepoint 收口，此处补**意图+对象**维度单写者）——生成题不覆盖用户真题为判分目标；回指解析锚到 history 真实题（复用 is_unresolved_switch 单一权威）。不加第二套"判分对象"decider。
- **DeepSeek + Qwen 都判 R2 最危险**（"答非所评，无法靠用户自查纠正"）→ 与 R1 并列 P0，**实务上 R2 略先**（信任伤害最重）。
- **协同点**：窗口A 已有 active_object 收口边界（task#20 簇A），R2/R5 作为该收口的**意图+对象维度增量 Step**，避免与窗口B 的 R1（题面维度）撞，也避免另起第二套锚定权威。

### P1 病②残留（R3 sycophancy + R4 编采分点）— **窗口B 主修（闸-4 域）**
- **R3**：先 live 复现 g5 质疑轮，验闸-4 是否已挡"2020修订罚款8%"；残留 sycophancy 在单一 `GROUNDING_CLAUSE`（core/grounding.py）加一句"不得附和/背书学生未经证据核实的事实断言"（单点，不在 directive 再加）。
- **R4**：自承"无标准答案"后**禁编采分点**——走 open-world RAG-grounded 判分或诚实 hedge（"这道题我没拿到标准采分点，按规范/教材给你方向性判断"），禁硬给配分。归闸-4/grounding 域。

### P2 病③（R6 展示层）— 低优先
- 〔N〕流式 delta 剥离有跨 delta 边界复杂度（终态/历史已干净）；meta 脚手架泄露收口到单一公开 sink。产品取舍，排最后。

## 4. 红线（三方共识）
- **别把病①②③合成一次"判分大收口"**——机制不同，合并=巨型改动 + 两窗口在飞收权互撞。
- **R1 接通已存在投影权威**（dormant→consumed），不新建识别层；**R2 收口 active_object 单写者**，不加第二套判分对象 decider；**R3/R4 靠 grounding 单一 clause + 闸-4**，不加更多对抗 LLM（同源盲点已证）。
- **每条修完必 live ≥3 轮一致**（eval-design）；unit 绿 ≠ live 工作（本轮已多次实证）。
- **两窗口分工**：B 修 R1（题面，最独立）+ R3/R4（内容域，它的闸-4 主场）；A 修 R2/R5（对象维度，它的收口姊妹）。各自单点，先对齐 active_object 收口边界再动 R2，防互撞。

## 5. 一句话总账
- **发现**:~10 类 + 7 条编造 | **已修 live 验证**:凭空判分(A)+ 硬事实数值(B) | **残留**:R1/R2/R5(判分锚定·同族)+ R3/R4(内容真相残留)+ R6(展示层)。
- **根因**:**五方一致——3 个病不是一个**;但残留集中在「判分锚定单一权威」一族(意图 R2 / 对象 R2下游·R5 / 题面 R1 三维),是病①已收口"触发维度"的姊妹,应协同修非各打各。
- **多模型评审增量**:DeepSeek 揭示 R1/R2/R5 同族(实体绑定);Qwen3-max 进一步拆出 R2 是**意图误路由**(判分被当生成)先于对象绑定。两个同厂 Claude 窗口都没拆到这一层——**这就是引第三、四个异源模型评审的价值**。
- **分工**:窗口B 接 R1(题面,最独立单点)+ R3/R4(内容域);窗口A 接 R2(意图+对象,信任伤害最重,先动)+ R5。各自单点 + live ≥3,先对齐 active_object 收口边界防互撞。
