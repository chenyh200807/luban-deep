## 执行者原推荐（已被否决）：方向 C「混合分层」

核心理由：

1. **可信度成为前注意视觉属性**——trust_level 编码为卡片边框色温（暖橙发光=A 级可信，灰冷熄火=C 级降级），老板扫一眼就能看出哪个数字"熄火"，不依赖阅读徽标文字。这是"数据可信度即 UI"主轴的最强表达。
2. **契约即设计**——点击任意指标弹出的语义卡（口径公式 + 三源数值 + 对账 verdict）直接由 `BI_METRICS` 注册表驱动：注册表外的标签连语义卡都没有，UI 层面自动暴露 F5 类问题，设计本身成为治理的强制机制。
3. **是 A 的超集而非另起炉灶**——保留暖色大屏叙事与全部既有 ECharts 资产，增量为全局控制条、可信度徽标、语义弹卡、边框色温映射四件套，实现成本可控。

## 从落选方向带走的要素（随 A 案调整）

- 取 B 的**指标台账视图**作为 ops tab 的"数据治理"子页（P3 对账告警的落点），不作为全局默认形态。
- A 案自带的**对账趋势图**（Langfuse vs BI 双线 + 缺口带 markArea）进入 overview 成本区。

## P4b/P4c 执行约束

- KPI 可信度徽标的数据结构 = P2 扩建后的 `BIMetricDefinition` 契约 payload（trust_level/数据源/新鲜度/measured-estimated 分量），**UI 不自行聚合**（合流规则：冲突时数据线赢）。
- 实现期严守 Web 内存护栏；dev server 不挂 agent 名下。
- P4c 验收：上 test2 后用对账 harness 复测"UI 显示值 = 治理后真值"。
