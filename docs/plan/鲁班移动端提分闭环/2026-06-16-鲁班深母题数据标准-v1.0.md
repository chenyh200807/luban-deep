# 鲁班深母题数据标准 v1.0

> Status: **Proposed / 设计天花板锁定稿**。本标准锁定「深母题集」的数据资产设计与所有权边界,作为后续 schema 登记、F16 样板编译、运行消费的唯一施工蓝图。
> Date: 2026-06-16
> 基座:[深母题 schema v2(两对象)](2026-06-16-luban-deep-archetype-asset-schema-v2.md) · [移动端提分闭环 PRD v1.3](2026-06-11-luban-mobile-scoring-loop-ui-ux-product-plan.md) · [母题资产生产计划](2026-06-11-luban-mobile-case-family-asset-production-plan.md)
> **重要边界**:本标准**只锁设计**。它**不授权量产**——扩到第 2 个母题包 / 建编译自动化 / 扩团队,全部硬闸在 §9 的留存证明之后。

## 0. 本稿与 Codex 红队对抗的关系(透明记录)

2026-06-16 经 Codex(GPT-5.5)红队对抗,最狠一刀:**"把留存问题误判成内容结构问题,在没人证明会回来前抢先挖护城河"**。产品负责人裁决:**仍先写本标准(锁设计,成本低),但留存实验并行、且不阻塞编译**。本稿据此把 Codex 未被否决的架构修正**焊进标准本体**:

- 运行时**只读、只发候选、不写结论**(§2 铁律,源 Codex③)。
- schema 分**必备 / 可延后笔记**两层,门禁只卡必备,防资产污染(§3,源 Codex④)。
- 边界金标必须人工/专家裁决,否则禁止声称 scoring moat(§4 红线,源 Codex②⑤)。
- 留存硬闸写成**禁令式**,量产 gated on retention(§9,源 Codex⑥⑧)。
- ECD/Q-matrix/KT/IRT 降为远期参考,非承重(§11,源 Codex⑨)。
- 显式登记**待验证假设**(§9),由留存实验回答,不靠先建厂赌(源 Codex①⑧+"用户是否真想理解")。

## 1. 四层总纲与定位

| 层 | 名称 | 说明 |
|---|---|---|
| 产品战略层 | **深母题集 / 深母题引擎** | 对外口径。终局形态 = 建筑实务掌握度操作台 |
| 数据资产层 | **Deep Archetype Pack 深母题包** | 核心资产,要做深(§3) |
| 工程承载层 | **case_family_production + case_family_structure** | 是承载,**不是设计天花板** |

口径纪律:**产品叫深母题集,工程叫 case_family,不混。**

## 2. 所有权地图(本标准的脊梁)

深母题 = 中心资产、要做深;但**绝不抢评分与学情 authority**。

| 深母题 **拥有 = 要做深** | 深母题 **只引用、绝不拥有(权威在别处)** |
|---|---|
| 不变量 invariant | 正式评分 → 已签发 grading artifact(`CaseGradingSkillKernel` / `rubric_grader_v1`,引 artifact_id + point_id) |
| 出题人意图 examiner_intent | 统一错因轴 → `ERROR_CODE_REGISTRY`(`deeptutor/contracts/error_codes.py`,E01-E12) |
| 场景模板 + 变题规则(变量边界) | 知识身份/章节 → canonical taxonomy(`FINAL_CLEANED_TAXONOMY2026.json` node code) |
| 误解模型 misconception(新概念,比 error_code 深一层) | 学生长期画像 → `learning_evidence` / `LearnerStateService` |
| 训练任务族 task family | 教材/规范/真题证据 → source_refs + content_sha256 |
| 掌握鉴别 mastery_discriminator | 复测调度 → 既有 `revalidation_queue` |

### 2.1 运行时铁律(源 Codex③,必须遵守)

> **深母题在运行时只读、只发候选,绝不写结论。**

- 深母题只能输出:诊断**候选标签**(misconception candidate)、采分点**映射**(scoring_point_refs)、出题**约束**(variable space)。
- 最终错因码由 `ERROR_CODE_REGISTRY` 裁定;最终得分由 grading artifact 裁定;最终掌握/学情由 `LearnerStateService` 裁定。
- 任何让深母题"直接写错因结论 / 直接写掌握度 / 直接复制评分规则"的设计,一律视为造第二权威,拒绝。

## 3. Deep Archetype Pack 模块(必备 vs 可延后,源 Codex④)

复杂度 ≠ 壁垒。模块分两层,**生产门禁只卡"必备"**,可延后模块进 optional notes、不进 schema、不进 gate,逐步补,防"看起来完整、实际没人验证"的资产污染。

### 3.1 运行时必备(进 schema + 进生产门禁)

| # | 字段 | 作用 | 备注 |
|---|---|---|---|
| R1 | case_family_id + 来源依据 source_refs(+content_sha256) | 身份 + 可追溯(信任地基) | 引用不可追溯/只凭 LLM 总结 = 不合格 |
| R2 | 不变量 invariant | 换皮不变的底层逻辑 | 必须能一句话说清本质,否则不算"深" |
| R3 | 场景模板 scenario_templates | 工程背景/角色/条件/干扰 | ≥5 个不同场景变体 |
| R4 | 变题规则 variable_rules | 可变/不可变变量边界 | LLM 只能在边界内变,见 §5 |
| R5 | 采分点绑定 scoring_point_refs | 引用 grading artifact 的 point_id | **只引用,不复制评分规则** |
| R6 | 标准答案骨架 answer_skeleton | 高分答案结构/关键词/表达模板 | |
| R7 | 边界答案样本 boundary_answers | 写了但不够分/似是而非的判分边界 | **必须人工或强 domain reviewer 裁决**(§4) |
| R8 | 误解候选 misconception(candidate) | MCQ 干扰项 → 误解候选 → 映射 error_code | **只发候选,不写结论**(§2.1) |

### 3.2 可延后笔记(不进 gate,逐步补)

考点簇详表 / 出题人意图详述 / 弱表达分级细化 / 掌握度证据分档(M12)/ **交叉链接(M13,≥2 个母题包后才有意义,F16 单包阶段留空)**。

## 4. 红线(12 条用户红线 + 4 条 Codex 红线)

1. 母题不是题目集合——必须有不变量、变题规则、误解模型。
2. 来源必须可追溯——每个关键点有 source_ref + sha256。
3. 采分点不复制评分规则——只能引用 grading artifact。
4. 错因不新建野码——必须映射 `ERROR_CODE_REGISTRY` E 系列,禁 unknown_error。
5. MCQ 错误选项必须可诊断——每个干扰项绑定 misconception 候选,缺失只能进 mock。
6. 半写任务必须有 task_scope——未覆盖采分点不能算漏答(miss)。
7. 轻练不能关闭弱点——light_signal 不等同掌握。
8. 复测必须标 binding_level——same_point / same_node / original_review。
9. 变题不能越过变量边界——LLM 不能自由编题。
10. 金标样本必须沉淀——尤其边界答案。
11. 交叉母题必须显式链接——不靠 LLM 临场联想。
12. 上线必须过 review gate——教研/评分/规范/工程/QA 签出。
13. **(Codex③)运行时只读、只发候选、不写结论。**
14. **(Codex②⑤)无人工/专家裁决的边界金标 → 禁止声称 scoring moat。** F16 先做 30-50 条真实或专家裁决的边界集;多 AI 只做草稿+交叉质检,**不做评分终判金标**。
15. **(Codex 信任漏洞)判分依据必须可追溯到教材/真题/规范原文**,并在体验上可见,否则深诊断显得玄、复考用户不信。
16. **(Codex⑨)禁止用 ECD/Q-matrix/KT/IRT 等学术框架"证明"当前方案正确**;它们仅作远期参考。

## 5. 三运行模式(authority gate)

| 模式 | 适用 | official_score_allowed | 输出 |
|---|---|---|---|
| 官方评分 | 已编译 + 有 published artifact + 人工审核 | true | 得分/命中/漏点/扣分/改写/下一步 |
| 受控变题 | 母题已验证,LLM 在变量空间内生成,规则校验 | false | 同母题变式训练题,标难度/考查点 |
| 开放诊断 | 自由提问/未命中母题 | false | 保守:教学诊断,非正式评分,推测考查点 |

## 8. 质量门(10 硬门)+ 上线评测(7 指标)

**10 质量门**:不变量锐度 / 来源可追溯 / 评分不越权 / 错因可诊断 / 表皮可生成(≥5)/ 讲解可理解 / 复测可验证(≥1 same_point)/ 证据不污染(task_scope+evidence_weight 完整)/ 有金标样本(边界集 ≥30-50)/ 可交叉扩展。达不到只能叫"普通母题"。

**7 评测指标**:母题识别准确率 / 干扰项诊断准确率 / 采分点召回率 / 采分点误判率 / 错因诊断准确率 / 复测有效性 / 证据污染率。

## 9. 生产门禁与留存硬闸(源 Codex⑥⑧,禁令式)

> **写本标准 ≠ 授权量产。** 写标准 / schema 登记 / F16 单样板编译可与留存实验并行(产品负责人裁决);但**量产扩包必须 gated on retention**。

**硬闸(禁令式)**:F16 样板**不证明日回访(D1/D7)+ 不过 §8 七项指标**,则:
- **禁止**新增第 2 个母题包;
- **禁止**建编译自动化(compiler automation);
- **禁止**扩团队。

扩展阶梯 **1 → 5 → 15 → 40** 全部 gated on retention,逐级解锁。

**待验证假设(显式登记,由留存实验回答,不靠先建厂赌):**
1. 复考的忙碌成年人,要的是"理解/看穿",还是"短、准、能得分、过线"?若是后者,"深"可能是负担而非帮助。
2. 成人用户愿不愿意每天在小程序里**写**案例答案(输入摩擦)?MCQ 轻练只能证明点选意愿,不证明写作意愿。
3. 日回访是新鲜感(3 天),还是真有效(7/14 天看分数提升)?闸不能只看短期回访。
4. 留存失败是内容问题,还是时机/季节/备考阶段问题?

## 10. F16 防水样板范围(只做必备 + 留存切片)

- **后台做深**:R1-R8 必备字段;不变量(基层先行/节点优先/大面连续/搭接方向/保护层/试验验收);≥8 个误解候选;边界答案集 30-50 条(真实或专家裁决)。
- **前台只露轻练切片**:今日 2 分钟 MCQ → 暖版"看穿"诊断(错误类型 + 为什么 + 教材定位)→ 明日复测。暖语气,先捧→就差一步→我相信你(见 [[wow-see-through-must-be-warm-not-harsh]] 记忆)。
- **不做**:第 2 个包、编译自动化、M13 交叉链接、完整 14 模块的可延后部分(除非样板验证后)。

## 11. ECD / Q-matrix / KT / IRT 定位(源 Codex⑨)

**远期参考,非承重。** MVP 只用规则化 mastery + 时间衰减 + 采分点命中率。不得用这些学术框架"证明"当前方案正确,以免制造可信幻觉、误以为在做教育测量而实际只在做规则分数。

## 12. 下一步(本标准锁定后)

1. schema 登记 + 扩校验器(§7)。
2. F16 样板编译(§10 必备字段),产物 = 留存实验弹药。
3. 跑留存实验(并行),回答 §9 待验证假设。
4. **闸点**:F16 过 §8 指标 + 留存证明 → 才允许扩到第 2 个包,进入 1→5→15→40 阶梯。
