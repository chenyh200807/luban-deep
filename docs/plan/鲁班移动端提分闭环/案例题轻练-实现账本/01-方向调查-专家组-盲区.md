# 01 · 方向调查 / 专家组 / 盲区

> 执行账本条目。设计权威见 [v1.3 计划](../2026-07-08-luban-case-question-light-practice-capability-plan.md) §0/§5。这里只记"怎么得出方向、查了谁的盲区、结论"。

## 起点
owner 对最初的 F16 5 天版案例题轻练"没我想象中好",提出两问:(1) 半写案例这个**形式**本身对不对?(2) 是东西做得不够好,还是方向错。要求派**独立 agent 跨越 owner 和我共同的盲区**,并研究 Khanmigo / 同行 / 跨行。

## 5 席调查 + 盲区 agent 结论
- **案例题判分是整条链最脆的地基**:判官不稳(见 [02](./02-判官temp0-欠切分.md))+ 采分点欠切分,先修地基再谈形式。
- **用户第一需求是"学习路径 / 按薄弱点排序 / 诊断"**,不是关卡化考试(与记忆 `luban-feedback-validates-learning-path-demand` 一致)。
- **形式没错,但核心必须是"丝滑少打字"**:微信小程序打字不便 = 半写案例的真约束。轻练要能接住任意主题(不止 F16),靠 Nexus-like + KnowQL + 专业 skills + 母题集。
- owner 拍板:**方向对**(案例题轻练 = 教学动画后的重要补充),技术侧执行——修 bug + 基于母题集(成品文件夹)继续做 demo。

## 长期战略保留意见(盲区 agent 反复提)
整个方向仍**缺真实用户需求验证**("5 人 3 天")。计划严谨,但建在一个未验证方向上。→ 落为 §5 并行轨(不阻塞技术,但 owner 必须知道)。这是 [08](./08-真LLM端到端-人门-优先清单.md) 里"5 人验证"人门的由来。
