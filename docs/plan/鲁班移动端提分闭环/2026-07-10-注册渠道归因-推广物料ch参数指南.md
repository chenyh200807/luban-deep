# 注册渠道归因 — 推广物料 ch 参数指南（owner 一页版）

> 状态：已实现（分支 `fix/p2-channel-attribution`，2026-07-10）。
> 目标：下一波推广能算 ROI——同一渠道发出去多少码/链接、带来多少注册，按渠道分组直接看。
> 背景：2026-07-08 推广带来 18 个注册，但库里没有渠道字段，转化率算不出来。

## 一句话用法

**给每个投放渠道发不同的 `ch` 值，物料落地路径带 `?ch=渠道代号`，其余全自动。**

## ch 值命名约定

- 只允许 **字母、数字、下划线、连字符**（`[0-9A-Za-z_-]`），最长 64 字符。中文/空格/标点会被后端清洗掉。
- 建议格式 `{渠道}_{活动或日期}`，一次投放一个值，例：

| 投放场景 | ch 值示例 |
|---|---|
| 小红书笔记 7 月 10 日 | `xhs_0710` |
| 微信群 A 转发 | `wxgroup_a` |
| 抖音 KOL 张老师 | `dy_zhang` |
| 线下宣讲会二维码 | `offline_0715` |

## 物料怎么生成（三种，任选）

落地页路径统一用登录页：`pages/login/login`（其实任何页面都行，渠道参数是 App 启动时全局捕获的）。

1. **小程序码（推荐，正式版）**：微信公众平台 → 开发管理 → 或调接口 `getwxacode`，
   `path` 填 `pages/login/login?ch=xhs_0710`。
2. **普通二维码**：接口 `createwxaqrcode`，`path` 同上。适合印刷物料。
3. **URL Link（发群/私聊用的链接）**：接口 `urllink.generate`，
   `path=pages/login/login`，`query=ch=xhs_0710`。

⚠️ **不要用 `getwxacodeunlimit`（scene 参数形态）**——那种码把参数放在 `query.scene` 里，本实现只解析 `query.ch`，扫了会丢渠道。

## 数据在哪看

1. **BI 会员列表**：每个会员多了 `channel` 字段（注册渠道），可直接筛。
2. **BI 会员统计**（`/api/v1/bi/members/stats`）：新增 `channels` 分组——每个渠道的总会员数 `count` + 窗口内新增 `new_count`。ROI = 新增注册 / 该渠道发出的码扫描量（曝光量自己记）。
3. **SQL 兜底**（Supabase）：

```sql
SELECT metadata->>'reg_channel' AS channel, count(*)
FROM public.user_identity_aliases
WHERE alias_type = 'phone'
GROUP BY 1 ORDER BY 2 DESC;
```

## 归因规则（防止数据被污染的三条）

1. **first-touch**：渠道只在用户**首次注册**时写入；老用户扫了新推广码再登录，不会覆盖原注册渠道。
2. **微信场景值自动带上**（`reg_scene`，如 1047=扫小程序码、1011=扫普通二维码），可区分入口形态，不用管。
3. 未带 `ch` 的自然注册渠道显示为 `unknown`（BI 分组里就是自然量基线）。

## 技术落点（给工程看的一行索引）

客户端捕获 `wx_miniprogram/app.js`（onLaunch/onShow → storage `reg_attribution`）→ 请求透传 `utils/api.js` + `pages/register/register.js` → 后端 `deeptutor/api/routers/mobile.py`（register / wechat login / bind-phone 三入口）→ `member_console/service.py` `_channel_attribution_metadata` 并入既有 `identity_metadata` → 落 `user_identity_aliases.metadata`（jsonb，无新表新列）→ BI 读 `member_console/directory.py` 白名单 + `bi_service.get_member_stats` channels 分组。
