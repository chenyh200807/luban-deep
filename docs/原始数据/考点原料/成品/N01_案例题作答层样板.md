# N01 案例题作答层样板 — Answer Layer Prototype（计算/判读型实测）

> **这是什么**：在 [`N01_网络计划关键线路.md`](./N01_网络计划关键线路.md)（深母题知识层 R1–R8）之上**加的一层**，不是新母题体系。
> 知识层回答「**这条线路是不是关键、时差算没算对、延误影不影响总工期**」（学生"会算/会判"）；作答层回答「**怎么把计算结果 + 判读结论写成阅卷友好、能拿分的句子**」（学生"会写答案"）。
> **第一性原理**：一建网络计划案例失分，**计算题尤其不是"不会算"，而是"算对了写不成分"**——只写数字不给线路、漏另一条并列关键线路、只凭责任方下索赔结论不比时差、总工期漏单位。作答层的杠杆 = 把「算出什么」变成「按阅卷结构写全采分点」。
>
> **⚠️ 本样板是 N01 实测载体（核心目的）**：N01 是本批第一个**计算/判读型**考点（对比 J01 文字程序型）。作答层方法论（四件套 + 五维框架 + 句式库）原设计偏文字程序题，**本样板在造的同时实测它对计算题够不够用**，结论见末尾「## 实测报告」节——这是 N01 的真正交付物。
>
> **🆕 缺口已闭合（本次更新）**：N01 首跑实测暴露"计算题缺一类推导句式"，当时按红线**如实留白未硬套**。现 skill §1.③ 已正式补入**第 9 类「计算判定链」**（A01/N01/K01 三方实测撞同一缺口后补入），§1.② "记录维"已扩名为**"记录/计算表达维"**。本样板据此把原留白的**纯推导段补实**成可上答题纸的标准作答结构（§2 模板 T5、§3.3 改写、实测报告 b）。
>
> **职责边界（thin layer，不造第二 authority）**：

## 0. 五维框架（作答层的"采分点分类器"）+ 计算题适配诚实标注

案例采分点几乎都能归到这**五维**之一。但 **N01 是计算/判读型，五维的"程序/记录/后果"维偏弱，而出现了一个五维框架未显式覆盖的维度：「计算/数值表达」**（线路写全没、算式带单位没、时差数值对没）。下表先按原五维铺，再用 🔵 行诚实标注"计算表达"这一**框架缺口**（详细论证见末尾实测报告 b）。

| 维 | 含义 | 在 N01 的典型采分点 | 高频漏法 |
|---|---|---|---|
| **主体维** | 谁来做（编制/审核/监测/调整的责任人） | （N01 弱）进度监测/调整由项目部组织；编制经总监审查确认 | N01 案例主体维考得少，偶在"谁组织调整"出现 |
| **程序维** | 按什么顺序做（先后不可颠倒） | 绘图（补虚工作）→ 计算参数 → 定关键线路 → 编制/实施（应用程序 7 阶段） | 未补全逻辑就直接算 / 跳过"计算参数"直接定线路 |
| **条件维** | 达什么阈值/触发什么条件才做（**判据维**） | 关键工作 = 总时差最小；延误 ≤ 总时差 → 不影响总工期 | 把"非关键工作延误"当成必影响总工期；只看责任方不比时差 |
| **记录维** | 要留什么书面/必含内容（**含算式表达**） | 总工期须「线路 + 算式 + 单位」；关键线路须节点连续全列 | 只写数字不给线路；漏另一条并列关键线路；漏单位 |
| **后果维** | 达标/违反后会怎样（再判读、结论） | 影响关键线路 → 工期索赔成立；未超时差 → 不成立（费用另议） | 只写"影响/不影响"不接索赔结论；工期/费用索赔混判 |
| 🔵 **（缺口）计算/数值表达维** | **算式正确性 + 数值与对象绑定 + 单位**（五维框架未显式列，N01 实测暴露） | TF/FF 数值算对且标对工作；总工期沿关键线路求和；多条线路工期相等 | 沿非关键线路求和、TF/FF 混淆、数值与工作错配 | 

> **用法**：批改时先把参考采分点按五维（+ 计算表达）铺开，学生答案逐维比对——**漏哪维一目了然**。对 N01 这类计算题，**记录维被"算式表达"撑大、条件维被"判据/判读"撑大**，是五维框架适配计算题时的真实形变（见实测报告 b：五维够用但需把"记录维"显式扩成"记录/计算表达维"，不必另起一套）。

### 勾选自全局 §1.③ 的句式（N01 用到 5 类）

| 全局句式类 | N01 是否用到 | N01 实例 |
|---|---|---|
| **判断纠错（三段式）** | ✅ 用到 | 索赔判读题："不妥/不成立。理由：…总时差…。正确做法/结论：…" |
| **程序（箭头链）** | ✅ 用到 | 应用程序：`绘图(含补虚工作) → 计算参数 → 确定关键线路 → 编制/实施`；调整：关键工作调整优先 |
| **内容清单枚举** | ✅ 用到 | 进度监测五项内容 / 进度调整五种方法 / 网架安装方法枚举 |
| **索赔（四步判定）** | ✅ 用到 | "先判责任归属 → 再判是否影响关键线路/超总时差 → 再判工期 vs 费用 → 给结论" |
| **🆕 计算判定链（第 9 类·计算题专用）** | ✅ 用到（**计算题主力·原留白处**） | "先亮判据（关键线路=最长路径·总时差为零）→ 代入逐路径长列式 → 得关键线路/总工期数值 → 回判 TF=LS−ES 与延误是否超时差" |
| 措施 / 验收 / 主体定位 / 事故处理 | ❌ N01 低频 | less is more，不堆 |

### 模板 T1 · 索赔/延误判读类（"是否成立""影不影响总工期"）— N01 最高频、计算题主力

```
【责任+时差两步链】①责任归属：<事件由谁负责（甲方/承包人/不可抗力）> 。
                ②时差比较：<该工作> 总时差 = <数值>，延误 <数值>，
                          <延误 ≤ 总时差 / 延误在关键线路> 。
                结论：<不影响/影响>总工期，工期索赔<不成立/成立>（费用索赔另议）。
```
- **要害**：① **两步缺一不可**——只写责任不比时差 = 半分（漏条件维）；② 工期索赔与费用索赔**分开判**（2018：工期不成立但费用可另议）；③ 时差数值要**绑定到具体工作名**（"A 总时差 2 周"而非孤零零"2 周"）。
- N01 实例：见 §3 批改示范。

### 模板 T2 · 关键线路 + 总工期类（"写关键线路并算总工期"）

```
【线路+算式+单位】关键线路为 <节点序列①→②→…> （若并列最长，全部列出）。
               总工期 T = <沿关键线路各工作持续时间相加的算式> = <数值><单位> 。
```
- **要害**：① **线路 + 算式 + 单位三件齐全**，缺一压线扣分；② **并列最长路径全列**（2015/2020 均两条）；③ 算式必须沿**关键线路**求和（沿非关键线路求和=计算错误 E09）。
- N01 实例：`关键线路：B→E→G→K→P 和 B→E→G→J→P；T = 4+3+1+3+2 = 16 天`（2020 两条）。

### 模板 T3 · 程序/调整类（"正确顺序""如何调整"）


### 模板 T5 · 计算判定链（第 9 类 · 计算题专用 · 🆕 原留白处已补实）— N01 纯推导段主力

> **来源**：全局 §1.③ 第 9 类「计算判定链」（A01 强度判定 / N01 关键线路时差 / K01 索赔金额三方实测撞同一缺口后补入）。首跑时该类未入库、本样板留白；现正式勾选，把"逐路径算长→定关键线路→算 TF=LS−ES→比延误"的**纯计算推导段**补实成可上答题纸的标准结构。

```
【计算判定链】①亮判据/公式：关键线路 = 最长路径，关键工作总时差 = 0；
                            非关键工作总时差 TF = LS − ES（FF ≤ TF）；
                            延误判读：延误 ≤ 总时差 → 不影响总工期。
            ②代入题干数据列式（逐路径求长，取最长）：
                            路径1 = <工作序列> = <各持续时间相加> = <数值><单位>；
                            路径2 = … = <数值><单位>；（逐条算，多条并列全列）
            ③得数值结论：最长路径 = 关键线路 = <线路（节点连续）>，
                            计算工期（总工期）= <数值><单位>；
                            目标非关键工作 TF = LS − ES = <数值>（绑定到工作名）。
            ④回判定性：<目标工作> 延误 <数值> vs 其总时差 <数值>
                            → <未超时差·不影响总工期 / 在关键线路上·影响总工期>
                            → 工期索赔 <不成立 / 成立>（费用索赔另议）。
```
- **要害**：① **四步顺序不可省**——只写④结论不写①②③ = 丢过程分（计算题"只写数字不给推导"的高发失分）；② ②③ 的**线路 + 算式 + 单位**三件齐全，TF 必写成 `LS−ES` 的代入式而非孤零零数值；③ 数值**绑定到具体工作名**（"A 的 TF=2 周"非孤立"2 周"）；④ ④回判把"延误 vs 时差"显式比较后才下索赔定性，杜绝"只看责任方下结论"。
- **数值边界（红线）**：本句式只管**作答结构**（推导是否按"判据→列式→数值→回判"四步写全），**数值算术正确性不在本层判对错**——归 signed scoring artifact + 判分内核（见 §4.3 / 实测报告 d）。
- N01 实例：见 §3.3④ 改写（关键线路 B→E→I、A=2周/F=3周、两事件索赔判读，全套四步链）。

> **🆕 缺口闭合说明**：首跑时全局只有 8 类、无"计算推导句式"，N01 的"逐路径算长度→比长短→定线路"和"六时标注算 TF/FF"两段纯推导**无对应句式骨架**，本样板当时按红线如实留白、未硬塞进 T1 索赔链。现第 9 类「计算判定链」已正式入库并勾选（即上方 T5），该留白补实完毕；T1（索赔判读两步链）承接"责任+时差比较"的**判读结论**部分，T5 承接其前置的**逐路径求长→定线路→算时差**纯推导部分，两者衔接（T5 的④回判定性 = T1 的两步结论）。

### b. 计算题适配的关键问题（N01 实测核心）：句式库 + 四件套 + 五维框架对计算题够用吗？

> **🆕 缺口已闭合（本次更新）**：首跑实测结论是"基本够用，但缺第 9 类计算推导句式 + 记录维需扩名"，当时按红线如实留白未硬套。现 skill **§1.③ 已正式补入第 9 类「计算判定链」**、**§1.② 记录维已扩名为"记录/计算表达维"**，两处定点扩展均已落地，本样板据此把原留白补实（T5、§3.3④）。下文保留首跑发现的论证，并在每条标注"现状=已闭合"。

**总结论：计算题适配成立——首跑发现的两处定点缺口（缺第 9 类句式 / 记录维扩名）现均已补入 skill，原留白已补实；批改逻辑的"链式"特征已与第 9 类四步顺序衔接。不是推倒重来，是定点扩展，且已完成。**

**够用的部分**：
- **四件套（必写关键词/标准表达/易错表达/版本状态）完全够用**，只是"必写关键词"对计算题的语义从"名词术语"变成"**判据词 + 算式形态**"（如"关键线路/总时差最小/线路+算式+单位/数值绑定工作"）。这是语义适配，不是结构缺口——四件套的格子本身不用改。
- **版本状态维对计算题反而轻松**：网络计划判据是长期稳定规范（GB/T 13400 体系），没有 J01 危大那种"新规范覆盖旧强条"的高发漂移区，10 行统一 `现行有效`，只有虚工作定义/公式机理按 pack 裁决标 🔵。

**不够用 / 需扩展的三处（核心发现）**：

1. **五维框架：够用，"记录维"被"算式表达"撑大 → ✅ 现已扩名为"记录/计算表达维"（skill §1.② 实证扩名）。**
   N01 的 R5-4/R5-5/R5-6（写全关键线路、总工期线路+算式+单位、TF/FF 数值绑定工作）全部落"记录维"，但本质是"**计算结果的可判分表达**"，与 J01"留什么书面/签字"的记录维语义不同。五维仍能容纳（不必造第六维）。**现状=已闭合**：skill §1.② 已把"记录维"显式扩名为**"记录/计算表达维"**，并写明"计算题在此维写算式链+数值结论（N01 实证扩名，不另造第六维）"——铺计算型 pack 时"线路+算式+单位"有了归属维。**结论：五维框架够用，扩名已落地。**

2. **句式库：首跑缺"计算推导句式" → ✅ 现已补入第 9 类「计算判定链」（skill §1.③）。**
   首跑时全局只有 8 类"判断/程序/主体/内容/索赔"型，都是**结论性表达**；N01 计算题的**纯推导过程**（"逐条算各路径长度 → 取最长定关键线路 → 六时标注算 TF=LS−ES/FF → 比较延误 vs 时差"）无句式骨架，T1 索赔链只能承接最后的"判读结论"。本样板首跑按红线如实留白、未硬塞进 T1。
   **现状=已闭合**：skill §1.③ 已正式补入**第 9 类「计算判定链」**（A01 强度判定 / N01 关键线路时差 / K01 索赔金额三方实测撞同一缺口后补入），骨架为"先亮判据/公式 → 代入题干数据列式 → 得数值结论 → 回判规范阈值或合同条款定性"，并明确"数值与结论都要写、数值正确性归 signed scoring artifact 不在本句式判对错"。本样板已据此把原留白补实成 **T5（§2）+ §3.3④ 改写**：
   ```
   【计算判定链】①亮判据：关键线路=最长路径·关键工作总时差=0；非关键工作 TF=LS−ES；延误≤总时差→不影响总工期。
                ②代入列式：逐路径求长（路径1=…、路径2=…），取最长。
                ③得数值结论：最长路径=关键线路=<线路>，计算工期=<数值><单位>；目标工作 TF=LS−ES=<数值>（绑定工作名）。
                ④回判定性：延误<数值> vs 总时差<数值> → <影响/不影响>总工期 → 工期索赔<成立/不成立>。
   ```
   该类入库后，所有计算/判读型 pack（N 系列网络计划、含工期/费用/造价计算的题）全局共用，仍是 fat skill 只写一次。**这是 N01 实测对全局句式库的贡献，现已落地为正式第 9 类。**

3. **批改逻辑：计算题多一层"地基采分点错→连锁错"的链式特征，文字题没有。**
   J01 文字题批改是**并列指漏**（漏 P1、漏 P2 各自独立扣分）。N01 计算题出现**链式失分**：P1 关键线路判断错（地基）会让 P2 时差、P3 索赔即使数字对也"理由链断裂/自相矛盾"（§3.3 学生 P3 结论蒙对但与自己写错的线路矛盾）。批改必须**先判地基采分点（关键线路/总工期）对不对，再判上层判读**，不能各点孤立打分。这不是句式/四件套/五维的缺口，而是**批改算法对计算题要加"先地基后上层"的判读顺序**——建议写进作答层 AI 批改模组的计算题分支（§4.3 已记为待判分内核定档的不确定点）。

**一句话回答 b**：四件套够用（仅必写关键词语义从名词变判据词）；五维框架够用且记录维**已扩名为"记录/计算表达维"**（skill §1.②）；句式库首跑缺的第 9 类「计算判定链」**已正式补入**（skill §1.③），本样板首跑如实留白、现已据此补实成 T5+§3.3④；批改算法对计算题的"先地基后上层"链式判读**已与第 9 类四步顺序衔接**。**两处定点缺口均已闭合——作答层方法论对计算题成立且收口完毕，不是推倒重来。**
