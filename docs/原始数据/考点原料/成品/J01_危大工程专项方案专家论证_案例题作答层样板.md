# J01 案例题作答层样板 — Answer Layer Prototype

> **这是什么**：在 [`J01_危大工程专项方案专家论证.md`](./J01_危大工程专项方案专家论证.md)（深母题知识层 R1–R8）之上**加的一层**，不是新母题体系。
> 知识层回答「**这一步该不该做、由谁做、程序对不对**」（学生"会看答案"）；作答层回答「**怎么把它写成阅卷友友好、能拿分的句子**」（学生"会写答案"）。
> **第一性原理**：一建案例失分不是"不会"，是"会一点但写不成分"——漏采分点 / 答非所问 / 只写结论不写理由 / 程序顺序错 / 主体写错。作答层的杠杆 = 把「知道什么」变成「按阅卷结构写全采分点」。
>
> **职责边界（thin layer，不造第二 authority）**：
> - **采分点 ground truth 归 J01 §5 R5**（signed pack）。本层的「可写化三件套」从 R5 **派生**，不另造采分点。
> - **判分归 signed scoring artifact**。本层的 AI 批改示范标 `official_score_allowed = false`，是**候选教学示范**，非官方判分。
> - **错因归 `deeptutor/contracts/error_codes.py` ERROR_CODE_REGISTRY**（E01–E12 / M01–M10）。本层错因标签只**映射** registry 已注册码，禁自造。
> - **学情归 LearnerStateService**。本层不写学习证据。
>
> **三原则**：依附 J01 pack 不另起体系（thin）/ 句式模板跨母题复用（fat skill）/ less is more 别堆。
> **status**: `candidate_answer_layer_prototype`（候选作答层样板，验证"会看答案→会写答案"跃迁用）。
> **三色铁律继承自 J01**：🟢 采分点锚定 J01 R5（已 signed）｜ 🔵 作答策略/句式（教学用，非判分眼）｜ 🔴 待真人/专家裁决（判分边界、给分档位）。

## 0. 五维框架（作答层的"采分点分类器"）

案例采分点几乎都能归到这**五维**之一。学生写答案漏分，多是某一维整维漏掉。作答层给每个采分点标命中哪维，让学生答题时"五维自检"不漏维。

| 维 | 含义 | 在 J01 的典型采分点 | 高频漏法 |
|---|---|---|---|
| **主体维** | 谁来做（编制/审核/审查/组织/交底的责任人） | 总包组织编制；总包组织论证；总监审查；编制人交底 | 写成"施工单位"含糊，不点"总承包单位" |
| **程序维** | 按什么顺序做（先后不可颠倒） | 审核→审查→论证；先编案再论证 | 跳步 / 顺序倒置 / 直接论证 |
| **条件维** | 达什么阈值/触发什么条件才做 | 危大档(≥3m/≥24m)；超规模档(≥5m/≥50m) | 混档：把危大阈值当论证阈值 |
| **记录维** | 要留什么书面/签字/必含内容 | 方案八项内容；论证报告签字；计算书及施工图 | 漏应急处置/验收要求；漏签字 |
| **后果维** | 违反/达标后会怎样（法律后果、再程序） | 不得擅自修改，改了须重新论证 | 只写"不能改"，不写后续须重新论证 |

> 用法：批改时先把参考采分点按五维铺开，学生答案逐维比对——**漏哪维一目了然**，比"逐字找差"更快定位"差哪句"。

## 2. J01 答题句式模板（从研究方案 8 类选 J01 用到的 · fat skill 跨母题复用）

> **复用声明**：下列句式骨架是**跨母题作答结构**，不是 J01 专有——任何"判断/程序/主体/内容"型案例（C04 模板拆除、B02 基坑支护、S 系列…）都可套同一骨架，只换采分点内容。这是 fat skill：句式在作答层只写一次，40 pack 共用。

### 模板 T1 · 判断纠错类（"指出不妥之处并改正"）— J01 最高频案例题型

```
【三段式】不妥之处：<原文照抄不妥做法> 。
        理由：违反《××规定》关于<采分点>的要求。
        正确做法：应<标准表达> 。
```
- **要害**：① 必须**照抄题干原话**点出不妥（阅卷按"不妥点"给分，泛泛说"组织不妥"不得分）；② "理由"+"正确做法"成对出现——**只写不妥不写正确做法 = 半分**（漏后果维/记录维）。
- J01 实例：见 §3 批改示范。

### 模板 T2 · 程序顺序类（"正确顺序应是""排序"）

```
【箭头链】应按顺序：<步骤1> → <步骤2> → <步骤3> → … 。
        （关键：<点出不可颠倒的那一步>）
```
- J01 实例：`专项方案编制 → 施工单位审核 → 总监理工程师审查 → 专家论证 → （论证通过）实施`。
- **要害**：箭头表达让阅卷一眼看到顺序；**点名不可逆步**（"专家论证是最后一道关，不能先论证后审查"）。

### 模板 T3 · 主体类（"由谁……""哪个单位""还有哪些单位"）

```
【主体定位】<某事项>应由<责任主体（精确到单位/岗位）>负责（组织/编制/审查/交底）。
          （区分：总承包 vs 专业分包 / 施工 vs 监理 vs 建设）
```
- J01 实例：`专项方案由施工总承包单位组织编制；专家论证会由施工总承包单位组织召开；总监理工程师负责审查`。
- **要害**：**精确到单位**——"施工单位"含糊，要写"施工总承包单位"；分包情形要点出"专业承包单位"。

### 模板 T4 · 内容清单类（"应包含哪些内容""还应包括哪些"）

```
【编号枚举】<某文件/某清单>应包括：①…②…③…（逐项编号，写全不漏）。
          （查漏：对照标准清单逐项打钩，漏项即丢分）
```
- J01 实例：基坑方案八项 / 论证主要内容三项 / 需单独编案工程清单。
- **要害**：**编号枚举**比堆叠句号更阅卷友好；写完后**对照标准清单逐项查漏**（记录维最易漏维）。

> 选型说明：J01 案例题以 **T1 判断纠错 + T3 主体 + T4 内容清单 + T2 程序** 四类为主（对应 J01 §4 R3 场景 S2/S3/S4/S6）。研究方案其余类（计算类/列举类等）J01 案例低频，本层不堆（less is more）。

## 3. 一道完整案例题作答训练（验证闭环 · 关键）

> **真题来源**：`{2019,第2题}`（`_J01_exam_evidence.json` evidence#27，已逐字直读核真）。
> 选它的原因：题干**自带典型错误**（基坑支护专业施工单位编制方案后、组织含总承包单位技术负责人在内的5名专家论证）——正是 R5-9 专家组回避 + R5-3 编制主体两个采分点的高频陷阱，最适合验证"模拟学生写不全→AI 按采分点指漏"。

### 3.1 题面（场景 + 案例问法）

> **背景资料**（节录自真题，与基坑论证相关部分）：
> 某新建办公楼工程，地下二层，地上二十层，框架剪力墙结构，建筑高度 87m。建设单位通过公开招标选定了施工总承包单位并签订工程施工合同，**基坑深 7.6m**。基坑施工前，**基坑支护专业施工单位编制了基坑支护专项方案，履行相关审批签字手续后，组织包括总承包单位技术负责人在内的 5 名专家对该专项方案进行专家论证**，总监理工程师提出专家论证组织不妥，要求整改。
>
> **问题**：指出基坑支护专项方案论证的**不妥之处**，应参加专家论证会的单位还有哪些？

### 3.2 模拟学生作答（"会一点但写不全"——典型失分样本）

> 设定：学生记得"专家要5人"，但**漏了回避要求**（参建方人员不得当专家），且**没点出题干那个具体不妥点**（总包技术负责人当专家），还**把组织主体写含糊**了。这正是真实考生最常见的失分形态。

```
学生答：
论证不妥。专家应该有5个人，这点是够的。专项方案要经过论证才能施工。
应该让施工单位再仔细检查一下方案。
```

### 3.3 AI 按采分点批改（对照 J01 R5 可写化采分点 · 候选教学示范）

> `official_score_allowed = false`（候选教学示范，非官方判分）。给分档位 🔴 待真人/专家裁决。错因标签映射 ERROR_CODE_REGISTRY。

**① 参考采分点（锚 J01 R5，本题命中 R5-9 / R5-3 / R5-7）**

| 采分点 | 必写关键词 | 五维 |
|---|---|---|
| **P1**（R5-9）不妥点1：总承包单位技术负责人属参建方人员，**不得以专家身份参加** | 参建各方人员、不得以专家身份 | 主体维 |
| **P2**（R5-9）专家组应为 **5人以上**且无利害关系 | 5人以上、利害关系 | 记录维 |
| **P3**（R5-3/R5-7）应由**施工总承包单位组织**论证（题干是"基坑支护专业施工单位"组织，需点出由总包组织更妥/或至少明确组织主体） | 施工总承包单位 | 主体维 |

**③ 作答错因标签（映射 ERROR_CODE_REGISTRY）**

| 错因 | error_code | 体现在 |

| **采分点遗漏**（漏 P1 回避要求这一核心不妥点） | **E02** 采分点遗漏 | 没写"参建方人员不得当专家"——本题第一得分点 |

**④ 更像标准答案的改写（用 §2 句式模板 T1 判断纠错类 + T3 主体类）**

```
     及相关专业承包单位的项目负责人/技术负责人（以见证人/参建方身份参加，
     非专家身份）。
```

### 4.2 横向铺 40 pack 的方法（这个形态对不对 + 怎么铺）

**形态判断：对。** 理由——作答层是**纯派生层**，它的全部"知识内容"都来自已 signed 的 pack R5，自己只贡献"可写化包装（关键词/标准表达/句式）"。这意味着：
1. **不增 authority 风险**：每个 pack 的作答层只是把它自己的 R5 重新包装，采分点真值永远在 pack 手里。
2. **句式模板全局共享**：§2 的 T1–T4 是跨母题的，40 pack 共用一份句式库——**句式只写一次**（fat skill），各 pack 作答层只填"采分点可写化表 + 一道作答训练"。

**铺 40 pack 的标准动作（每 pack 约做三件，前两件是机械派生）**：
1. **派生可写化表**：把该 pack §5 R5 逐行 → 补「必写关键词 / 标准表达 / 易错表达 / 五维」四列。关键词从 R8 误区"关键词缺失"反推，易错表达从 R8 误区 + R7 边界候选映射 error_code。
2. **选句式**：从全局 §2 T1–T4（+研究方案其余类，按需）勾选该 pack 案例题用到的 2–4 类，不新造。
3. **跑一道作答训练闭环**：取该 pack 证据包内一道真题案例 → 写"会一点但写不全"的模拟答案 → AI 按 R5 采分点批改（命中/漏 + error_code + 改写 + 复练方向）→ 验证"能按采分点给分 + 指漏点"。

**可半自动化**：第1步（R5→可写化表）和第3步的"参考采分点拆解"可由 LLM 按本样板的固定模板批量生成，人工只需核"关键词是否真必写、错因码是否贴切、改写是否回到 signed 采分点"——把人工从"逐 pack 手写"降到"逐 pack 审校"。
