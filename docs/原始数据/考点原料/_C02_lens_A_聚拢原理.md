### 🔗 因果链 ①：为何预付款要先“扣暂列金”？

**📌 成因**
2015年真题案例4明确要求：预付款 = (合同价 - 暂列金额) × 比例。许多学员直接用合同价乘比例——这是最常见的 **M01（漏算基础值）** 错因。

**🔍 机理**
- 🟢 暂列金额是发包人预留的“备用金”，用于施工中可能发生的工程变更、索赔、签证等，**不一定发生**。
- 🟢 预付款是承包人启动工程的“启动资金”，应基于**确定发生的工程费用**计算。
- 🟢 如果将暂列金纳入预付款基数，相当于发包人提前为“不确定事件”垫付资金，违反预付款的“实体工程量导向”原则。

**📏 为什么这个措施有效**
- 🟢 扣除暂列金后，预付款与**实际需完成的工程实体价值**挂钩，保证了资金配置的真实性。
- 🟢 2013版清单计价规范明确规定此规则，统一了行业操作口径。

**🧠 学生易错点 → 错因码 M01**
> **错因类型**：计算基数选取错误——未从合同价中扣除暂列金额、计日工、专业暂估价等非实体费用。
>
> **预防措施**：强制建立“三步走”计算流程：
> 1. 确定合同签约价
> 2. 扣除暂列金额、暂估价中非实体部分
> 3. 用净额乘预付款比例

### 🔗 因果链 ②：挣值法 —— 三个数字如何管住“钱”和“进度”？

**📌 成因**
在进度款管理中，发包人关心的不仅是“付了多少钱”，更核心的是“钱花得值不值”——这正是挣值法解决的问题域。教材将挣值法编排在施工成本控制章，但其在**计量计价**中同样是核心判断工具。

**🔍 机理**
挣值法将计划、实际、完成三个维度统一为**金额语言**：

- 🟢 **BCWP（挣值）** = 已完成工程量 × 预算单价  
  → “实际干的活值多少钱（按预算标准）”
- 🟢 **BCWS（计划值）** = 计划工程量 × 预算单价  
  → “计划该干的活值多少钱”
- 🟢 **ACWP（实际成本）** = 已完成工程量 × 实际单价  
  → “实际干这些活花了多少钱”

**三个核弹公式**：
- 🟢 **CV = BCWP - ACWP**：正数=省钱，负数=超支 → 回答了“钱花超了吗”
- 🟢 **SV = BCWP - BCWS**：正数=提前，负数=滞后 → 回答了“活干快了吗”
- 🟢 **CPI = BCWP / ACWP**：>1=效率高，<1=效率低
- 🟢 **SPI = BCWP / BCWS**：>1=进度快，<1=进度慢

**📏 为什么这个措施有效**
- 🟢 传统的“花了多少钱”只能看到**支出**，看不到**产出**。挣值法把进度也“货币化”，让进度和成本在同一个量纲下比较。
- 🟢 在进度款支付场景：发包人除了看“累计完成产值”（类似BCWP），还可以对比“计划产值”（BCWS）判断进度偏差，决定是否触发扣款或调整支付比例。

**🧠 学生真题演示例**（基于2024真题改编训练）
> 某项目第20周末，BCWP=6370万，ACWP=6240万，BCWS=5340万。
>
> CV = 6370 - 6240 = +130万（节支 ✅）
> SV = 6370 - 5340 = +1030万（提前 ✅）
> CPI = 6370/6240 ≈ 1.02（效率好 ✅）
> SPI = 6370/5340 ≈ 1.19（进度快 ✅）
>
> **结论**：项目成本受控、进度领先，承包人履约状态良好，发包人可按正常比例支付进度款。

### 🔗 因果链 ③：从挣值到进度款支付 —— 管理落地的闭环

**📌 成因**
挣值法给出的是“判断数据”，但进度款支付需要的是“执行动作”。两个体系如何衔接？

**🔍 机理**
- 🟢 每月申报进度款时，承包人提交的是**实际完成工程量 × 合同单价**（本质就是BCWP的变体）。
- 🟢 监理/发包人审核时，对比的是**计划完成工程量**（BCWS的变体）与实际完成。
- 🟢 如果 SV < 0（进度滞后），发包人可能：
  - 按合同约定降低当期支付比例
  - 要求承包人提交赶工措施方案
  - 触发违约条款
- 🟢 当期应付进度款的公式（kc:1A435000_042_0056:0）就是这一逻辑的数学表达：
  > 当期应付 = [累计完成×支付比例 - 累计扣预付款 - 前期已付] - 发包人扣款

**📏 为什么这个措施有效**
- 🟢 将挣值法的“分析结果”与进度款的“支付动作”直接挂钩，形成 **“度量→判断→支付”** 的闭环。
- 🟢 当合同未约定支付比例时，80%的最低标准（kc:1A435000_042_0056:1）充当安全底线，防止发包人过度压款影响施工连续性。

### 🔗 因果链 ④：调值公式 —— 通胀风险如何分摊？

**📌 成因**
一个大型项目（如真题中的660万/14250万级合同）工期可能长达数年。签约时的价格到竣工时可能大幅变化，必须有一种“自动修正机制”。

**🔍 机理**
- 🟢 调值公式将合同总价拆为**固定部分a₀**（利润、管理等不随市场波动）和**可调部分a₁~a₄**（人工、钢材、水泥等主材）。
- 🟢 结算时仅对可调部分按**当期价格指数/基期价格指数**的比例修正。
- 🟢 公式：**P = P₀(a₀ + a₁×A/A₀ + a₂×B/B₀ + a₃×C/C₀ + a₄×D/D₀)**
- 🟢 关键约束（kc:1A435000_045_0064:1）：
  - a₀通常在0.15~0.35之间
  - 只调整对总造价影响大的少数项
  - 调整幅度一般≥±5%才触发
  - 考核地点应在工程所在地

**📏 为什么这个措施有效**
- 🟢 既保护承包人免受材料暴涨冲击，又防止发包人因价格下跌损失——风险**双向分摊**。
- 🟢 固定部分a₀确保承包人仍需承担一定的管理风险，不鼓励完全躺平。
- 🟢 5%阈值过滤小波动，减少结算争议。

## 🧩 镜头小结：C02 的教学逻辑线

```
预付款计算（扣暂列金）
    ↓
每月进度款申请（BCWP思路）
    ↓
挣值法四指标度量进度/成本健康度
    ↓
80%最低支付比例兜底
    ↓
竣工验收 → 调值公式修正结算价
    ↓
质保金≤3%扣留 → 最终结算
```

**五句话记住C02**：
1. 🟢 预付款要扣暂列金再乘比例。
2. 🟢 进度款 = 累计完成×支付比例 - 累计扣回 - 已付 - 扣款。
3. 🟢 BCWP告诉你挣了多少，BCWS告诉你该挣多少，ACWP告诉你花了多少。
4. 🟢 调值公式是通胀的“自动修正器”，固定部分0.15~0.35。
5. 🟢 质保金别超过3%。
