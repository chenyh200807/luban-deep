- **日期**: 2026-06-20

- **定位**: 这是生产引擎（造说明书）的方法记录，不是导航（运行时辅导）。两者靠 pack 文件交接。

## 一、方法：深度考点 pack 编译法

### 流水线（一个考点一次）

```
① 挖矿(跨章抽取去重)
   从 RichLeaf v3.2 编译库(5705点)按考点关键词筛 → 去重污染 → 得焦点源料
   产物: _Q02_compiled_source.json (31单元/93采分点/跨7章)
② 炼钢(召唤 AI 专家团 — workflow)
   Phase1 专家分工(4镜头并行): 聚拢原理 / 出题人 / 采分边界 / 误区动画
   Phase2 对抗验证(4审查员并行): 逐镜证伪, 三色降级, 抓造假
   Phase3 汇编(1 agent): 合成最终 pack + 写盘
③ 产出: 考点pack.md (R1-R8 + 跨章全景 + 因果层 + 误区→错因 + 动画分镜 + 缺口表)
```

### 关键设计（为什么这么炼）

1. **三色溯源内建**: 每条 claim 标 🟢锚定 / 🔵通识 / 🔴待验证。🔴 = 真题/真人/你终审该夯的精确位置。
2. **对抗证伪防同源幻觉**: 生成镜头之外，独立审查员专门打假。这是捅破"几个 AI 互相说服的自洽幻觉"的关键。
3. **对齐既有权威，不立第二套**: 知识身份→canonical taxonomy node_code；错因→`ERROR_CODE_REGISTRY`；结构→`case_family_structure` L0-L7；判分/学情→既有 authority。pack 只发候选。
4. **预抽真矿喂团队**: 先把焦点源料抽好(含教材原文 quote + point_id)，团队炼的是真矿不是空气。

### 成本与复用

- **成本**: 9 个 Opus agent、约 **85 万 token**、**约 17 分钟** / 考点。铺满 60 ≈ 5000 万 token 量级。
- **可复用**: workflow 脚本已落盘，可改 `scriptPath` 迭代或换考点重跑。
- **本轮局限**: 是 Opus 多镜头**自对抗**。要捅破同源幻觉天花板，剩余 🔴 应上 **Codex/DeepSeek 跨模型对抗**(异源抓同源抓不到的)。

## 二、Q02 结果评估

### 产出规模

8 节、约 420 行：0考点身份 / 1跨章知识点全景(15点散7章) / 2原理因果层 / 3 R2不变量 / 4 examiner_intent+R3/R4 / 5 R5采分+R6答案+R7边界 / 6 R8误区→error_code→解药(8条) / 7 动画分镜 / 8 Authority缺口表。

### 质量证据（为什么算"真"）

- **对抗抓出 13 处造假**并留痕，其中 **1 处 SEV-1**：第一稿编造"2023真题答案=50m与教材40m冲突需移交教研"，审查员查实=纯造假(40m唯一官方口径,50m是被判错的干扰项)，"若不修会污染判分库"。→ 证明对抗层真在防同源幻觉。
- **93 个采分点 point_id → chunk 映射逐条核对一致**；核心数值全锚教材原文 quote。
- **真题逐年取证**(2017/2019/2021/2022/2023/2025 各命中)；撤回了"八年命中"等 overclaim。
- **8 个误区全映射注册表真实 error_code**(E02/E05/E06/E07/E10)，零自造码。

### 🟢/🔴 分布（强弱一眼）

| 强(🟢) | 弱(🔴) |
|---|---|
| 知识点/数值/采分点/因果链/误区→错因 | **R7 真人边界答案(最弱,全候选,缺真实考生作答)** |
| 跨章聚拢(7章并1表) | node级频次张力(桶频184 vs node 1A413=5) |
| 真题逐年锚 | 2019整题答案数字串、MCQ错因平移 |

### 评级

**内容达到"大师级"**——足以喂判分/诊断/讲解/出题四件事（已用学生烂答案 demo 验证）。但状态是 `candidate_teaching_prototype`，**未签发、不授权 runtime 消费**。进 active 还差：R7 补 30-50 条真人边界、分值权重(signed artifact)、剩余 🔴 跨模型夯实。

## 三、动画就绪度评估（Q02 能不能做教学动画）

对照真实教学动画 IR（`*.lesson.json` 的 `teach.beats`，每 beat 需：narration / anchor(防漂移) / sync_keyword(板书高亮) / animation_action(camera+keycard,data-id目标) / keycard）：

| 维度 | Q02 §7 提供了吗 | 判断 |
|---|---|---|
| 讲什么(旁白内容) | ✅ 旁白锚点 S1-S5 | 够 |
| 画什么(visual隐喻) | ✅ 火苗/温度色带/对冲箭头/应力对撞/四阀门 | 够 |
| 怎么动(reveal顺序) | ✅ 严格沿因果链, 只动 transform/opacity | 够 |
| aha 设计 | ✅ "四个数字=同一条链上四个阀门" | 够 |
| 防漂移锚 | ✅ 每句可锚回 §1/§2 的 🟢 事实 | 够(Q02三色优势) |
| **renderer 吃的 lesson.json IR** | ❌ §7 是分镜稿(prose/表), 不是结构化 beats | **差一步转换** |

**结论**:
- **够，但差一步格式转换。** Q02 §7 已经给齐了教学动画**最难、最依赖深知识的那部分**(故事线/揭示顺序/画什么/说什么/aha)——这正是以前缺的。剩下是机械转换：§7 → `lesson.json`(9-12个beat,补 anchor/sync_keyword/animation_action/keycard) → `render_teaching_animation.py` 出 HTML + `build_lesson_narration` 配音。
- **形态 A(因果链揭示)**: 内容齐 + 渲染器已有(process_step_reveal/F16 renderer) → **转成 lesson.json 就能出片**。
- **形态 B(配合比计算白板)**: 内容有, 但**计算白板渲染器本身还没造**(动画体系 master plan 标为 P0 缺口) → 暂出不了, 等渲染器。

**一句话**: Q02 喂教学动画的"灵魂"够了(形态A可直接推进出片), 缺的是"§7→lesson.json"这一步转换 + 形态B的渲染器。
