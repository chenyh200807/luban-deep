## Runtime Authority 关键发现

`asset_gap_map_v1` 明确区分:

- `pointer_published`: pointer 自身是否 published。
- `payload_manifest_published`: payload manifest 是否 published。
- `consumer_evidence_status`: 是否有真实 consumer evidence。
- `hash_gate_status`: pointer hash 与 payload manifest hash 是否匹配。
- `gap_kind`: runtime 缺口类型。

当前 4 个 published pointer 中:

| namespace | gap_kind | hash_gate_status | 说明 |
|---|---|---|---|
| `kb_v5_chunks_full` | `published_pointer_no_consumer_evidence` | `matches` | hash 对齐，但缺 consumer evidence |
| `lecture_teaching_cards` | `published_pointer_no_consumer_evidence` | `matches` | hash 对齐，但缺 consumer evidence |
| `case_rubric_full` | `published_pointer_no_consumer_evidence` | `unverified` | 找不到 payload manifest metadata |
| `topic_waterproof` | `published_pointer_payload_manifest_conflict` | `mismatch` | pointer published=true，但 payload manifest published=false，hash 不一致 |

另外:

- `v_case_rubric_scored` 的 pointer policy 是 `runtime_read_allowed=false`。
- `rubric_grader_v1` 默认 `LUBAN_CASE_RUBRIC_BANK_SLOT=legacy` 会读 `v_case_rubric_scored/case_rubric_scored.json`。
- 因此它被单独标为 `runtime_policy_conflict_live_reader`，不能静默当成已签发 runtime truth。

## 三原则落地

- **Thin wrappers, fat skills**: `build_asset_gap_map.py` 只做缺口聚合和路由，不补 OCR、不编译 PDF、不判分、不签 runtime；后续进入 PDF compiler、rubric compiler、runtime consumer gate 等胖能力。
- **First principles**: 一等事实不是“文件存在”，而是“证据链是否足以被签发和消费”。
- **Less is more**: 不新增第二套 registry，不复制 payload，不把 candidate 升级为 truth，只输出缺口队列和 pass criteria。

## 诚实边界

- 139 个真题内容缺口不是同一种单位，分别来自 taxonomy chunk、case analysis、case score。
- 21 个 P1 PDF 只是下一步优先队列，不代表其它 PDF 永久不重要。
- 383 个 JSON 的 source claim review 缺口不等于 JSON 不可用；它表示这些 JSON 仍是 raw evidence ledger。
- 4 个 published pointer 仍不能称为 production-ready；至少需要 consumer trace / hash / schema / rollback evidence。
- 本产物不能写 runtime_supply、official score、LearnerState、GBrain 或 production registry。
