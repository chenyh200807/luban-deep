## 二、关键发现:被判的是什么答卷(诚实核查)

逐一核了「被判分的学生答卷」的真实来源 —— **全部是合成 / archetype / fixture,真实考生作答仍 = 0**:

- **m35 v3 的 162 行**:源 `tests/fixtures/luban_m35_fastapi_case_subquestions_20q_100a/student_answers.jsonl`,挂**真题题干(Q2023 等)**但答案是**能力分层合成**(`ability_label=high` / `answer_quality_label=excellent` / `estimated_score_range`)。
- **arbitration panel**:学生是 **archetype**(S3 = 「口号化空泛」等),合成对抗样本。
- **`real_answer_teacher_review_pilot_20260604`**:名字带 real,但 `answer_type=existing_fixture`,FINDING 明确「reviewer 是 `pilot_teacher_review`,**不是真人老师**」「DB mode: fake;no real DB written」。
- **`docs/原始数据/.../近三年案例题_按学生答卷排版.md`**(用户本轮给的):10 学生 × 15 题 = 150 **模拟作答**,「预估得分不等同官方评分」。

→ 「裁判(多 LLM 陪审/仲裁)」就位且验证;「真实考卷」未到位。

## 三、订正旧结论(留迭代痕迹,约定 #6)

**被订正文档**:
- `docs/数据盘点/2026-06-16-母题引擎资产利用全图.md` §三 / §五 / §六
- `docs/数据盘点/2026-06-16-编译资产盘点.md`(「缺真人签字」一句把两件事混了)

**旧结论(不准确)**:「唯一真缺口 = 真实考生作答 × 专家裁决判分一致性数据」。

**订正为(拆成三件可分开的事)**:
1. **专家裁决侧(多 LLM 陪审/仲裁)= 不缺。** 基础设施已建并验证:arbitration panel 共识 90% 复现参考金标、four_arm judge MAE 0.075 / 点 P 1.0、m35 带对抗检察官+变异测试。**用户「我们都是多 LLM 共同做的」属实。**
2. **真实考生作答侧 = 仍缺。** 所有被判语料是合成/archetype/fixture(见 §二),真实考生作答 = 0。
3. **金标治理升级 = 仍开口。** 金标 authority 仍 `ai_council_directional` / `quality_claim_allowed=false`。升 `governed_gold` 需全量 Fleiss kappa > 0.6;M35 v3 全量 kappa = −0.05,**根因是 fable/opus 订阅额度墙弃票(104/67)损坏协议,非模型分歧**;`arbitration_gold_panel` 纯 API 路线(0 弃票)是已验证的修法,只差全量复跑(485 单元,< $0.30)。

## 四、诚实边界(eval-design 自检)

- 上述「判分一致性」是**模型间一致 + 模型 vs fixture 参考金标一致**,**不是** vs 真人/官方裁决一致;存在「多 LLM 自评同源循环」风险(four_arm 已专设争议桶 `deepseek_dominant_or_disputed` 抗这个,但锚仍是 AI 自产金标)。
- 参考金标本身可能偏严(panel 反查出 S4 P8/P9 全票 partial vs 参考 miss)——金标未经人审/官方钉,不能当 official。
- 全部记录 `production_write=0 / canonical_truth_write=false / published_registry_write=false`;authority 永不冒充 official。
- 单题(Q3 50 点)高一致 ≠ 全量过 kappa 门;升 governed_gold 必经全量验证。
