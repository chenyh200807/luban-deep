# OpenMAIC 图解引擎评估：屋面卷材防水起鼓割补工序

> 日期：2026-06-17
> 性质：第二意见评估，不是采用决策。
> 结论先行：**OpenMAIC 的实时白板不适合作为鲁班智考“规范级建筑构造图”引擎；它的交互 HTML / SVG diagram widget 有中等复用价值，适合作为“图解微课静态互动卡”的参考形态。**

## 一句话结论

**白板引擎可复用度：3/10；最该复用的是“交互 HTML 的 SVG 流程图组件 + 离线资源内联导出思路”，不是它的多智能体课堂 App、实时白板或课堂播放形态。**

如果把“白板 + HTML 渲染”整体看成图解微课参考：**综合可复用度约 5.5/10**。能借鉴表现层和导出链路，但专业正确性必须由鲁班自己的母题/规范/采分点 schema 驱动，不能交给 OpenMAIC 的 LLM 自由生成。

## 范围

本次只评估 OpenMAIC 能否辅助鲁班智考的“图解微课”：

- 主题：`一级建造师 建筑实务 — 屋面卷材防水起鼓割补工序`

## 问题 A：白板能否画正确防水构造剖面 / 工序图？

### 结论

**实时白板不能可靠画出“规范级防水构造剖面”。它最多适合通用流程图、公式、表格、简单示意。**

本次 demo 的图解是“9 步工序流程图”，不是构造剖面图。截图中可以看到 9 个节点：

- 割开鼓泡
- 排气干燥
- 清理基层
- 涂刷基层处理剂
- 嵌填 / 修补
- 增铺附加层
- 热熔或粘贴卷材
- 搭接封严
- 蓄水 / 淋水检验

它表达了顺序和考试提示，但没有表达：

- 屋面基层 / 找平层 / 保温层 / 防水层 / 附加层 / 面层的剖面关系；
- 卷材搭接方向、宽度与节点边界；
- 鼓泡切开后新旧卷材层次关系；
- 附加层覆盖范围的几何边界；
- 屋面节点构造如女儿墙、泛水、收头、阴阳角等。

因此它可以做“流程图解微课”，不能做“构造详图权威图”。

### 源码证据

OpenMAIC agent-facing 白板动作限制在这些 primitive：

- `wb_draw_text`
- `wb_draw_shape`
- `wb_draw_chart`
- `wb_draw_latex`
- `wb_draw_table`
- `wb_draw_line`
- `wb_draw_code`

对应源码：

```text
/tmp/openmaic-luban-eval/OpenMAIC/lib/types/action.ts
```

其中 `wb_draw_shape` 只暴露：

```text

虽然底层 DSL 的 `PPTShapeElement` 支持任意 SVG path：

/tmp/openmaic-luban-eval/OpenMAIC/packages/@maic/dsl/src/slides.ts
```

但实时白板 action 没有把“任意 path / domain layer / construction section schema”暴露为稳定工具。因此 LLM 即使想画构造剖面，也只能拼矩形、线条、文字，正确性不可控。

## 问题 B：结构化 / 代码渲染，还是自由文生图？

### 结论

**本次 demo 不是自由文生图，是结构化 HTML + SVG + JSON config + JS 渲染。**

证据：

```json
{
  "hasSvg": true,
  "svgCount": 1,
  "hasCanvas": false,
  "imgCount": 0,
  "mentionedSteps": [
    "割开",
    "排气",
    "干燥",
    "清理",
    "基层处理剂",
    "嵌填",
    "修补",
    "附加层",
    "热熔",
    "粘贴",
    "搭接",
    "封严",
    "蓄水",
    "淋水"
  ]
}
```

HTML 内嵌：

```html
<script type="application/json" id="widget-config">
```

config 里有 9 个节点、8 条边、`revealOrder`。

这比文生图好，因为：

- 节点文本可检索、可审校；
- SVG 可截图、可抽取；
- 交互逻辑可改；
- 可做离线内联；
- 可被小程序 WebView 或静态 HTML 承载。

但它仍然不是“专业图纸 DSL”。因为图中节点、数值、考试提示仍由 LLM 生成。比如 demo 中给出：

- 附加层宽度不小于 300mm；
- 长边搭接 ≥100mm；
- 短边搭接 ≥120mm；
- 蓄水 24h、淋水 2h；
- 蓄水深度 20-30mm。

这些必须回到鲁班的规范 / 教材 / 真题 / 采分点 authority 校验。OpenMAIC 只能算渲染候选，不能当知识 authority。

### 移植成本

| 方案 | 成本 | 判断 |
|---|---:|---|
| 直接嵌 OpenMAIC classroom | 高 | 不建议，课堂 App 形态过重 |
| 抽 interactive HTML 到 WebView | 中 | 可做评估型微课卡，但要清洗 JS/CSS/CDN |
| 抽运行时 SVG 做静态图 | 低-中 | 适合只展示流程，不适合复杂交互 |
| 重写鲁班自己的 SVG/HTML 模板，参考 OpenMAIC 形态 | 中 | 推荐 |

### 关键风险：teacher action selector 错位

OpenMAIC 为 diagram widget 生成了 teacher actions：

```json
[
  { "type": "highlight", "target": "#n1" },
  { "type": "highlight", "target": "#n6" },
  { "type": "highlight", "target": "#n8" },
  { "type": "highlight", "target": "#n9" }
]
```

但实际运行时 SVG 节点是：

```javascript
g.setAttribute('data-id', node.id)
```

Playwright DOM 检查：

```json
{
  "byId": {
    "n1": false,
    "n6": false,
    "n8": false,
    "n9": false
  },
  "byDataId": {
    "n1": true,
    "n6": true,
    "n8": true,
    "n9": true
  }
}
```

这意味着 OpenMAIC 的 widget actions 可能无法准确高亮目标节点。对鲁班来说，这类 selector 稳定性必须由我们自己的渲染 contract 管住。

## 问题 D：license + 自托管是否适合鲁班？

### License

OpenMAIC 仓库 license 为：

```text
AGPL-3.0
```

这对鲁班的含义：

- 不建议把 OpenMAIC 源码、packages、组件直接并入 DeepTutor / 小程序后端。
- 不建议基于它改一个内部图解服务再联网提供给用户，除非接受 AGPL 义务并做法务确认。
- 可以把它作为本地评估工具、第二意见、设计参考。
- 生成的 HTML 是否可直接商用需要进一步法务确认；但即便 license 可行，专业正确性仍不应依赖 OpenMAIC 自由生成。

### 自托管

自托管可行：

- Node >= 20；
- pnpm >= 10；
- `pnpm install` 后 `pnpm build` 通过；
- `/api/health` 曾返回 `success:true`；
- 支持 DeepSeek / Qwen / OpenAI-compatible providers；
- 支持导出 `.pptx`、交互 HTML、课堂 ZIP。

但它作为鲁班生产依赖不合适：

- Next 16 + React 19 + LangGraph + 多 agent + TTS/ASR/media/export，系统面太大；
- 运行时课堂播放模型不符合鲁班“小程序丢分诊断 + 图解微课”的主场景；
- 生成一节课耗时偏长，demo 中第 2 个 HTML diagram 场景约两分多钟才完成；
- 如果线上实时生成，会拖慢用户反馈闭环；
- AGPL 和 Next server 运维边界都不适合作为鲁班主链路。

## 能复用什么

### 1. 交互 HTML / SVG diagram 的产品形态

适合鲁班做：

- 工序微课卡；
- 错因解释卡；
- 采分点补点卡；
- “下一步 / 上一步”分步揭示；
- 点击节点看“操作 / 要点 / 考点 / 易错”。

这与鲁班“做完题后立刻讲清楚错在哪里、下一步练什么”的产品方向匹配。

### 2. 离线资源内联思路

OpenMAIC 的 `inlineHtmlAssets()` 对小程序 WebView 有参考价值：

- 扫描外部 link/script/img/css-url/importmap；
- 抓取资源；
- 转成 data URI；
- 生成失败报告。

鲁班可借鉴这个“导出前检查 + 内联 + 失败报告”的思路，但不要复制 AGPL 源码。

### 3. Diagram widget 的数据结构思路

本次 HTML 的核心结构是：

```json
{
  "nodes": [],
  "edges": [],
  "revealOrder": []
}
```

鲁班可以做自己的更窄 schema：

```json
{
  "topic_id": "roof_membrane_bulge_repair",
  "diagram_type": "procedure_flow",
  "nodes": [
    {
      "id": "cut_bulge",
      "label": "割开鼓泡",
      "operation": "...",
      "exam_point": "...",
      "common_error": "...",
      "source_refs": []
    }
  ],
  "edges": [],
  "validation_rules": []
}
```

注意：这应该由鲁班母题包 / 知识库 / 规范依据编译出来，不由 OpenMAIC 现场自由发挥。

## 不能复用什么

### 1. 不复用多智能体课堂形态

鲁班不是课堂 App，核心不是 AI 老师 + AI 学生圆桌互动。鲁班当前主问题是：

```text
答题 → 判分 → 错因 → 图解 → 复测
```

OpenMAIC 的 Plan agent / scenario agents / 课堂回放不是主链路，接入会制造新复杂度。

### 2. 不复用实时白板作为专业图纸引擎

白板 primitive 太通用，不能承担防水构造正确性。

如果鲁班需要“构造剖面图”，正确做法是：

- 自己定义建筑构造图 schema；
- 由教研 / 规范数据编译；
- 用 deterministic SVG renderer 输出；
- LLM 只负责解释和变体讲解，不负责自由画图。

### 3. 不复用它的知识生成作为 authority

OpenMAIC demo 里的数值、步骤、规范表达必须二次审核。它能生成“像教学内容的图解”，不等于它能生成“可考试采分的权威图解”。

## 与鲁班原则的对齐判断

### Thin wrappers and fat skills

如果复用，只能作为 thin rendering wrapper 的参考。鲁班真正的 fat skill 应该是：

```text
母题包 / 图解微课编译器 / 采分点解释器 / 错因诊断器
```

OpenMAIC 不应成为新的知识 authority 或教学策略 authority。

### First principles

鲁班需要解决的不是“生成一个课堂”，而是：

```text
学生错了一个点后，能否在 30-90 秒内看懂正确做法，并在下一题/明天复测证明掌握。
```

所以图解引擎必须服务“丢分诊断后的即时解释”，而不是服务“大课生成”。

### Less is more

不引入 OpenMAIC 全套系统。只学习三个小点：

1. HTML/SVG diagram 卡片；
2. step reveal 交互；
3. 离线导出 / 资源内联检查。

## 建议决策

### 推荐选项

**不采用 OpenMAIC 作为依赖；把它作为图解微课表现层参考。**

鲁班下一步可以做一个自研极小闭环：

```text
Archetype Pack / 知识点解释卡
→ Diagram MicroLesson Schema
→ deterministic SVG/HTML renderer
→ 微信小程序 WebView / skyline-safe static card
→ 用户答错后展示
→ 下一题复测
```

第一个试点不要做复杂防水剖面，先做：

```text
屋面卷材防水起鼓割补 9 步工序流程图
```

等流程图稳定，再做构造剖面图。

### 不建议选项

- 不要把 OpenMAIC npm packages 复制进 DeepTutor。
- 不要接入 OpenMAIC 课堂 ZIP runtime。
- 不要让线上用户实时等待 OpenMAIC 生成微课。
- 不要用 OpenMAIC 文生内容当规范依据。
- 不要用 AGPL 代码改造成鲁班后端服务，除非法务明确接受。

## 最小下一步

建议不继续评估 OpenMAIC 全功能。下一步直接做鲁班自己的 1 张图解微课卡：

```text
主题：屋面卷材防水起鼓割补工序
范围：9 步流程图，不做构造剖面
数据来源：现有母题/教材/真题/讲义/规范候选
产物：一个鲁班自研 static HTML/SVG demo
验收：
1. 手机端 390px 无横向滚动；
2. 每个节点有“操作 / 要点 / 易错 / 采分表达”；
3. 所有数值有 source_ref；
4. 题后能从错因跳到对应节点；

```

做到这一步，才是真正服务鲁班“答题后即时兑现价值”的图解引擎，而不是引入一套课堂系统。
