## 二、视觉抽取方法

1. `mdls -name kMDItemNumberOfPages` 取页数;案例解析通常在后半部分(2025 在 pages 9-17)
2. `Read` 工具按 pages 区间读 PDF(视觉/图像),≤20 页/次
3. 按版式约定逐题逐点转录(见 §四)
4. **每抽完一份必须人工复核转录准确性**(视觉 OCR 有误差;数字/术语尤其核)

## 三、字段 schema(per-point 一条记录)

```json
{
  "year": 2025,
  "exam": "建筑工程管理与实务",
  "source": "佑森教育闫力齐独家解析",
  "source_authority": "training_org_analysis",
  "case_no": 1,                 // 案例(一)=1
  "sub_q_no": "1",              // 小题号
  "sub_q_total_score": 5.0,     // "本小题X分"
  "point_seq": 1,               // 该小题内采分点序
  "point_text": "钢筋绑扎机器人",
  "point_score": 1.0,           // 该采分点分值
  "point_type": "列举",         // 见枚举
  "partial_credit_rule": null,  // 如 "写出3项即得3分"
  "page": 9
}
```

`point_type` 枚举:`列举 / 计算步骤 / 计算结果 / 判断 / 改错 / 程序 / 分类 / 措施`

## 四、版式标注约定(佑森解析)

| 标注 | 含义 | 抽取动作 |
|---|---|---|
| `(本小题 5.0 分)` | 小题满分 | → `sub_q_total_score` |
| 行尾 `(1.0分)` `(2.0分)` `(0.5分)` | 该采分点分值 | → `point_score`(粒度可到 0.5) |
| `(一)(二)…` | 案例号 | → `case_no` |
| `1. 2.…` | 小题号 | → `sub_q_no` |
| `(1)(2)` `①②` | 点内层级 | → `point_seq` 拆分 |
| `【评分准则:写出3项,即得3分】` | 部分给分规则 | → `partial_credit_rule` |
| 计算式如 `分部分项=2200×12000/10000=2640.00万元 (1.0分)` | 计算步骤分 | `point_type=计算步骤`,记式子 |

## 五、★ 关键发现(踩点制:给分点池 ≥ 小题满分,判分封顶)

首份验证就抓到一个**必须写进协议**的事实:**Σ(point_score) 常 > sub_q_total / case 总分**。
- 2025 各案例 Σ(point_score):案例一=20 / 二=20 / 三=20,但**案例四 Σ=30、案例五 Σ=28.5**(超 20);案例五题4 内部 (1)4.0+(2)≥4.0 也超本小题 6.0
- **这不是抽取错误,是踩点制的本质**:佑森把"所有可能给分点"都列出并各标分,实际阅卷"答对一点给一点、累加到小题满分**封顶**"。给分点池 > 满分是正常的
- **对判分逻辑的含义(写进判分规则)**:`小题得分 = min( Σ(命中采分点 × point_score), sub_q_total )` —— **累加后按 sub_q_total 封顶**;不能假设 Σ(points)=满分,也不能用 Σ 反推官方
- 抽取时 `point_score` 与 `sub_q_total` **都要记**,二者关系是"池 vs 封顶",不是"分项 vs 合计"
