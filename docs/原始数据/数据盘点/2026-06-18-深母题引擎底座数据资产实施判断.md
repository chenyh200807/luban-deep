## 一、结论先行

现有数据资产已经足够做**深母题引擎底座的第一条竖切**，但还不够做“自动量产 30-40 个正式母题包”。

正确产品化方式不是让出题、判分、诊断、讲解、复测五条链各自去扫 `artifacts/` 或 raw PDF，而是建立一个**签发型 Deep Archetype Pack 编译层**:

```text
source registry / source_refs / sha256
-> raw question / textbook / standard / PDF rubric / RichLeaf / PGO candidates
-> deep archetype compiler
-> deterministic gates + expert review
-> signed/versioned case_family_production + case_family_structure
-> runtime_supply / LubanContextPack read-only consumption
-> 既有 grading / diagnosis / teaching / revalidation / LearnerState 链路消费
```

一句话: **数据已经够做底座，真正缺的不是资产，而是把 raw/source/shadow/candidate 资产推进成 signed、versioned、read-only、可回滚的母题包。**

---

## 二、底座的单一权威地图

深母题引擎必须遵守既有两对象设计:

| 对象 | 责任 | 不能做 |
|---|---|---|
| `case_family_production` | 指针层: source_refs、taxonomy_ref、question_bindings、grading_artifact_id、scoring_point_refs、task_scope | 不复制 scoring rule、不拥有教材/知识/判分 truth |
| `case_family_structure` | 教学结构层: invariant、examiner_intent、scenario_templates、variable_rules、misconception、variant、retest discriminator | 不写分数、不写 canonical 错因结论、不写 LearnerState |

运行时铁律:

- 深母题只读、只发候选、不写结论。
- 正式判分归 signed grading artifact / `CaseGradingSkillKernel`。
- 错因 canonical 轴归 `ERROR_CODE_REGISTRY`。
- 知识身份归 canonical taxonomy。
- 学情归 `learning_evidence` / `LearnerStateService` / `revalidation_queue`。
- runtime 只能读签发后的 `runtime_supply` / `LubanContextPack`，不能临场扫 raw artifacts。

## 四、当前最适合的底座形态

### 4.1 不做“题库平台”，做“签发型母题编译器”

底座应由四层组成:

1. **Source Registry 层**: 只允许 canonical raw sources 进入编译，记录 source path、sha256、span_hash、authority_tier、display_policy、training_policy、official_claim_allowed。
2. **Candidate Compiler 层**: 从真题、教材、规范、RichLeaf、PGO、lecture cards、PDF rubric 中产出 R1-R8 候选。
3. **Gate + Review 层**: 校验 source、taxonomy、scoring refs、error_code、task_scope、boundary answers、official_score_allowed。
4. **Runtime Supply 层**: 只发布 signed/versioned pack；消费者只读，不临场拼资产。

这层应是 fat compiler / fat skill。前端、prompt、adapter 都只能是 thin wrapper。

### 4.2 第一条竖切不要贪大

建议拆两条互补线:

| 线 | 母题 | 目标 | 为什么 |
|---|---|---|---|
| 前台留存薄切片 | F16 防水 | 5 天 MCQ / 轻练 / 选错即诊断 / 次日复测 | 验证忙碌复考成人是否愿意每天回来，并采真实作答与 confident-wrong |
| 后台深判分旗舰 | F01 进度网络计划 | 证明 anti-over-credit、步骤分、路径 / 工期 / 调整措施的保守判分 | 最能证明普通 AI 会看大意给分，而鲁班能按采分点守边界 |

`M_danger_work_expert_argumentation` 适合作为“理想样板形状”的 J01 教学原型，但当前仍缺 source hash、ERROR_CODE 映射、30-50 条人审边界答案和 signed scoring refs，不能直接当 active runtime pack。

## 五、30 天执行建议

| 时间 | 动作 | 产出 |
|---|---|---|
| Day 1-3 | 冻结 source registry allowlist | 题库、教材、taxonomy、标准、PDF rubric、讲义的可编译白名单 |
| Day 1-7 | 抽取 / 回填 2021-2025 + 2022 补考 PDF rubric，并复核 2025 | point_score、sub_q_total_score、cap_rule、score_authority |
| Day 5-12 | 对齐 PGO 482 点 / RichLeaf v3.2 5705 点 / PDF rubric | review queue；不硬凑 point 粒度 |
| Day 8-15 | 打磨 F16 留存薄切片 | MCQ distractor -> misconception -> error_code -> 教材定位 |
| Day 8-15 | 打磨 F01 深判分旗舰 RC | source_refs、scoring refs、variant boundaries、boundary answer draft |
| Day 12-20 | 映射 misconception 到 `ERROR_CODE_REGISTRY` | 禁 unknown_error active；新增错因必须走 registry 评审 |
| Day 15-25 | 采集 30-50 条边界答案 | 真实作答优先，专家裁决兜底 |
| Day 20-30 | 跑质量门与 shadow eval | 过则 RC；不过保持 candidate |

30 天内明确禁止:

- 禁止扩到 30-40 个母题。
- 禁止自动量产。
- 禁止把 shadow / workbench 当 active。
- 禁止宣称 official scoring moat。
- 禁止让深母题写 LearnerState、分数、canonical 错因结论。

## 六、进入 active 的 Pass Criteria

一份母题包至少同时满足:

1. 每个关键字段有 `source_ref + content_sha256 / span_hash`。
2. R2 invariant 能一句话说清，并能解释 ≥5 个换皮场景。
3. R3/R4 的变量空间封闭，LLM 不得自创工程类型、阈值或判据。
4. R5 只引用 signed / candidate scoring refs，不复制 rubric rule。
5. 逐点分值、题级封顶、`official_score_allowed` 血统明确。
6. R7 有 30-50 条真人或专家裁决边界答案。
7. R8 全部映射 `ERROR_CODE_REGISTRY`，禁 `unknown_error` 进入 active。
8. light / semi-write / retest 都有 `task_scope` 与 `binding_level`。
9. runtime 只读签发包，不扫 `artifacts/`，不临场读 raw PDF。
10. F16 扩包前必须有 D1/D7 留存与复测证据。

## 七、最终判断

这批数据资产可以成为深母题引擎底座，但底座的本质不是“更多题”或“更大 artifacts 目录”，而是:

```text
可信来源 -> 候选编译 -> 人审/规则门 -> signed pack -> runtime read-only -> 学习证据闭环
```

现阶段最有杠杆的工程动作不是再扩素材，而是把已有资产压成三张清晰表:

1. **source registry allowlist**: 哪些源可被编译、可展示、可训练、可声明 official。
2. **case_family pack manifest**: 每个母题 R1-R8 的来源、状态、缺口、review owner。
3. **authority gap table**: score null、缺边界答案、缺真人签字、缺真实作答、缺 error_code 映射的逐项缺口。

做到这一步，鲁班的深母题引擎才有可能成为可复利的数据底座，而不是又一套 shadow 题库。
