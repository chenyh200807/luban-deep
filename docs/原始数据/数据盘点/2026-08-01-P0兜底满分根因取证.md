## 1. 前提订正：任务书的 tier 归因是反的

任务书的前提是「live 落 tier-3（`derived_from_stem`）所以给满分，offline 落 tier-2 所以正常」。**生产 DB 实证相反。**

生产 `turn_events.metadata_json` 逐轮读出的 `grading_rubric_provenance`：

| turn | 学生/档位 | `grading_rubric_provenance` | `case_grading_direct_attempt_qid` | 得分 |
| --- | --- | --- | --- | --- |
| `turn_1785487445074_a33145b927` | Q2023-03 / S03 upper_mid | **`derived_from_stem`（tier-3）** | `''` | **5.69/10** |
| `turn_1785487570740_67937d8608` | Q2023-03 / S04 mid | `on_the_fly_reference`（tier-2） | `17371` | **10/10** |
| `turn_1785487621028_68f30f43a0` | Q2023-03 / S06 low | `on_the_fly_reference`（tier-2） | `9559` | **10/10** |
| `turn_1785487652972_d36c48d4af` | Q2023-05 / S03 upper_mid | `on_the_fly_reference`（tier-2） | `17382` | **10/10** |
| `turn_1785487689836_082dad3780` | Q2023-05 / S04 mid | **`derived_from_stem`（tier-3）** | `''` | **7.65/10** |
| `turn_1785487754207_30dae0b607` | Q2023-05 / S06 low | `on_the_fly_reference`（tier-2） | `17382` | **10/10** |

**tier-2 命中率 4/4 → 全部 10/10；tier-3 命中率 2/2 → 全部有区分度。**

学员可见文案独立佐证同一结论：tier-3 两轮带「未命中题库原题/标准答案，本轮是题干推导诊断批改」+「未核到教材出处」×13/15；四个满分轮带「本评分为 AI 阅卷草稿」且「未核到教材出处」= 0。

**推论：tier-3 兜底不是病灶，不该被"修掉"。真正在服上给满分的是更高权威的 tier-2。**

### 1.1 offline/live 的差异是 harness artifact，不是同一实验

`scratchpad/eval_army/06_offline_arm.py:150-158` 构造 ctx 时直接写入：

```python
ctx = {
    "question_id": "",                      # 刻意置空，绕开 bank 查找
    "correct_answer": q["official_answer"], # 官方答案直接喂进去
    ...
}
```

脚本自己的注释写明「qid="" forces the open-world tier-2 path keyed on THIS question's official answer」。**offline 拿到的是完整 4/5 问的官方答案，live 拿到的是 bank 里某一个小问的兄弟行。** 两臂输入不同，「offline 排序 12/12、live 1/6」的对比不成立为判分核的能力差异，只能说明**判分核在拿到完整参考答案时表现正常，在真实入口上拿不到完整参考答案**。

## 2. 钉一：live 为什么拿不到整题参考答案

### 2.1 tier-1（编译 rubric）在真实入口上结构性不可达

`deeptutor/tutorbot/agent/loop.py:1727-1741`：pgo 编译 bank 的键是 `{exam_year}::{source_chunk_id}::E{n}`，运行时能合成候选键，但代码**刻意只导出 marker、绝不喂进 `ctx.question_id`**：

> `E 索引在 questions_bank 落显式列并回填兄弟行 source_chunk_id 前，候选键只导出 marker 供观测窗口，绝不进 ctx.question_id 喂 load_rubric。`

（依据是 `2026-07-30-复合qid唯一性与E索引权威审计.md`：模拟建键命中 23/354、语义正确 0 条、全部错绑到相邻小问 rubric。这个自我设限是**正确的**，不该撤。）

于是 `_grade_one_case_v1`（`deeptutor/capabilities/deep_question.py:2473`）第一跳拿到的 `qid` 是 supabase 行的数字 id（`17371`/`9559`/`17382`），不是 pgo 键，`_G.load_rubric(qid)` 必然空。

**生产实证**：6 轮全部 `case_rubric_bank_slot = legacy:authorized:174`，tier-1 零命中。174 题编译 bank 在聊天判分通道上一次都没进过。

### 2.2 tier-2 拿到的是「兄弟行」——一个小问，不是整题

`deeptutor/services/rag/pipelines/supabase.py:2700-2775`：案例题在 `questions_bank` 里是**按小问拆成多行存的**（兄弟行）。exact 匹配把命中的行按 `display_index` 去重排序后，只取 `ordered_rows[0]` 作 `selected_row`，其 `correct_answer` 成为顶层参考答案：

```python
selected_row = ordered_rows[0] if ordered_rows else {}
...
"correct_answer": selected_row.get("correct_answer") or "",
"coverage_state": "multi_subquestion_exact" if len(covered_subquestions) > 1 else "single_subquestion_only",
```

`loop.py:1553-1630` `_current_case_reference_from_context` 再按「与学生粘贴题面匹配」筛一遍 `covered_subquestions`，返回拼接后的 reference。

**代码注释里已经自陈了这个 bug**（`loop.py:1795`）：

> `覆盖对账必须对学生所见题面（live 实证：exact 命中单小问兄弟行时，eq.stem 只含 1 问——拿 bank 行当整个世界，4 问粘贴被判 10/10）。`

也就是说：这个 10/10 现象**上一轮已经被观察到，修的是"对账基准换成 user_stem"（让告警能响），没有修"分数"**。告警响了，分照给。

### 2.3 tier 分配本身非确定性——同一份粘贴，三个学生三种结果

Q2023-03 三轮的用户消息**题面部分完全相同**（`05_live_arm.py:33` 的 TEMPLATE 用同一个 `q["stem"]`），身份检索也只喂题干（`loop.py:2250`，`_probe_stem` 剥掉作答）。结果：

- S04 → 命中 bank 行 `17371`
- S06 → 命中 bank 行 `9559`
- S03 → **零命中**（`attempt_qid=''`），落 tier-3

三轮的 `case_grading_prefetch_gate` 全是 `allowed`，`exact_question_blocked_reason` 全是空串——**没有任何闸拦它，是向量检索本身对同一题干返回了不同的 top 行**。

**这意味着学生的分数取决于本轮 RAG 抽到哪一行兄弟行，而不取决于他答得怎么样。** 这是比"满分"更根上的问题：判分权威的取得是随机的。

## 3. 钉二：局部 rubric 为什么必然给满分（结构性，非 LLM 宽松）

这是本次取证最重要的一条，它推翻了"判分 LLM 太宽松"的直觉。

### 3.1 两行代码合谋

**第一步 —— 分母被强行拉满**（`deeptutor/services/construction_grading/rubric_grader_v1.py:2204-2228`）：

```python
def normalize_points_to_nominal(points, *, nominal_total=0.0, fallback_base=10.0):
    raw_total = round(sum(float(p.get("score") or 0) for p in points), 2)
    target = float(nominal_total) if nominal_total and nominal_total > 0 else float(fallback_base)
    factor = target / raw_total
    scaled = [dict(p, score=round(float(p.get("score") or 0) * factor, 2)) for p in points]
    # ... drift 修正，保证 sum == target 精确相等
```

不管这个采分点池覆盖了整题的多少，**缩放后 `sum(scores)` 恒等于整题名义满分**。`deep_question.py:2545` 和 `:2565` 在 tier-2 / tier-3 两条路径上都无条件调用它。

**第二步 —— 分母就是这个池**（`rubric_grader_v1.py:120-205`）：

```python
for p in rubric_points:
    max_score = float(p.get("score") or 0)
    max_total += max_score          # ← 分母 = 采分点池的和，不是题目满分
    ...
    awarded_total += awarded
return {"awarded_score": awarded_total, "max_score": round(max_total, 2), ...}
```

**合起来**：`max_total == nominal == 10`，而 `awarded_total == 10` ⟺ 所有点命中。

> **结论：只要采分点池里每一个点都命中，就是满分——无论这个池覆盖了整题的 1/4 还是 4/4。命中即满分是结构性必然，不是判据宽松。**

### 3.2 live 实证：7 个点全在问题1，判 10/10

`turn_1785487621028_68f30f43a0`（Q2023-03 / S06 / low）学员可见文案：

```
⚠️ 判分覆盖范围：本次仅对 问题1 命中了采分点参考（题面共 4 问）；
   问题2、问题3、问题4 未匹配到采分点参考、未纳入本次判分……
得分预估（仅已覆盖小问）： 10 / 10 分。
采分情况：命中 7 个，部分命中 0 个，漏/错 0 个。
```

题面 4 问、只判了 1 问、7 个点全中 → **10/10**。

`turn_1785487754207_30dae0b607`（Q2023-05 / S06 / low）更极端：**2 个采分点**（5 问的题），全中 → 10/10，而且**连覆盖告警都没响**（见钉三）。

### 3.3 覆盖告警是纯文案，零扣分

`deep_question.py:2645-2657` 是覆盖对账的全部消费点：

```python
_cov = _G.case_subquestion_coverage(event, question_stem=_stem_for_cov)
if isinstance(_cov, dict):
    event["case_subq_coverage"] = f"{len(_cov.get('covered') or [])}/{len(_cov.get('total') or [])}"
    if _cov.get("uncovered"):
        event["case_subq_uncovered"] = ...
        event["case_subq_coverage_note"] = _G.build_case_subq_coverage_note(_cov)
```

**只写 marker 和文案，从不碰 `awarded_score` / `max_score`。** 同样地，RAG 侧算出的 `coverage_state = "single_subquestion_only"`（`supabase.py:2769`）在全仓只被拼进 prompt 字符串（`agents/chat/agentic_pipeline.py:2364,2377`）和透传（`:3356`），**判分核 `_grade_one_case_v1` 从头到尾没读过它**。

两个"我知道自己只判了一部分"的判据都在场，都没有被接到分数上。

### 3.4 判分 LLM 并没有乱判——弱答案在被判的那一问上是对的

必须说清楚，否则修复会打偏。gold pack 的"低档"学生 S06 的 309 字作答，**问题1 与问题2 是官方答案的逐字拷贝**，问题3 截断、问题4 缺失：

```
S06 问题1：①"项目部在开工后编制了项目质量计划"；正确做法：项目质量计划应在项目策划过程中编制。②…
官方 问题1：①"项目部在开工后编制了项目质量计划"；正确做法：项目质量计划应在项目策划过程中编制。②…   ← 完全一致
```

所以 7/7 命中**在被判的范围内是正确判定**。任务书引用的「与官方答案 Jaccard 仅 0.39」是**整卷**指标，低是因为问题3/4 缺失，不是因为写错。

> **这条弱答案之所以"弱"，恰恰弱在被 rubric 截掉的那几问上。分母一缩到"他答了的那一问"，弱点就正好落在盲区里。**
>
> 推论：**收紧判分 prompt / 换更严的 judge 对这个 P0 完全无效。** 这是分母问题，不是判据问题。

### 3.5 `point_pool_exceeds_max` 与踩点封顶在此处不起作用

`deep_question.py:2503-2515` 的 `point_pool_excess` 只在 **tier-1 编译 rubric** 分支计算（`if points:` 紧跟 `load_rubric` 之后）。tier-1 在真实入口零命中（§2.1），所以这个观测量在本次 6 轮里**从未被计算过**，DB 里也确实一条没有。

已知的「V1 主路径无踩点封顶」问题独立存在，但它是"池 > 满分时打高分"；本 P0 是"池 < 整题时分母被拉满"，**方向相反的另一个病**。封顶 `min(Σ命中点分, 满分)` 解决不了本 P0——本 P0 里 Σ 恰好等于满分。

## 4. 钉三：覆盖判定为什么不稳

### 4.1 实证：同输入两遍，15 点 vs 26 点、3/4 vs 4/4

`offline_grades.jsonl` 的 A/B 两臂是**同配置第二遍**（`06_offline_arm.py` docstring 自陈 relabel 为 REPEATABILITY probe）：

| (题, 学生) | arm A 点数 / 覆盖 / 得分 | arm B 点数 / 覆盖 / 得分 |
| --- | --- | --- |
| Q2023-03 / S03 | 15 点，`3/4`（uncov=4），20.0/20 | **26 点**，`4/4`，20.0/20 |
| Q2023-03 / S04 | 18 点，4/4，16.92/20 | 20 点，4/4，17.28/20 |
| Q2023-03 / S06 | 20 点，4/4，10.4/20 | 20 点，4/4，11.5/20 |
| Q2023-05 / S03 | **31 点**，5/5，20.0/20 | **20 点**，5/5，20.0/20 |
| Q2023-05 / S06 | 21 点，5/5，6.9/20 | 20 点，5/5，**10.76/20** |

**同一份官方答案、同一个学生作答、同一份配置，抽出的采分点池在 15↔26、31↔20 之间摆动，得分在 6.9↔10.76 之间摆动（±56%）。** 覆盖 3/4↔4/4 的不稳只是这个更大不稳的一个投影。

### 4.2 归属链的三段弱判据

`case_subquestion_coverage`（`rubric_grader_v1.py:671-707`）的小问归属靠两跳：

1. `_point_question_label`（`:649-668`）先找结构化键 `question_no` / `sub_no` / `subquestion_index` / `question_index`，再用正则从 `source_qid` / `qid` / `point_id` 抠 `Q<n>` 或 `::E<n>`。**tier-2/tier-3 的 LLM 产出点这些键全靠模型自觉填**（`_DERIVE_PROMPT_TMPL` 里只有一句"无法判断才填 null"），填不填、填对不填对逐轮变。填不出 → 返回 `"整题"`。
2. `_infer_question_label_from_title`（`:724-738`）兜底：把点文本与各小问标题做 n-gram 重叠打分，**要求恰好一个标题得分 ≥4**，否则仍返回 `"整题"`：

```python
scored = [(idx, score) for idx, score in scored if score >= 4]
if len(scored) != 1:
    return "整题"
```

LLM 每轮生成的点文本措辞不同 → 重叠分越过/掉下 4 这条线 → 归属漂移。点池大小本身还在 15↔31 之间变（§4.1），**归属漂移 = 池漂移 × 判据脆弱，两层非确定性相乘**。

### 4.3 更危险的一档：告警**静默**

`case_subquestion_coverage` 有三条静默返回 `None` 的路径（`:679-698`）：

- `if not titles or len(titles) < 2: return None` —— 题面解析不出 ≥2 个小问
- `if not sp: return None`
- `if not attributed: return None` —— **一个点都归不到小问**

设计意图是"判定不出宁可沉默，不许猜"，但在**分数不受覆盖影响**的前提下，沉默 = 学生看到一个干净的 10/10，连告警都没有。

**live 实证**：Q2023-05 的两个满分轮（S03/S06）`coverage_warning = false`（`live_metrics.json`），而它们的采分点只有 2 个、题面 5 问。**该响的告警没响。** 对照 Q2023-03 的满分轮，告警响了（"题面共 4 问"）。同一个缺陷，一半场次连遮羞布都没有。

## 6. 结论与修复建议

### 6.1 三钉根因判定

| 钉 | 根因 | 权威位置 |
| --- | --- | --- |
| **一** | 真实入口拿不到整题参考答案：tier-1 因复合 qid 自我设限而结构性不可达（`loop.py:1727-1741`）；tier-2 拿到的是按小问拆存的**单个兄弟行**（`supabase.py:2700-2775`）；且 exact 匹配对同一题干非确定性，tier 归属逐轮随机（生产实证 §2.3） |
| **二** | **局部 rubric × 满分分母**：`normalize_points_to_nominal`（`rubric_grader_v1.py:2204-2228`）把任意覆盖度的点池缩放到整题名义满分，`grade_with_rubric`（`:120-205`）又以该池之和为 `max_score` → **全中即满分是结构性必然**。覆盖事实（`case_subq_coverage`、`coverage_state`）只进文案，零扣分（`deep_question.py:2645-2657`） |
| **三** | 覆盖判定的输入本身不稳：LLM 点池逐轮在 15↔31 之间摆动，小问归属靠"模型自觉填 `question_no`"+"n-gram 重叠 ≥4 且唯一"两段弱判据（`rubric_grader_v1.py:649-668`、`:724-738`）；且解析不出时**静默返回 None**，告警连响都不响（`:679-698`） |

### 6.2 修复建议（治本，按优先级）

**P0-1｜分数必须对齐"学生所见整题"，而不是"我碰巧拿到的 rubric"。** 这是唯一能真正止血的一刀。`max_score` 不能再等于点池之和：

- 让 `grade_with_rubric` 接受一个显式的 `nominal_total`（题目满分，来自 `construction_grading_result.max_score`），`max_score` 固定取它；
- 未覆盖的小问按"未判 = 未得分"计入分母，而不是从分母里消失；
- 相应地 `normalize_points_to_nominal` 应改成**按覆盖比例缩放**（`target = nominal * covered_ratio`），而不是无条件拉满。

这样 §3.2 那轮会变成"7 个点全中 = 2.5/10（只覆盖 1/4 问）"，与学员可见的覆盖告警自洽。**注意这必须与告警文案同源改，否则会出现"文案说只判了 1 问、分数却按 4 问算"的新不一致。**

**P0-2｜覆盖不足应当阻断"给分"，而不是只加一句话。** 当 `coverage_state == "single_subquestion_only"` 或 `case_subq_coverage` 分子/分母 < 1 时，判分核应当降级为**不出总分的逐点诊断**（只报"问题1 你答对了这 7 个点"），把"整题得几分"这件事显式拒答。理由：一个带 ⚠️ 的 10/10，学生记住的是 10/10。

**P0-3｜覆盖判定改成"宁可报警不可沉默"（fail-loud 而非 fail-silent）。** `case_subquestion_coverage` 返回 `None` 的三条路径当前等价于"全覆盖"。应当区分「确认全覆盖」与「判定不能」——后者也要触发 P0-2 的阻断。当前的 fail-silent 是把不确定性折算成了对系统有利的方向，这是典型的自证陷阱。

**P0-4｜小问归属不该靠 LLM 自觉。** 兄弟行在 supabase 侧本来就带 `display_index`（`supabase.py:2731`），tier-2 从某一行的 `correct_answer` 抽点时，**该行的 `display_index` 是已知的确定性事实**，应当直接盖在生成的每个点上，而不是事后拿 n-gram 去猜。这一刀能同时消掉钉三的大半。

**P0-5（结构性，非本轮）｜`questions_bank` 的兄弟行拆分是这一整族病的上游。** 案例题按小问拆行 + `E{n}` 无 DB 权威列（`2026-07-30-复合qid唯一性与E索引权威审计.md`），导致 tier-1 不可用、tier-2 只能拿到碎片。在 `questions_bank` 落显式小问序号列、并让 exact 匹配返回**整题 bundle 而非 `ordered_rows[0]`** 之前，钉一只能缓解不能根治。

**不建议做的事**：收紧判分 LLM 的 prompt / 换更严的 judge / 加 fallback 分支。§3.4 已证实判分 LLM 在被判范围内判得对，动它只会在真正的病灶之外增加一层。

## 8. 盘外必须说的三件事（取证时撞见，不在三钉范围内）

### 8.1 gold pack 的能力档位是「官方答案截断」，不是「不同水平的作答」

这条会影响所有基于本 gold pack 的结论。逐字比对 `student_army_grading_gold.v1.json`：

- **S03（upper_mid）Q2023-05 的作答是官方答案的逐字全文**，只在末尾加了一句"其余小问按规范补充相应审批、签字、检测或验收项目；细节列举不够全。"
- **S06（low）Q2023-03 的作答是官方答案的逐字前缀**：问题1、问题2 一字不差，问题3 截到一半，问题4 整问缺失。

含义有三：

1. **offline「排序 12/12 全对」不是判分核准确的证据。** 上档学生就是答案本身，判它满分是恒等式，不是能力。
2. **这套 gold 只能测「遗漏」，测不了「答错」。** 三个档位之间没有任何一个是"写了但写错"的样本。而真实考生的主要失分形态恰恰是答错和术语不精确。
3. **`2026-08-01-eval军团三臂判分质量.md` 已实测 4-gram 严重泄漏**，本次逐字比对与之一致，并进一步说明泄漏不是"少量重合"而是**构造方式本身就是拷贝答案**。

**建议：在做任何"判分准确率"结论之前，gold pack 必须重造——档位差异要来自真实作答形态（错答/漏答/术语不准/答非所问），而不是对答案做字符串截断。** 否则后续所有 A/B 都会在一个恒等式上打转。

### 8.2 这个 P0 上一轮就被看见了，只修了告警没修分数

`loop.py:1795` 的注释白纸黑字写着"4 问粘贴被判 10/10"，日期 2026-07-30。那一轮的动作是把覆盖对账的基准从 `eq.stem` 换成 `user_stem`（让告警能响）。**告警响了，分照给。**

这是一个值得单独记的模式：**把"发声"当成了"修复"。** 本仓已有大量 observe-only marker（`point_pool_exceeds_max`、`coverage_state`、`case_rubric_score_total_mismatch`、`case_reference_unsigned_demoted_to_tier3`…），本次核到的 `coverage_state` 在全仓**零决策消费者**。观测层建得很厚，但从观测到决策那一跳缺得系统性。建议做一次"marker → 消费者"的反查：每个判分 marker 要么有决策消费者，要么显式登记为"仅观测且已知不阻断"。

### 8.3 判分权威的取得是随机的——这比满分更根上

§2.3 的实证（同一题干、三个学生、三种 tier 归属）说明：**同一个学生把同一道题再贴一遍，可能得到完全不同的分数，因为 RAG 抽到了不同的兄弟行。** 满分至少还是"高了"，这个是"不可复现"。

对付费产品而言，判分不可复现比判分偏高更伤——学生会发现重贴一次分数变了。建议把「同题重判的分数稳定性」直接立成一条发布门（同一 (题, 作答) 连发 N 次，分差超过阈值即 NO-GO），它同时覆盖钉一的随机性和钉三的点池抖动。
