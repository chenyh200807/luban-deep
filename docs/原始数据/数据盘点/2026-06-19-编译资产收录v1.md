3. 大型 payload 原地保留，避免重复、膨胀和 authority 混乱。

## 三原则落地

- **Thin wrappers, fat skills**: ledger 只做薄收录和边界声明；真正知识编译、判分签发、微课编译仍归各自 compiler / skill / runtime supply。
- **First principles**: 当前一等事实是“编译资产在哪里、属于哪层 authority、能不能被 runtime 用”，不是“把所有文件复制到另一个目录”。
- **Less is more**: 不复制 1GB+ payload，不制造第二套 artifact source；只复制可审计的小型 manifest-like 快照。

## 诚实边界

- `artifacts/*` 大多是 workbench / candidate / shadow / QA 输出，不等于生产 runtime truth。
- `runtime_supply` 也不是整体全可用；必须逐个 canonical pointer / manifest 检查 `published`、`status`、schema 和 gate。
- `compiled_asset_ledger_v1` 不能签发官方判分、不能写生产 registry、不能写 LearnerState 或 GBrain。
- 如果后续要让 AI “直接使用”某个编译资产，必须走 signed release / runtime packet / consumer gate，而不是直接读 workbench payload。

## 下一步

下一步不是再复制更多文件，而是做 `compiled_asset_authority_map`:

1. 每个 compiled asset group 的唯一 owner / authority。
2. 哪些是 workbench candidate，哪些是 release candidate，哪些是真的 published runtime supply。
3. 哪些下游 consumer 可以读，哪些必须禁止读。
4. 对 runtime supply 的 canonical pointer 做逐个 published/status 校验。
