# 2026-06-22 成品考点视觉原型盘点

> 目的:给 `docs/原始数据/考点原料/成品/` 下 40 个成品 Deep Pack 先定视觉原型,防止 Luban OpenMAIC-style Animation IR Workflow 在批量生成时退化成纯文字解释卡。
>
> 原则:按**认知结构**选表现形式,不按教材章节选。①-⑥ 默认必须做图示动画解释;只有(七)数值/记忆类才允许轻文字卡,且也优先做表格/数轴/闪卡,不是段落讲稿。

## 使用规则

- 生成 `source_card` 后,必须先查本表或重新给出同等粒度的 `visual_archetype_decision`,再进入 lesson/IR。
- `pill / note / answer_box / dialogue_box` 只能当辅助提示,不能当主教学图示。
- 如果某卡实际生成结果与本表主原型不同,必须在 review packet 里解释为什么认知结构变了;否则按 workflow 偏离处理。
- 所有 `*_案例题作答层样板.md` 统一不走普通讲解原型,默认是 `scoring_diagnosis_reveal / answer_scan`:用答题纸逐句扫 hit / partial / miss,不做纯文字解析页。

## 2026-06-22 修正:本表不是只给“原型标签”,必须给“领域对象 + 动作”

本表第一版的问题:虽然标了 6+1 原型和 primitive,但没有强制生成器回答“这一卡画面里到底应该看见什么工程对象,这些对象如何变化”。结果 S02 这类安全判断题仍可能退化成“四道门文字框”,机器门还会因为有 `decision_tree/process_flow` 而放行。

从本修正版开始,`visual_archetype_decision` 还必须补充:

```json
{
  "must_show_domain_objects": true,
  "domain_visual_plan": [
    {
      "scene": "本对象出现在哪一幕",
      "domain_objects": ["学生必须看见的工程对象/现场对象/资金对象/图结构对象"],
      "visual_action": "对象如何进入、移动、分层、命中、淘汰、扫描或退出",
      "why_object_not_box": "为什么不能只用文字框/判断框替代"
    }
  ]
}
```

硬门:

- ①-⑥ 默认至少 4 个主讲 scene 必须出现 domain objects;只有抽象判断框/流程框不算。
- `decision_tree` 只是骨架,不能替代现场图。安全题必须看见设备/构造/环境/风险对象;合同计价题必须看见资金链/口径/扣减路径;质量题必须看见病灶/正确构造/错法对照。
- 每个 domain object 必须绑定一个动作:移动、升降、分层、trace、命中、淘汰、错改对、答题纸扫描。只把图标摆在旁边不算动画解释。
- 如果生成器产出“文字框在动,工程对象不动”,该卡标记为 `coarse_draft_requires_redraw`,不得进入 `finished/`。

## 结论

当前 40 个成品考点里,没有一张应该默认做纯文字教学。即使 E01/E05/S07 这类公式/阈值题,主讲也应是公式链、三线图、阈值阶梯,不是段落解释。后续批量脚本如果产出以文字框为主的画面,应先判定 workflow 失败,而不是继续单卡美化。

更严格地说:只做到“有非文字 primitive”也不够。合格动画必须让学员第一眼看到本考点的工程对象/现场对象/资金对象/图结构对象,并看见这些对象通过动画解释知识。否则就是“抽象框图伪图示”,不得进 `finished/`。
