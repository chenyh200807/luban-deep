# 2026-06-22 成品考点视觉原型盘点

> 目的:给 `docs/原始数据/考点原料/成品/` 下 40 个成品 Deep Pack 先定视觉原型,防止 Luban OpenMAIC-style Animation IR Workflow 在批量生成时退化成纯文字解释卡。
>
> 原则:按**认知结构**选表现形式,不按教材章节选。①-⑥ 默认必须做图示动画解释;只有(七)数值/记忆类才允许轻文字卡,且也优先做表格/数轴/闪卡,不是段落讲稿。

## 使用规则

- 生成 `source_card` 后,必须先查本表或重新给出同等粒度的 `visual_archetype_decision`,再进入 lesson/IR。
- `pill / note / answer_box / dialogue_box` 只能当辅助提示,不能当主教学图示。
- 如果某卡实际生成结果与本表主原型不同,必须在 review packet 里解释为什么认知结构变了;否则按 workflow 偏离处理。
- 所有 `*_案例题作答层样板.md` 统一不走普通讲解原型,默认是 `scoring_diagnosis_reveal / answer_scan`:用答题纸逐句扫 hit / partial / miss,不做纯文字解析页。

## 结论

当前 40 个成品考点里,没有一张应该默认做纯文字教学。即使 E01/E05/S07 这类公式/阈值题,主讲也应是公式链、三线图、阈值阶梯,不是段落解释。后续批量脚本如果产出以文字框为主的画面,应先判定 workflow 失败,而不是继续单卡美化。
