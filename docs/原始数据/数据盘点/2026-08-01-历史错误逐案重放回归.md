## 6. 缺口与诚实边界

1. **B 族的历史条数被重述了**。清册写「07-29 07:56 两条」,实际是**同一条消息的双写**
   (一份写 `unified_...` session,一份写 `tutorbot:bot:...:chat:...` 别名 session)。真实独立故障 = **1 条**。
   同理,全库 163 条「这类内容我不展开」里,近 7 天真实独立故障只有 **B1(1 条)+ B2 家族(3 条同题连发)**。
2. **B2 的三条是同一输入在 8 秒内连发三次**(07-31 19:32:09 / 19:32:13 / 19:32:17,三个不同 `tb_` session),
   看形态像自动化复现轮而非真实学生。但**输入是完全正当的 4 小问案例题 + 学生作答**,
   拒答就是错的,所以仍按真实故障重放 —— 现已 PASS(3646 字完整批改)。
3. **本次重放全部用 qa 账号 `7aed4eac`,不是原故障账号**。B 族病灶含"记忆态"成分,
   #638 之后拒答模板不再投影进学员状态,但**原账号的历史污染记忆未被验证清除** —— 本次未覆盖。
4. **每案只重放 1 轮**(C3 因 WS 断补跑 1 轮)。LLM 有随机性,单轮 PASS 不等于稳定 PASS。
   按「live≥3 轮才宣称」的既有纪律,**本文只宣称"原 failure mode 在本轮重放中未复现",不宣称"彻底修好"**。
5. **未核对回答的学科正确性**。判据是"有没有可见终答",不是"答得对不对"。
   实际抽读发现内容质量问题(见 §7),但那是另一条战线,不在本次回归范围。
6. **G 族(supabase 500)是本次新发现**,未在原清册内,只做了会话面核对,未做逐案重放。

## 7. 你没问但必须说的(抽读重放正文发现的问题)

这些**不是**本次回归的判据,是逐案读回答正文时顺手看到的,单独记一笔:

1. **同一道题、同一 SHA,五个小问的答案在不同重放之间互相打架**。
   第 5 问「标准间(200 m²)室内环境污染物浓度检测至少几个点」:
   - A1 结论写「至少 **5 个点**」,但同一段正文紧接着写「100~500m² → 不少于 **3 个**」—— **自相矛盾**;
   - A3 写「答案是 **3 个**」;
   - A4 直接判「甲醛 0.11 超 0.10 → **不合格**」,A1 判「**合格**」。

   **同一输入、同一版本,判定结论在合格/不合格之间翻转** —— 这是比"有没有回答"严重得多的病。

2. **内部独白泄进了用户可见正文**。C3 服务端落库的回答开头是:
   「我注意到检索证据中未直接给出表6.0.15的具体数值和甲醛限值,让我补充检索这两个关键参数。」
   这是过程自述,不该出现在终答里(记忆里「独白剥离」那条修过一次,这里又见)。

3. **A2 和 A3 输入几乎同题却走了两条完全不同的链**:
   A2(带作答,838 字)→ 逐采分点批改链(18 个采分点、587 个事件、诊断分 4.5/10);
   A3(不带作答,693 字)→ 直接讲解链(39 个事件)。分流本身合理,
   但 **A1/A4 与 A3 同 payload 却分别走出 45 / 27 / 39 个事件、TTFT 40–64s 差 24s** —— 路由与耗时都不稳定。

4. **TTFT 差异巨大且不可预测**:同 payload `5ead86ea9e66` 的四次重放 TTFT 分别是
   **64.3s / 56.5s / 40.0s / –(断)**。走批改链的 A2 反而只要 2.6s(有渐进吐字)。
   **不走批改链的路径没有渐进吐字,用户要盯着空屏 40–64 秒**,这是可感知的体验缺口。

5. **`DEEPTUTOR_PROMPT_VERSION=git-4505e0c10c90` 指向 2026-04-24 的提交**,
   而 `DEEPTUTOR_GIT_SHA` 是 07-31 的 `27e36476`。两个版本变量相差三个月。
   如果 prompt 版本是独立的装载权威,它可能没跟着代码走 —— **未深挖,只报现象**。

- **E / F 族**:免重放判据成立,并已用 DB 逐会话证据(E 2/2、F 21/21)替代"日志零复发"式论证。
- **不宣称"彻底解决"**:单轮重放 + 未验原账号记忆态 + 内容正确性未测(且 §7.1 已发现同题结论翻转)。
  按现有纪律,可宣称的最强结论是:**「原 5 个 failure mode 在当前生产 SHA 上的逐案重放中均未复现」**。
