## 4. 步骤三：分批回填 + 逐批验证

### 4.0 写入方式（为什么这样写）

`apply_batch.py` 的每一次 PATCH 都满足三条：

1. **id 精确定位**：`id=in.(...)`，从 `plan.jsonl` 来，**没有任何 like / 相似度 / 文本匹配**；
2. **类型护栏**：每条 PATCH 额外带 `question_type=eq.case_study & source_type=eq.REAL_EXAM`——万一 id 清单里混进一个错 id，PATCH 会**打不中**（返回 0 行）而不是写坏一行非案例题；
3. **写完即回读**：`Prefer: return=representation`，PostgREST 直接把它实际写成的行返回，脚本当场比对"返回行数 == 请求 id 数"且"每个字段 == 计划值"，**任一不符立即 `sys.exit` 中断，不继续下一个 unit**。

只写这 4 个新列（`assert set(values) <= NEWCOLS`），**任何既有列都不在 PATCH body 里**。

### 4.2 ④ canonical 的裁决账（这是本轮最容易出错的一批，逐格记账）

## 6. 回滚

**脚本已就位**：`extractions/case_group_mapping_c1/rollback_c2.sql`（3,520 bytes，内嵌 385 个 id 的显式清单）

```sql
begin;
update public.questions_bank
   set case_group_id = null, case_subquestion_index = null,
       case_row_granularity = null, case_row_canonical = null
 where id in (/* 385 个 id 逐一列出 */);
select count(*) as still_filled from public.questions_bank
 where case_group_id is not null or case_subquestion_index is not null
    or case_row_granularity is not null or case_row_canonical is not null;
-- 期望 still_filled = 0；不为 0 = 有清单外的行被写过，立即停并报主控
commit;
```

**为什么这一条就够**：C2 **只 ADD COLUMN + 只 UPDATE 这 4 个新列**，一个既有列都没碰（V12 已对 10 行 × 34 个既有列逐字节验证无 drift）。所以"回滚"是把新列清空，**不依赖备份文件是否完好**，也不需要恢复任何业务数据。

三层深度：
1. **列级**（上面这条，最常用，C3 已接线时也可用）；
2. **DDL 级**：`alter table ... drop column ...`（脚本尾部已注释好，**仅在 C3 未接线时可用**）；
3. **行级**：从 `backup_rows_before_c2.full.jsonl`（scratchpad，8.9MB，38 列全量）逐 id 还原——按设计永远用不到，留作 C2 没改既有列这一断言的兜底证据。

## 8. 你没问但我必须说

1. **`case_row_canonical = NULL` 会咬 C3，这是本轮最大的活口。** 72 行冲突行留 NULL，直接后果是 **11 个组的 canonical 小问序号带洞**（如 `2020-case2` canonical 只剩 `[3,4]`，`2023-case2` 只剩 `[3,4]`）。C3 如果写 `where case_row_canonical = true`（最自然的写法），这 11 组会**静默少召回 1–2 个小问**——而 `covered_indexes` 会显示 `[3,4]` 看起来"齐了"，正是 C1 §7 第 5 条警告的那种"把错误伪装成 full coverage"。已在 `contracts/rag.md §44(c)` 钉死：**必须用 `canonical is not false`，并对 NULL 格打 `case_answer_conflict_unresolved` 进 trace**。这条不做，C2 相当于给 C3 埋了一颗更隐蔽的雷。

2. **V4"组内背景指纹唯一"这条断言比它看起来弱得多，我做了独立复核，结果不干净。** C1 存的 `case_group_fingerprint` 是**按组赋的值**，所以它在逻辑上**永远不可能**报出"这个组合并错了"——拿它当 V4 是自证。我改成从 live `stem` 逐行现场重算背景指纹（`v4_independent.py`），结论是：
