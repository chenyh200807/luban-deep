## 五、产品化判断

### 能直接开工的方向

- **客观题闭环**: 337 道历年选择题 + 1033 道章节练习，答案和解析完整，适合先做确定性判分、错因解释、章节掌握度和 distractor 归因。
- **教材检索与讲解**: 650 教材 blocks + 1976 taxonomy 叶节点 + 327 讲义页 JSON，足够支撑“按知识点组织讲解”和“从教材/讲义抽取解释素材”。
- **规范增强回答**: 8 部标准、5077 nodes，可用于高可信引用、规范题解释和构造/质量/验收类图解。
- **案例题答案理解**: 218 道案例答案文本已可用于答案结构分析、常见问法归类、案例题知识覆盖。但只能称为“答案理解/参考答案 grounding”，不能称为 signed rubric。

### 不应过度承诺的方向

- **不要把整段 correct_answer 当采分点表**。它可以生成候选采分点，但还需要 PDF 视觉抽取、专家复核或 signed grading artifact 才能做判分 authority。
- **不要把章节题数量当深题质量**。章节练习覆盖广，但多为客观题，不能证明案例开放题的评分一致性。
- **不要继续引用当前目录内的 650 md 知识卡片**。本次实测路径不存在；除非找回实际文件，否则只能引用“650 教材 content_blocks”和 taxonomy anchored chunks。

## 六、建议下一步

1. **先补三张机器表**: `exam_case_score_gaps`、`taxonomy_missing_chunks`、`source_path_authority_map`。这三张表能把“哪些题可判分、哪些题只可解释、哪些题缺映射”切清楚。
2. **把案例题分成 3 桶**: `rubric_ready`、`answer_only`、`needs_pdf_backfill`。不要用单一 case_study 数量做能力评估。
3. **找回或废弃知识卡片引用**: 若 `cards-from-json-all/` 已迁移，补路径；若已被 v3 content_blocks 替代，旧文档应统一改口为“650 教材内容块”，避免 agent 继续找不存在目录。
4. **为 canonical 文件写 manifest**: 至少列出题库、教材、taxonomy、标准文件的 authority path、文件数、更新时间、schema family、禁止使用的旧路径。
5. **图表依赖单独处理**: 本次脚本已支持 PNG 图输出，但当前 Python 缺 `matplotlib`。如果后续要生成可视化报告，先在独立分析环境补图表库，不要把依赖写进业务项目。

## 八、最终判断

当前原始数据已经足够支撑鲁班智考的**客观题闭环、教材讲解、规范 grounding、案例答案理解和候选 rubric 生成**。真正要补的不是“再收更多 PDF”，而是把已有结构化资产切出 authority 层级: 哪些是标准答案、哪些是解释素材、哪些是考试给分 authority、哪些只是 OCR/PDF 补源。

最容易产生 false progress 的地方是把“题多、PDF 多、答案多”误判为“判分闭环已成”。正确路线应是: 先用当前 JSON 做 manifest 和缺口表，再用 PDF/专家流程补 signed rubric，最后才谈案例判分器训练和线上评测。

### 编译资产纳入后的总判断

把编译资产纳入后，结论要从“原始资料足够支撑候选生成”升级为:

1. **知识编译资产已经很厚**: RichLeaf runtime context、v3.2 scoring points、LLM deep compile、lecture cards、runtime supply 都真实存在，不是从零状态。
2. **但 authority 没有自动升级**: `runtime_supply/v_rich_leaf_context` 是 `published:false`；v3.2 是 shadow candidate；LLM deep compile `quality_claim_allowed:false`；PGO 的 482 个 point 全部 `score:null`。
3. **release truth 必须看 runtime supply + gate，而不是 artifacts 目录体量**: workbench 越大越容易制造 false progress。能作为 runtime 消费的只有经过 canonical pointer、published/gating、loader 验证的供给。
4. **官方判分 authority 仍缺最后一公里**: 当前缺口不是“没有采分点候选”，而是逐点分值标定、真人/PO 签字、真实考生作答、隔离题处理和 production default gate。

因此，本文前面“不要把题多/PDF 多误判为判分闭环已成”的判断仍成立，但要补一句更准确的话: **也不要把 artifacts/workbench 编译资产多误判为 release truth；真正的分界线是 signed/versioned runtime supply + published gate + official score authority。**
