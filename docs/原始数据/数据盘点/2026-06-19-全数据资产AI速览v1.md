# 全数据资产 AI 速览 v1

- **日期**: 2026-06-19
- **目标**: 让 AI 在一分钟内知道鲁班当前有多少数据资产、各类资产在哪里、能支持什么、不能越权到哪里。
- **范围**: `docs/原始数据/` 下的原始资产本体、`artifacts/` / `runtime_supply/` 下的编译资产索引，以及 `docs/原始数据/数据盘点/extractions/` 下已经生成的 source-layer 候选工件。
- **产物**: `docs/原始数据/数据盘点/extractions/data_asset_brief_v1/`
- **状态**: `asset_inventory_only`，不是 runtime supply，不是 official score authority，不写 LearnerState / GBrain / production registry。

## 结论先行

当前最应该选的目标不是 `CaseGradingSkillKernel` 或 `LubanContextPack`，而是 **全数据资产总账 v1**。

原因很简单: 现在真正的一等事实是“我到底有什么数据资产、多少、在哪、可用到哪层”。如果先接某个 runtime consumer，系统会很快把“资产盘点”和“生产能力”混成一套 authority，后续教材、真题、讲义、规范、PDF、候选 rubric 都会互相串权。

## 三原则落地

- **Thin wrappers, fat skills**: `build_data_asset_brief.py` 是薄 wrapper，只整理已有 profile / ledger / candidate scope / compiled ledger；真正的教材编译、判分、讲义解释仍应进入后续专门 compiler / skill kernel。
- **First principles**: 这一步解决的是“数据资产可见性”问题，不是“生产判分能力”问题。
- **Less is more**: 不做 OCR、不接 runtime、不建 graph viewer、不写 GBrain，只生成 AI 首入口和机器总账。

## 诚实边界

- PDF 95 个只是原件资产，不代表全部 OCR、切块、可检索。
- 383 个 JSON 代表结构化入口，不代表全部内容已经签发为 release truth。
- 5,059 个编译资产文件代表 artifacts/runtime_supply 可见性，不代表这些 payload 已可被 runtime 或 official score 直接消费。
- 4 个 published runtime pointer 也只表示 hash/schema/consumer gate 后可读，不表示 official score 或 learner truth 写入。
- `asset_gap_map_v1` 指出 1 个 runtime live-reader policy conflict，但它本身不修 reader、不签 pointer。
- 25 cases / 117 rubrics / 431 scoring points 是 OKF-like candidate scope，不是 signed grading artifact。
- 本产物不能作为 `runtime_supply`、official score、LearnerState 或 GBrain 写入依据。
