# 清洗 JSON 源账本 v0

## 范围

本次只登记 `docs/原始数据/2026_副本` 下已经清洗成 JSON 的源文件，不处理 PDF 原件，不写 runtime supply，不写 LearnerState / GBrain / production registry。

生成产物：

- `docs/原始数据/数据盘点/extractions/json_source_ledger_v0/manifest.json`
- `docs/原始数据/数据盘点/extractions/json_source_ledger_v0/sources.jsonl`
- `docs/原始数据/数据盘点/extractions/json_source_ledger_v0/summary.json`

## 方法

按 `llm-data-organization` 的 authority split 执行：

1. 清洗 JSON 仍是 raw evidence，不直接升级为 canonical truth。
2. 本账本只做确定性登记：路径、bucket、文件大小、SHA-256、JSON shape、runtime guard。
3. 后续 LLM 可以基于账本做候选抽取、切分、对齐、综合与质检建议。
4. release artifact 仍必须经过 schema validation、source review、expert/STORM review、签名与 rollback 设计。

复现命令：

```bash
python docs/原始数据/数据盘点/scripts/build_json_source_ledger.py --generated-at 2026-06-19T00:00:00+08:00
python -m pytest tests/scripts/test_json_source_ledger.py -q
```

## Authority Guard

所有账本记录统一标记：

```json
{
  "authority_status": "raw_evidence_ledger",
  "source_claim_reviewed": false,
  "runtime_guard": {
    "release_stage": "raw_source_ledger",
    "runtime_consumable": false,
    "installed_runtime_supply": false,
    "canonical_write_allowed": false,
    "learner_truth_write_allowed": false,
    "gbrain_write_allowed": false,
    "production_registry_write_allowed": false,
    "official_score_allowed": false
  }
}
```

这意味着：清洗 JSON 已经可以作为候选证据入口，但不能直接被 TutorBot、判分器、LearnerState、GBrain 或 production registry 当成正式事实消费。

## 结论

OKF 下一步不再需要从 PDF 起步，应从 `json_source_ledger_v0` 选择已清洗 JSON 做候选编译。最小稳健路径是：

```text
json_source_ledger_v0
  -> case/rubric/formula/standard candidate compiler
  -> source/STORM review ledger
  -> deterministic validator
  -> signed runtime_supply candidate
  -> shadow consumer
```

当前条件下，最优下一步是扩展 OKF builder 的输入面：从 `case_rubric_canonical.json` 的单案例 projection，升级为读取账本中 `exam_cleaned_json + standard_cleaned_json + textbook_core_json` 的可追溯 candidate pack；仍然保持 `runtime_consumable=false`，直到签发 gate 通过。

## 缺口与边界

- 本账本只证明清洗 JSON 文件存在、可解析、可哈希、可分类；不证明里面每条 claim 已经 source-reviewed。
- `taxonomy_backup_json` 只是历史版本记录，不能直接作为当前 taxonomy authority。
- 讲义 JSON 数量最大，但版权/来源/可引用粒度仍需单独 review。
- 标准文件 JSON 更接近 primary source，但清洗过程仍需核验条文编号、章节层级和原文一致性。
- 真题 JSON 可作为题干/解析候选来源，official score 仍必须由 signed grading artifact 决定。
