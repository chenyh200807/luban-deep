# Topic OKF v0

## 范围 / 方法

本次把 OKF 从“AI 知道有什么资产”推进到“AI 能围绕高频主题稳定找证据”。范围先限于 5 个 P0 主题:

- 屋面防水
- 流水施工
- 网络计划
- 索赔
- 质量验收

生成方式:

1. 从 `json_source_ledger_v0/sources.jsonl` 读取 383 个清洗 JSON source ledger 记录。
2. 从 `okf_candidate_scope_v0/scoring_points.jsonl` 读取 431 个候选采分点。
3. 用每个主题的别名/关键词种子扫描原始 JSON 文本节点和候选采分点。
4. 输出 `topic_okf_v0` 的 machine artifacts，并把 5 张主题卡接入 `okf_bundle_v0/topics/`。

## 缺口与诚实边界

- `raw hits` 是关键词命中导航信号，不是官方考频。
- `candidate scoring points` 来自佑森解析/候选 rubric，不是官方评分权威。
- Topic OKF 目前是确定性抽证据 + 人工主题种子；后续更强版本应由 LLM compiler 做语义聚类、反例审查和主题摘要，再由确定性 gate 校验来源边界。
- OKF 不参与 production runtime、LearnerState、GBrain、RAG 默认决策或 official scoring。

## Claude / Codex 调用方式

为避免 Claude Code 不知道什么时候用 OKF，本次新增 repo-local workflow skill:

- `agent-skills/luban-okf-context/SKILL.md`

触发条件:

- 问数据资产、教材、真题、讲义、规范、PDF/JSON、编译资产；
- 问某个建筑实务主题怎么考、怎么讲、有哪些来源；
- 问 candidate / release / fixture / runtime-shadow / governance 边界。

调用路径:

1. 先读 `docs/原始数据/数据盘点/okf_bundle_v0/index.md`。
2. 主题问题读 `docs/原始数据/数据盘点/okf_bundle_v0/topics/index.md`。
3. 找到具体 topic card。
4. 高风险结论必须回到 card 中链接的 raw JSON、rubric candidate、规范、教材或盘点报告复核。

## 结论

Topic OKF v0 已达到“AI 主题导航层”的第一阶段目标:下次 AI 问屋面防水、流水施工、网络计划、索赔、质量验收时，不需要盲扫全仓，可以先读主题卡，再按 source path 回源。

它仍然不是生产能力层。它的价值是减少 AI 理解成本、降低幻觉、让主题回答可回源、可复查、可继续编译。
