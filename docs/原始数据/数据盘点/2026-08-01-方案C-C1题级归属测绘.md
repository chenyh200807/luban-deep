## 0. 一句话结论

**方案 C 具备执行条件，但 C1 推翻了 codex 报告的两条前提事实**：

1. `question_type='case_study'` 的 1959 行里，**只有 385 行是真题案例**（19.7%）；其余 **1574 行是教材/讲义自动生成的单问考核题被误标成 `case_study`**。它们同样会被 RAG 的 `case_rows` 聚合吃进案例 bundle——这是一条比"找不到兄弟行"更早的污染面。
2. 真题案例行**存在两种互斥的行粒度**，混在同一张表里：**小问行 280 行**（一行一问）与**整题行 96 行**（一行含 问题1..N 全部）。codex 报告全程假设"一行一小问"，因此 §5.3 的数据前置 SQL（`count(*) = 题面小问数`）在整题行占多数的年份（2024 全部 5 道、2017 5/6 道）会永远红——**不是数据缺失，是粒度不同**。

回填映射已建成：**280 行拿到 `case_group_id + subquestion_index`（高置信 186 / 中 92 / 低 2）**，96 行只给组不给 index（整题行），9 行只给组，1574 行留空不猜。56 个题级组，2015–2025 每年 4–6 组，与一建《建筑实务》每年 5 道案例的卷面结构吻合；与佑森 431 采分点资产逐组对账 **23/25 组覆盖齐、2 组缺问**。

### 1.2 冲突裁决（事实权威阶梯）

按记忆律「事实权威阶梯 = 教材/真题原文裁决 LLM 面板」，本方案的裁决序是：

```
真题原文题干（背景正文 + 【问题】N 序号）
  > original_id 显式编号（XW_..._CASE_n_Q_m）
  > 佑森采分点资产的 case_no/sub_q_no（只用于对账，不用于回填）
  > source_meta.original_anchor（语义不统一，仅作佐证写进 evidence）
  > source_chunk_id / exam_year（只作 namespace，永不作 parent identity）
```

**为什么背景正文是主权威而不是 chunk/anchor**：小问行的题干 = 完整背景 + 本问，是从真题原文逐字复制的；背景是同一道案例所有小问唯一共享且来自原文的事实。chunk 和 anchor 是抽取管线的副产品，实测都不自洽。

## 2. 映射构建

### 2.1 组键推导（确定性、可重跑）

```
background   = stem 中第一个 【问题】/【 问题 】/###问题/^问题[:：] 之前的部分
             （无标记时取整段 stem，问题区退化为尾部 900 字）
hardnorm(s)  = 去掉除「汉字、数字」外的一切字符（吃掉 ，、~- ㎡/m² 全半角与 OCR 空白差异）
fingerprint  = md5(hardnorm(background))[:16]
```

年内合并（union-find），三条合并规则，全部记账到 `merge_log.json`：

1. `hardnorm` 完全相同 → 同组；
2. 一方是另一方的**子串**（治 OCR 截断，例：2018-case2 的 `混凝土框架结构部分屋面为…` 是 `某高校图书馆工程…` 的尾段）；
3. 6-gram Jaccard ≥ 0.55（治 `57000m²` vs `57000㎡`、`9-12层` vs `9~12层`、`、` vs `，`）；
4. 补充：同 `_CASE_{hash8}` 强制同组。

`case_group_id = {exam_year}-case{N}`，N 的来源优先级：`XW` 显式题号 > `source_meta.page_num` 升序 > `min(row_id)` 升序，逐组记 `case_no_src`。

> **稳定性说明（必须写进 C2 契约）**：`{year}-case{N}` 是人类可读 id，但 N 来自年内排序，**新灌入一道漏题会让后续 N 漂移**。因此 C2 必须同时落 `case_group_fingerprint`（内容派生、不随排序变）并规定：**`case_group_id` 一经写入即不可变**，新组只能取该年当前 max(N)+1，永不重排。

### 2.2 小问序号权威阶梯

| 优先级 | 来源 | 命中 | 置信 |
|---|---|---|---|
| 1 | `original_id` 的 `XW_{y}_CASE_{n}_Q{m}` | 40 | high |
| 2 | 【问题】之后的行首阿拉伯序号 | 218 | high（组内连续且无答案冲突时） |
| 3 | 无【问题】标记时，尾部升序连续 run（治 `问题2：写出图…`、`1. 计算每立方米…` 这类丢标记行） | 20 | medium |
| 4 | `source_meta.original_anchor` 的 `问题N`/`第N题` | 2 | medium |
| 5 | 以上皆无 | — | **留空不猜** |

### 2.3 行粒度分类（本轮新增，codex 报告缺失）

| 粒度 | 判据 | 行数 | `subquestion_index` |
|---|---|---|---|
| `single_subquestion` | 问题区内只有 1 个序号 | **280** | 写 N |

### 2.5 入库世代（回填前必须知道的事）

同一道真题在 `questions_bank` 里被**重复灌入过 4 个世代**，靠 `original_id` 形状可判别：

| 世代 | `original_id` 形状 | 特征 |
|---|---|---|
| g0_xw | `XW_{year}_CASE_{n}_Q{m}` | 2015/2016，编号最完整 |
| g1_auto | `AUTO_{hash16}` | `correct_answer` 是 **string** |
| g2_exam_chunk | `EXAM_{node}_P{page}_{seq}_CASE_{hash8}` | 带 `source_meta`/`source_chunk_id`/`anchor` |
| g3_exam_year | `EXAM_{year}_{node}_{hash8}` | `correct_answer` 是 **array**，**覆盖最全** |

实证（2023-case3，即 live 复现的 17371–17374 家族）：

```
2023-case3  fingerprint=53744e961e672050  8 行 = 3 个世代 × 4 小问
  idx1: 9559(g2) 17371(g3)
  idx2: 8993(g1) 17372(g3)
  idx3: 8994(g1) 17373(g3)
  idx4: 8995(g1) 17374(g3)
  contiguous=true, answer_conflicts=[]
```

**这直接解释并可修复 live 症状**：`9559` 与 `17371` 不是"污染重复行"这么简单，而是同一小问的两个入库世代；现有 `seen_by_index` 按 `display_index` 去重时二者互相夺位，而 `17372/17373/17374` 因为不在候选里就永远召不回——所以判 1/4。回填后按 `case_group_id='2023-case3'` 一次取全组即可。

**代价**：240/280 行的 `(group, index)` 存在多世代重复，其中 **72 行答案文本不一致**（见 §3.3）。C2 不能"任选相似度高的"——必须显式定世代优先序。

## 4. 验证断言集（C2 执行后必须跑）

### 4.1 数据前置断言（回填后立即跑，全部只读）

```sql
-- V1 组内 index 唯一性：按世代收权后，每个 (case_group_id, subquestion_index) 只能有 1 行
select case_group_id, subquestion_index, count(*) n
from public.questions_bank
where case_group_id is not null and subquestion_index is not null
  and canonical_row = true          -- C2 引入的世代裁决位
group by 1,2 having count(*) > 1;
-- 期望：0 行

-- V2 组内 index 连续：1..max 无空洞（只对"有小问行"的组断言，整题行组豁免）
select case_group_id, max(subquestion_index) mx, count(distinct subquestion_index) dn
from public.questions_bank
where case_group_id is not null and subquestion_index is not null and canonical_row
group by 1 having max(subquestion_index) <> count(distinct subquestion_index);
-- 期望：0 行

-- V3 组内答案非空
select id, case_group_id, subquestion_index from public.questions_bank
where case_group_id is not null and subquestion_index is not null and canonical_row
  and (correct_answer is null or correct_answer::text in ('null','""','[]','{}'));
-- 期望：0 行

-- V4 跨组无串题：同一 case_group_id 内背景指纹必须唯一
select case_group_id, count(distinct case_group_fingerprint) k
from public.questions_bank where case_group_id is not null
group by 1 having count(distinct case_group_fingerprint) > 1;
-- 期望：0 行

-- V5 组不跨年
select case_group_id, count(distinct exam_year) from public.questions_bank
where case_group_id is not null group by 1 having count(distinct exam_year) > 1;
-- 期望：0 行

-- V6 整题行不得带 index
select id from public.questions_bank
where case_row_granularity = 'whole_case' and subquestion_index is not null;
-- 期望：0 行

-- V7 只有真题案例行能拿到组
select id, source_type, question_type from public.questions_bank
where case_group_id is not null and (source_type <> 'REAL_EXAM' or question_type <> 'case_study');
-- 期望：0 行

-- V8 回填行数与 C1 映射逐行一致（用 mapping.csv 建临时表比对，不做模糊匹配）
-- 期望：280 行 A 类全等；96 行 B 类 case_group_id 有值且 subquestion_index is null
```

### 4.2 与佑森资产的题号对账断言

对 2021/2022补考/2023/2024/2025 的 25 组：
每组 `覆盖集合 = {小问行 index} ∪ {整题行 span 展开}` 必须 ⊇ 佑森 `sub_q_no` 集合。
当前已知会红 2 组（`2022-case1` 缺问3、`2023-case4` 缺问6）——**这两条必须是"已登记的已知缺口"而不是"新回归"**，否则 C2 就把断言写松了。

### 4.3 运行时断言（C3 接线后，不属于 C2 出口）

沿用 codex §5.3 的判据，但用新列改写：

- 任意 seed 行 → 按 `case_group_id` 取全组 → bundle canonical hash 与 seed 无关（参数化 seed = 第 1/2/4 行 + 打乱返回顺序）；
- `matched_question_ids` 全部属于同一 `case_group_id`；
- MCQ seed → sibling 查询次数 = 0；
- `case_group_id IS NULL` → fail closed 到现单行 bundle，写 `case_bundle_hydration="skipped:null_group_key"`；
- **整题行命中时不得触发 sibling 查询**（它本身已是全题），写 `hydration="skipped:whole_case_row"`。

```sql
  add column if not exists subquestion_index        smallint,
  add column if not exists case_group_fingerprint   text,
  add column if not exists case_row_granularity     text,   -- single_subquestion | whole_case | background_only
  add column if not exists case_group_source        text,   -- 归属证据串（可审计）
  add column if not exists case_group_confidence    text;   -- high | medium | low

alter table public.questions_bank
  add constraint questions_bank_subquestion_index_range
    check (subquestion_index is null or (subquestion_index between 1 and 12)) not valid;

alter table public.questions_bank
  add constraint questions_bank_whole_case_no_index
    check (case_row_granularity is distinct from 'whole_case' or subquestion_index is null) not valid;

create index if not exists idx_qb_case_group
  on public.questions_bank (case_group_id, subquestion_index)
  where case_group_id is not null;
```

**非破坏性已实测核过**（不是推断）：

- `questions_bank` 上的 8 个 RPC（`search_questions_bank_vector` / `_text` / `_text_ranked` / `search_questions` / `search_questions_by_keywords` / `match_questions` / `get_questions_quality_stats_v2` / `refresh_syllabus_stats`）**全部返回显式 `TABLE(...)` 类型，没有 `SETOF questions_bank`**，加列不改其返回形状；
- 唯一相关视图 `v_retrieval_questions` 用**显式列清单**，无 `SELECT *`；
- RAG 的 `_QUESTION_SELECT`（`deeptutor/services/rag/pipelines/supabase.py:54-59`）是显式列串，加列不影响；
- 表上**没有非内部触发器**；`relrowsecurity = true`，**回填必须以 service_role / postgres 身份执行**。

### 5.3 备份与回滚

```sql
-- B0 备份（只读导出，落 scratchpad + 阿里云无关）
copy (
  select row_to_json(q) from public.questions_bank q
  where id in (/* mapping.csv ∪ whole_case ∪ group_only 的 385 个 id */)
) to stdout;
```

回滚路径分三层，**任何一层都不需要恢复业务数据**：

1. **列级回滚**（最常用）：`update public.questions_bank set case_group_id=null, subquestion_index=null, case_group_fingerprint=null, case_row_granularity=null, case_group_source=null, case_group_confidence=null where case_group_id is not null;` —— 因为这 6 列是**纯新增、无既有读者**，清空即回到 C2 前状态；
2. **DDL 回滚**：`alter table … drop column …`（仅在 C3 未接线时可用）；
3. **行级恢复**：从 B0 的 JSON 逐 id 还原（仅在误改了既有列时；按设计 C2 不写任何既有列）。

**硬约束**：C2 **只 `ADD COLUMN` + `UPDATE` 新列，绝不改任何既有列**（不动 `stem`/`correct_answer`/`source_chunk_id`/`question_type`）。这样"回滚"永远是一条 `set null`，不依赖备份文件完好。

### 5.4 C3 接线的数据前置断言

codex §5.3 的前置 SQL 改造为用新列，**并按行粒度分叉**：

```sql
-- C3 门 1：目标家族能按新组键取全（替代 codex 的 year+chunk 版本）
select case_group_id,
       count(*) filter (where case_row_granularity='single_subquestion') as n_sub,
       count(distinct subquestion_index) as dn,
       count(*) filter (where case_row_granularity='whole_case')        as n_whole,
       bool_and(correct_answer is not null
                and correct_answer::text not in ('null','""','[]','{}')) as all_answered
from public.questions_bank
where question_type='case_study' and case_group_id = :target_group and canonical_row
group by 1;
```

放行判据（**两条互斥分支，缺一不可**）：

- 小问行组：`n_sub = dn = 题面小问数` 且 `all_answered = true`；
- 整题行组：`n_whole ≥ 1` 且 `n_sub = 0` → **C3 必须直接用该行，不发 sibling 查询**。

C3 还须新增两条 codex 未覆盖的门：

- **门 2（粒度门）**：hydration helper 入口断言 `case_row_granularity`，`whole_case` 直接短路；
- **门 3（识别门）**：codex §6.1 已指出 `exact_question_identity_corresponds()` 对 case 直接 `return True`（`supabase_strategy.py:999-1003`）。有了 `case_group_fingerprint` 后，case identity 才第一次有可证伪的比对对象——**这条应与 C3 同批做，不能先聚合后收权**，否则一个假命中会直接拿到整组 4–6 条官方答案。

## 7. 你没问但我必须说

1. **1547 行误标 `case_study` 的教材/讲义题今天就能进案例 bundle**，因为聚合分支只看 `question_type` 含 `case`。方案 C 回填不修它，`question_type` 收权是独立战役——但**它比方案 C 更靠前**：一个教材题混进 2023-case3 的 bundle，比"少召回 3 个兄弟"更能污染官方答案。
2. **整题行的存在意味着"整卷提交只判 1/4"不是全年份现象**。2024 全年 5 道都是整题行，理论上一命中就有全题；2023/2020/2019/2025 才是小问行主导。**live 复现时如果只测 2023 家族，会误判为"全库都这样"**——度量场景必须按年份分层。
3. **`correct_answer` 的类型在世代间不一致**：g1/g2 是 `string`，g3 是 `array`。任何"整组拼接答案"的代码必须两种都吃，否则 C3 会在 g1 行上静默丢答案。
4. **`case_group_id` 一旦被 C3 消费就成了 authority，`{year}-case{N}` 的排序派生性就成了债**。要么现在就规定 id 不可变 + 新组只追加，要么直接改用 `{year}-{fingerprint前8}` 放弃可读性。这是一个必须现在拍板的选择，不能拖到 C2 中途。
5. **回填 240 行重复 (组,index) 时如果不引入 `canonical_row` 裁决位，C3 会拿到 2–4 份同一小问的答案**，`covered_indexes` 看着是 `[1,2,3,4]`（ratio=1、full coverage），实际参考集里混了三个世代的措辞差异——**这正是 codex §4.5 警告的"污染 bundle 恰好凑齐 index 1–4 把错误隐藏成 full coverage"**。所以 B5 不是可选批次，是 C3 的前置。
6. **本轮所有产物都是确定性可重跑的**（`export_rows.py` + `build_mapping_v3.py`）。主控核验时不要读我的结论，重跑脚本对 `stats.json`。
