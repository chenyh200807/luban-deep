## 二、引擎流水线(6 层,料已就位)

```
L0 来源证据:taxonomy + 教材 + 真题 + 规范 + 知识卡(版本化,有;消费前需 registered source_ref)
L1 编译母题:考点(真题频次)→ 不变量(313深编译)→ 出题人意图/误解(JSON analysis+logic_chain)
            → 采分点+分值候选(signed artifact / bootstrap rubric / score_assigner proposed scores)→ 场景(JSON stem)→ 计算判据(公式汇总)
L2 受控生成:LLM 在变量空间变题(变场景/条件/问法,不变考点)+ score_assigner 给变题生成 proposed scores
L3 判分(护城河):artifact_first judge + signed artifact / bootstrap 分值候选 + 踩点池封顶 + ERROR_CODE 错因
L4 诊断/学情:错因→E系列;学情→learning_evidence/LearnerState;复测→revalidation_queue;处方→training_intent
L5 前台:每日2分钟MCQ轻练 + 暖版看穿诊断 + 案例渐进作答
```

## 三、"全权顶尖"靠什么 —— 不是题量,是这条复利链

普通题库 = 题 + 答案 + 解析。我们的引擎差异化 = **真题踩点分值候选(431)× 验证过的赋分候选逻辑(score_assigner)× 编译知识(313深编译)× 多模型陪审校准 × 结构化错因 × 真题频次驱动的母题优先级**,且这些**通过人审与 signed artifact 治理、随真实作答复利**。

**唯一不可抄、唯一真缺的料** = **真实考生作答 × 专家裁决的判分一致性数据**(中国一建人工踩点、口径不公开,不在任何公开语料)。其余全部可抄/已建——所以"顶尖"的最后一公里**只能靠真实作答校准输入 + 人审校准**,这正是留存实验产出的东西。

## 四、装配顺序(从"料齐"到"顶尖引擎",不再缺资产,只缺装配)

1. **采分点+分值候选统一源**:training_org_analysis_yousen rubric(5年踩点分值候选)+ score_assigner(其余/变题 proposed scores)→ signed grading artifact 的候选输入(✅ 已就位,但非 official score authority)。
2. **误解模型提炼**:从 JSON analysis+logic_chain+option_reasoning 提炼结构化 misconception(映射 E 系列)——不用抽 PDF,料在 JSON(待做,§3 步)。
3. **计算 formula registry**:把 26 公式 + 网络计划公式编译成可执行判据(待做)。
4. **判分链装配**:signed artifact / bootstrap 分值候选 + score_assigner proposed scores + judge封顶 + 错因 → shadow 案例判分候选链(✅ judge 已有,接分值即可; official 需签发)。
5. **母题包编译**:按真题频次,先编 1 个高频案例母题(进度/混凝土)到深度样板(用上 1-4)。
6. **真实作答校准输入**:留存实验产出真实作答 → 进入人审边界样本池 + 判分一致性校准 → 为 shadow 解冻提供候选证据 → 沉淀为 `compiler_feedback` / 评测回归。

## 五、诚实边界
- 大量资产是 shadow(published:false/runtime OFF/WEAK_GO),消费前过治理闸;只引用不改写;authority 不冒充官方。
- score_assigner / 缺年份分值 = `engine_rule_derived`(非官方、非 signed artifact);判分器 quality_claim_allowed=false(待真实作答+人审升级)。
- **build gated on retention**(深母题数据标准 §9):装配 L1-L5 与留存实验并行,但量产扩包硬闸在留存证明后。
