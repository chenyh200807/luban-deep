# 给分逻辑(分值引擎基础)

- **日期**:2026-06-16
- **定位**:从真题反推出的**给分设计逻辑**,作为未来「**分值引擎**」(给变题/生成题确定性分配 per-point 分值)的规则基础。
- **数据来源**:`docs/数据盘点/extractions/ALL_jianzhu_case_rubric.jsonl`(**431 采分点 / 5 年 / 25 案例 / 117 小题**,经独立专家 agent 复核高准确率)
- **来源权限**:反推自佑森教育解析的踩点给分(`training_org_analysis_yousen`,≈ 踩点制),**一致性高但非官方阅卷算法**(官方口径不公开)。**生成题本无官方分值,套此逻辑分配即正确做法。**
- **配套**:与 [真题分值抽取协议](2026-06-16-真题分值抽取方法与首份验证.md) 的「踩点池封顶」判分规则成对,凑齐生成题"出题→给分→判分"闭环。

## 一、给分逻辑(7 条规则,每条带数据证据)

### R1 基本单位 = 1.0 分 / 采分点(默认)
- 证据:431 点中 **1.0 分占 67%**(291);在**非列举型里 1.0 分占 80%**(判断 47/61、改错 44/51、计算步骤 29/33、计算结果 16/20、程序 9/13、措施 10/12)。
- 规则:**每个"独立给分单元"默认 1.0 分。**

### R2 小题满分 = 3-7 分为主
- 证据:117 小题满分分布 —— 5分29 / 6分24 / 4分22 / 3分15 / 7分13(合计占 83%);另有 2/8/9/10/12 分少量。
- 案例总分:早年案例(一)(二)(三)各 20;**近年案例(四)(五)各 30**(2024/2025/2022补考均如此)。
- 规则:**小题满分按考点深度选 3-7 分**;综合/多步计算题可 6-8。

### R3 按 point_type 给分
- 证据(各类型分值众数):
  - 计算步骤(33):1分×29;计算结果(20):1分×16;判断(61):1分×47;改错(51):1分×44;程序(13):1分×9;措施(12):1分×10 —— **全部以 1.0 分为绝对众数**。
  - 列举(238):**二态**——逐项 ≤1分 148 个 / 整块多项打包 ≥2分 79 个。
- 规则:
  - **计算步骤·计算结果·判断·改错·程序·措施 → 每单元 1.0 分**;
  - **列举 → 见 R4**。

### R4 列举型二态
- ① **有限明确项列举**(如"五种机器人"):**每项 1.0 分**;
- ② **开放列举**("……还有哪些"):**整块打包 2/3/4/5 分**,按命中项数给分(见 R6)。
- 证据:列举型 1分×135 / 2分×34 / 3分×22 / 4分×14 / 5分×8(打包块分值随答案项数上升)。

### R5 0.5 分粒度 = 项数 > 小题满分时均摊
- 证据:0.5 分点(30 个)**只出现在"采分点数 > 小题满分"的小题**:如 2025案例5题1(8点/5.5分,0.5×7)、2023案例1题2(6点/3分,0.5×6)、2022案例1题2(8点/5分,0.5×7)。
- 规则:**当独立给分单元数 > 小题满分 → 每单元降为 0.5 分**(把多项塞进小满分)。

### R6 开放列举给分规则:"写出 N 项即得 N 分"
- 证据:11 处 partial_credit,**全是列举型**;文本=`写出N项即得N分`(N=3 或 5)。
- 规则:**开放列举 → 列 M 个给分点(M > N),每点 1 分,挂"写出 N 项即得 N 分"封顶到 N。**

### R7 踩点池封顶
- 证据:117 小题中 **Σ采分点=满分 109 个**(整齐)、**Σ>满分 5 个**(给分点池>满分)、Σ<满分 3 个。
- 规则:**默认 Σ采分点 ≈ 小题满分**;允许 Σ>满分(给分点池);**判分 = min(Σ命中采分点×point_score, 小题满分) 封顶**。

### 每小题采分点数(供 R2/R5 参考)
1点18 / 2点29 / 3点13 / 4点15 / 5点19 / 6点12 / 7点7 / 8点2 / 12点2 小题。**2-6 个采分点最常见。**

## 二、给分分配算法(给变题/生成题用,确定性)

**输入**:一道(案例)小题 + 其采分点列表(每点带 `type` + 若为列举则标 `项数` 与 `是否开放`)。
**输出**:每点 `point_score` + `sub_q_total_score` + 判分规则。

```
def assign_scores(sub_q):
    # 1. 数"独立给分单元"
    units = 采分点列表(计算步骤/结果·判断·改错·程序·措施 各算1单元;
                       有限列举每项1单元;开放列举=1个"池"单元)
    # 2. 定小题满分(R2):按考点深度 3-7;多步计算/综合 6-8
    total = pick_total(考点深度, units 数)
    # 3. 分配(R3/R4/R5)
    if 单元数 <= total:        每单元 1.0 分            # 常态
    else:                      每单元 0.5 分            # R5:项多塞小满分
    开放列举池 → 列 M(>N) 点各1分 + "写出N项即得N分"(R6)
    # 4. 校验(R7):Σ ≈ total;判分 min(Σ命中, total) 封顶
    return per_point_score, total, "min(Σ命中×点分, total)封顶"
```

**一句话**:给分 = **数独立给分单元个数 × 1 分,按小题满分封顶;单元超满分则 0.5/单元;开放列举挂"写N项得N分"**。生成器自己造采分点、知道单元数 → 可**确定性**套用。

## 三、分值引擎设计意图(future)

- **双轨**:
  - **真题** → **查表**:直接用 `ALL_jianzhu_case_rubric.jsonl` 抽取的真实分值(authority=佑森解析);
  - **变题/生成题** → **套逻辑**:用本文 §二算法分配(authority=engine_rule_derived)。
- **接口**:`score_assigner(sub_q_meta, scoring_points[])` → `[{point_id, point_score}], sub_q_total, judge_rule`。
- **judge 配对**:判分一律 `min(Σ命中采分点×point_score, sub_q_total)` 封顶(R7),对真题/变题统一。
- **register-before-use**:引擎若落代码,`score_assigner` 输出的分值 authority 标 `engine_rule_derived`,**不得冒充官方**;真题分值标 `training_org_analysis_yousen`。两者都≠官方。

## 四、诚实边界

1. 反推自佑森解析(教研级踩点估分),**非官方阅卷算法**;但一致性高(1.0分/单元 + 封顶,跨 5 年稳定)。
2. **生成题没有官方分值**,套此逻辑是正确且唯一可行的做法;真题则用抽取的真实分值。
3. 列举"打包块"分值(R4②)与"小题满分"选择(R2)仍有教研判断空间,不是纯机械;引擎可给默认 + 允许教研覆写。
