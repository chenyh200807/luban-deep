方向修订：首次体验正式进入 Canonical Learner State

第二权威不是 Learner State；绕开 Learner State 才会产生第二权威

正确做法不是让前端按四题答案直接决定下一站，而是把结构化结果写进现有唯一事件流，再由现有画像、处方和首页投影消费。

设计裁决：完成报告时做一次幂等批量写回；客观答题证据、用户自述偏好和系统推断分层保存。写回成功后，第二天的学习首页、问鲁班、学情与复测都从同一 Learner State 读取。

首次体验 UI

一页一题；本地 checkpoint 只负责断点恢复。完成时提交 script_version、题目作答、时长和显式偏好。

薄适配层

POST /first-run/complete

只做鉴权、大小限制、幂等键和错误语义；不算画像、不决定下一站。

FirstRunWritebackService

校验静态题版本与权威答案；写学习证据、合并显式偏好、生成低置信推断，并委托既有 home personalization / training intent。

→
同一 Learner State 读侧

第二天继续

学习首页焦点、学情报告、问鲁班教学方式、复测与会员路线说明读取同一份 durable state。

三类信号必须分层

客观作答证据

四道静态题的 question_id、canonical topic、选项、确定性 verdict、错因、时长和来源。进入 learner_memory_events.learning_evidence，单次只算 L0 observation，不直接宣称掌握。

用户显式偏好

记忆方式、答题节奏、学习时段、动力来源。合并到 profile 的 learning_preferences / support_preferences，可随时在“我的”中修改。

系统推断画像

“实战型快枪手”等组合标签只是带 provenance 与 confidence 的推断；后续行为冲突时可被覆盖，不能反向改写客观证据。

单一 authority 的硬门

唯一 ledger所有长期事件只走 `append_memory_event`，复用 dedupe、outbox 与 read-your-writes。
唯一处方下一步训练只由 canonical `training_intent` 生成，首页继续由 `home_next_step_projection` 仲裁。
唯一内容版本前端只提交 question_id 和选择；后端按注册过的 script_version 复算 verdict，不信任客户端分数。
明确禁止前端自行把“错两题”映射到某个 pack；也不把偏好选择当成“已掌握/未掌握”。
第二天回来

首页显示真实薄弱主题、建议动作和待复测，不再回到陌生 starter 状态。

继续问鲁班

表达节奏可读取显式偏好；知识判断仍来自真实证据，不靠标签猜。

查看学情

四题成为第一批可追溯证据，报告能深链回当时的问题与答案。

购买会员

Learner State 解释“你的路线还差什么”；会员资格和支付仍由 wallet/membership authority 决定。

难度评估：中等，不是基础设施重造。现有事件账本、assessment 写回、profile、home personalization、training intent、next-step 投影都能复用。新增工作主要是：注册 `first_run_diagnostic.v1`、补专用 writeback service 与 endpoint、给 4 道题补 canonical question/topic/pack 映射、前端幂等重试和真实微信 QA。工程约一个小迭代；最大的外部门是第 4 题仍缺双教研 verdict。

写回粒度怎么锁定？

A

完成报告时一次性写回（推荐）

中途恢复仍走本地 checkpoint；完整完成后幂等写入 Learner State。范围可控，已满足第二天连续性。

B

每一步都保存到服务端

支持跨设备中途续做，但需要 durable first-run session、并发控制和更多隐私/清理语义，范围明显更大。
