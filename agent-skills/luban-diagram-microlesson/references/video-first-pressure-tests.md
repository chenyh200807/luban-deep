# video-first-pressure-tests.md · 动画学习卡压力测试

> 用途:防止 skill 在新考点上退化成“套 N01 皮肤”。每次声明 video-first 样板完成前,至少用本页做一次自审。
> 原则:薄 wrapper 不造权威;胖 skill 给出方法和 gate;缺数据就停在视觉小样。

## 1. 生产前必须填的导演表

| 字段 | 必填问题 | 不合格信号 |
|---|---|---|
| `prototype` | 6+1 里它是哪一类,为什么? | 按章节选,不是按学生卡点选 |
| `main_exam_action` | 学生看完要会写/会判/会算哪一句? | 只是“了解知识点” |
| `opening_hook` | 为什么现在值得学,考试怎么用? | 第一秒直接讲定义 |
| `wrong_idea` | 学生最自然的错觉是什么? | 错项是随便编的离谱错误 |
| `anchor` | 每个事实回到哪个 card/master/source 字段? | 旁白事实没有 anchor |
| `sync_keyword` | 哪些词必须和画面同步出现? | 只有大段旁白,没有关键词时点 |
| `visual_state` | 这一 beat 画面状态怎么变? | 只是下一页/淡入/慢放大 |
| `camera_verb` | 镜头如何筛注意力? | 没有 push/spotlight/dim/trace/freeze |
| `practice_id` | 这段对应哪道练习或输出题? | 动画好看但没有题验证 |
| `acceptance_still` | 哪一帧单看也能懂? | 关键帧截图看不出教学意图 |
| `closing_echo` | 结尾如何回扣开头主线? | 答疑结束后突然停 |

## 2. 6+1 原型压力场景

### ① 时序/工序

- 场景:防水施工流程、验收流程、事故处理流程。
- 合格:步骤逐个 reveal,错步能回退,每步有前后因果。
- 失败:做成普通列表翻页,只背口诀。
- 最低证据:有 `step-reveal` still、错步题、排序/下一步练习。

### ② 构造/空间

- 场景:防水节点、钢筋锚固、后浇带、剖面层次。
- 合格:剖面/爆炸/局部放大,层色稳定,点某层能说明作用和错法。
- 失败:套 N01 网络图节点;没有可靠图元就让 LLM 文生图。
- 最低证据:有剖面 SVG 或确定性图元,题目让学生找错误层/正确构造。

### ③ 计算/图结构

- 场景:网络计划、关键线路、时差、流水节拍。
- 合格:图节点可推演,路径/计算/判断依据同步出现,改数值可重算。
- 失败:只播放答案;把最长单项、最长路径、关键线路混在一起。
- 最低证据:N01 类图解 + 改数值题 + 采分句输出题。

### ④ 判断/分支

- 场景:危大专家论证、脚手架/模板验收放行、合同变更、事故等级。
- 合格:判断树或条件卡按“对象→时点→阈值/要件→结论”分支 reveal,命中绿、淘汰暗。
- 失败:把判断题讲成知识点列表;选项只有“能/不能”。
- 最低证据:每题有条件图或判断树,选项写“对象 + 结论 + 判断依据”。

### ⑤ 对比/正误

- 场景:规范 vs 非规范、正确做法 vs 错误做法、质量通病。
- 合格:左右对照,红错绿对,点错因能落到采分表达。
- 失败:只给两张静态图,不解释为什么扣分。
- 最低证据:每个 contrast item 有 wrong/right/scoring_point_binding/warm_correction。

### ⑥ 采分点/诊断

- 场景:学生答案逐句判分、采分点命中/漏点、常见错误表达。
- 合格:答案片段逐句扫光,hit/partial/miss 颜色稳定,最后补一句采分句。
- 失败:只给标准答案,不诊断为什么没分。
- 最低证据:题目给学生答案片段,反馈指出命中/漏点/错因。

### ⑦ 数值/记忆

- 场景:纯参数、定义、规范数值、口诀。
- 合格:默认不动画化;用静态卡、表格、记忆钩子、间隔复习。
- 失败:为了统一形式强行做 Remotion 动画。
- 最低证据:说明“不动画化”的理由和复习机制。

## 3. 特殊压力测试

### 预览评审不生成 MP4

- 输入:用户只要求看 UI/UX、排版、文案、交互、学习卡效果。
- 合格:改 HTML/CSS/JSON,复用已有媒体或 still,跑 preview validator/截图。
- 失败:每次都 full render MP4,让迭代变慢且缓存复杂。

### 缺母题数据

- 输入:只有一个考点名,没有 master/card/variants/source。
- 合格:先声明“只能做视觉小样”,列出缺口,不标深母题学习卡完成。
- 失败:AI 自由编采分点、阈值、题目和看穿标准。

### 用户质疑题目

- 输入:用户说“这题是不是突兀/不对/没必要”。
- 合格:先回 basis_ref / R3/R4 / source 验证;站得住就解释并优化表达,站不住才改。
- 失败:为了顺从质疑直接删迁移题或改判据。

### 手机首屏小

- 输入:390px 截图里视频内容很小。
- 合格:普通态是 orientation-adaptive 学习舞台;竖屏不小片化,横屏/宽屏不锁成窄竖条;全屏只显示学习内容;控制层点击浮出。
- 失败:把外层容器变大,里面视频仍 contain 缩小。

### student-safe 泄漏

- 输入:HTML/练习页出现 `candidate`、`source_ref`、`P10`、`E03`、`schema_version`。
- 合格:学生包 fail;追溯字段只留源 JSON/后台/制作档。
- 失败:解释说“用户一般看不到源码”。

## 4. Quiz 梯度模板

| level | cognitive_action | visual_asset_required | answer_shape |
|---|---|---|---|
| 1 | 看见对象 | 原图高亮/对象放大 | 对象 + 结果 + 依据 |
| 2 | 识别错觉 | 错点局部/错误表达 | 错因 + 正解 |
| 3 | 复走过程 | 改数/改条件变化图 | 新结果 + 推导依据 |
| 4 | 卡边界 | 边界条件/相邻工序/临界阈值 | 档位/路径 + 为什么 |
| 5 | 换外壳 | 新工程/新图/新题干 | 不变量 + 新条件 |
| 6 | 写采分句 | 答题纸/采分格 | 采分原子完整 |

## 5. 完成判定

一张 video-first 卡只有同时满足下面条件,才算“可以给用户看下一轮”:

- `validate_schema_drafts.py` 过。
- `build_lesson_narration.mjs --print` 过,closing claim 也被 anchor 检查。
- `validate_video_first_preview.mjs <topic>.rendered.html <topic>.practice.html` 过。
- `validate_learning_stage_runtime.mjs <topic>.rendered.html` 过,覆盖 390 竖屏首屏、390 播放态、844x390 横屏、1024x720 宽屏和 390 theater 控制层。
- 390px 竖屏普通页截图、横屏/宽屏普通页截图和 theater/fullscreen 截图无横滚、无小片化、无控制遮挡核心内容。
- 练习页能从第一题走到结果页,且至少一道输出题训练采分句。
