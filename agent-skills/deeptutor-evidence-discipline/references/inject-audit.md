# 注入片段 · 审计类

**用于**:只读核验、覆盖度检查、代码/资产/文档审计、「查一下有没有问题」。

**主要封死**:S3 局部冒充全量、S4 中途停止。

---

## 可粘贴片段

```text
本任务是只读审计,不改任何文件。

【分母纪律】
- 动手前先测绘全集:总共有 N 个候选,你实际检查了哪 M 个。
- 结论必须写出 N 和 M。M < N 时,结论只能写"就这 M 项而言",禁止全称词
  (整体/都/全部/基本没问题/未发现问题)。
- 计数以数据为准,不以任务说明为准。任务说明里的数字与实际扫描结果冲突时,
  报告冲突,不要迁就说明。

【覆盖纪律】
- 除了我点名的项,必须额外跑一轮 adversarial expansion:sibling path、
  异常路径、重入、断网重试、并发、边界值。只查点名项 = 未完成。
- happy path 通过不等于该能力通过。至少把正常路径与恢复/失败路径分开结论。

【证据纪律】
- 每条因果 claim 必须锚到 file:line 或可复现命令。写不出锚点的判断,
  显式标为「推断」。
- 禁止主观印象式表述(看起来没问题 / 应该可以 / 基本合理)。

【交付形状】
1. 分母与覆盖面(N / M / 未覆盖清单)
2. 发现,按严重度排序,每条带 file:line 锚点
3. 未发现问题的项,单独列,不要和"已确认无问题"混写
4. 我需要现在做什么(谁/做什么/什么算通过)
5. 你不确定的、被阻塞的、以及你认为我没问到但该知道的

【tripwire — 命中即停并报告,不要继续】
- 你需要改文件才能继续验证
- 你无法用一条命令复现我描述的现象
- 你发现真实数量与任务说明不符
```

## 这份片段封死了什么(实录)

| 逃逸路径 | 实录原文 |
|---|---|
| 只查点名项就给全称结论 | 「只核对用户点名的 fix,就给『基本没问题』。原因:没有继续往 sibling path / 第六问题 / 新漏洞追」 |
| happy path 冒充全量 | 「只读前端审查只看 happy path 单题流,就把 retest 重构当通过。原因:没继续查重进、断网重试、答完再进的恢复语义」 |
| 分母混淆 | 「把 40/41/60/501/2,112 混为一个『总池』。修复:每次显式标出交付表面、资产池与理论池分母」 |
| 数量靠猜 | 「surface anchors 数量按任务说明猜定。原因:没有读取 review items。B02 实际为 10、S01 为 15,计数不符时以数据为准」 |
| 主观印象 | 「审查写成主观印象。原因:没落到文件/字段/命令复现」 |
| 取证完没收束 | 「只做完证据收集,没有把用户要求的固定结构结论交付出来」 |
