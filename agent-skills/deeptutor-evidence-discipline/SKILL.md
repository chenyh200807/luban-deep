# DeepTutor Evidence Discipline

本 skill 只治一个病。它不是 checklist 集合,是**证据面与结论强度之间的对齐规则**。

来源:`~/.codex/memories/MEMORY.md` 里 351 条实录失败的聚类结果。其中「第二权威 /
authority 分裂」一族(约 48 条)归
[deeptutor-authority-debugging](../deeptutor-authority-debugging/SKILL.md),
本 skill 不重复持有那个 authority。

---

## 目标不是「预知一切」

**明确否定一个错误的起点**:本 skill(以及任何方法论 skill)的目标**不是**在动手前
预知全部问题。那个目标理论上不可能、成本发散,而且**最危险的是它制造虚假安全感**——
一个自称能预知的系统,比一个承认自己会漏的系统更危险,因为前者让人停止建检测机制。

真实目标是**分层拦截**:

| 问题类型 | 该被什么挡住 | 现实目标 |
|---|---|---|
| 低级 / 常识 / 经验型 | **嗅觉**(看一眼就不对) | 挡住 ~90% |
| 结构性 / 深层 | **算子**(提问推理) | 挡住一部分 |
| 新颖 / 未知 | **体系**(定期识别 + 快速恢复) | 不求提前,求快发现 |

**遇到问题不可怕。没有定期识别问题的体系才可怕。**

## 本 skill 的分层与失效条件

进化合同的 canonical 在 [agent-skills/README.md · Evolution Protocol](../README.md#evolution-protocol--所有-skill-共用的分层与进化合同),此处不复制正文。
分层判据不是「重要性」(主观),是「**这条知识什么时候会失效**」(客观)。

| 层 | 内容 | 失效条件 | 时间尺度 | 改动纪律 |
|---|---|---|---|---|
| **L0** | 三大原则(AGENTS.md) | 永不 | — | 不在本文件 |
| **L1 内核** | 三个算子 + 一个母病 + 证据阶梯 | 计算的物理本质改变 | 十年 | **改需论证**:必须给出一个现有算子答不出的真实案例 |
| **L2 嗅觉** | 嗅觉库(模式 → 直觉) | 语言/框架惯用法改变 | 年 | **持续增长**,每次踩坑追加 |
| **L3 体系** | 四时点 + Tripwires + 层盲区表 | 团队规模/工具链改变 | 年 | 持续调 |
| **L4 实例** | 四条推论、`references/*` 里的本仓命中 | 本 repo 代码改变 | 周/月 | **随时过期,过期即删** |

> **L4 会过期是正常的,不要为了保住它而不改代码。** 反过来,L1 被频繁修改是危险信号——
> 说明当初提炼错了层。

## 一个母病

> **用不足以支撑该结论的证据面,产出了那个结论。**

注意它**不是**"撒谎",也不是"没检查"。绝大多数实录里,检查确实做了、命令确实跑了、
输出确实是绿的——**病在于那个绿色所覆盖的范围,小于被宣称的范围**。

所以本 skill 的唯一动作是:**在写下结论之前,先写下这个结论需要的证据级别,再问手上
的证据够不够到那一级。** 不够就降级结论,不是升级证据的解释。

## L1 · 三个内核算子(动手前问,答案改变行动)

算子**不是规则**(if-X-then-Y,只在见过的场景触发),**也不是箴言**(方向对但无判据)。
它是**能在任意场景机械提出、且有否证条件的问题**。

### 算子一 · 这件事的不可约束缚是什么?

不是「有什么困难」,是「**什么是物理上/结构上不可能改变的**」。
**找到它,所有试图绕过它的方案当场出局——不需要实验,不需要争论。**

否证条件:答案必须是一个**具体的物理/结构事实**。说不出来 = 还没找到,不许动手。

实例(2026-07-26):`GIL` / `进程边界` / `SQLite 写锁是 per-file` / `丢失的记录不在文件里`。
仅凭「写锁跨进程」+「生产 workers=2」两条,就推翻了一份高质量专家报告的核心结论,
且**没做任何新调研**。

### 算子二 · 我要的答案,能从我手上的东西里推出来吗?

**可测性问题,先于测量。** 答案是「不能」时,正确动作是换源或写 BLOCKED,不是硬推。

否证条件:**二值**。能/不能。

实例:「历史丢了多少」→ 查 `users.json` 结构上无效(丢的不在里面);
「生产 worker 数」→ 查 `Dockerfile` 无效(那是默认值)。
**这个算子最大的价值是「预测错了也算赢」**——2026-07-26 它预测「BUSY 可推导」被证伪,
但正因为先问了,才省下一次注定白费的日志调查,并直接指向「改前向埋点」。

### 算子三 · 我要改/删的东西,正在提供什么我没声明的保证?

否证条件:答案是**可穷举的列表**。列不出来 = 没查。

实例:`async def` 无 await 在提供「事件循环上不可被抢占」= 一把免费互斥锁;
同步阻塞在提供 admission control;`indent=2` **什么也没提供**——所以只有它能删。

> **`less is more` 只会催你去删。算子三告诉你什么时候不能删。**

**当前样本量 = 2**(一次反推 + 一次前瞻)。**待第三次在完全冷启动的层上验证。**
四个预测的完整对照(含被证伪的那条)见 `references/operator-trial-log.md`。

## L2 · 嗅觉库(看一眼就该起疑,不需要推理)

算子要花时间推理,**嗅觉是零成本的**。它负责挡住 90% 的常识型问题。
**每次踩坑追加一条,这是本 skill 增长最快的一层。**

| 看到这个形状 | 立刻起的疑心 | 一句话验证 |
|---|---|---|
| `except Exception:` 包着**数据写入** | 失败会静默,数据丢了没人知道 | 这个 except 里有 log 吗? |
| `async def` 里**一个 await 都没有** | ①签名在撒谎 ②可能藏着"不可被抢占"的保证 | 它调的东西释放 GIL 吗? |
| `threading.Lock` 出现在**多进程服务** | 跨不过进程边界,等于没锁 | `UVICORN_WORKERS` 是几? |
| `sqlite3.connect` 后没设 `journal_mode` | 默认 `delete` → **读写互斥**(WAL 才能并发) | `PRAGMA journal_mode` 实测是什么? |
| **用 `grep「有没有写 X」` 推断「运行时 X 的值」** | **跳过了语言/框架的默认值层** | 起一个进程 `PRAGMA`/`print` 实测一次 |
| **全量读写**一个会随用户增长的文件 | 成本随规模爆炸,且常在锁内 | 10 倍用户时这里多久? |
| `json.dumps(..., indent=)` 用于**机器数据** | 纯浪费(实测 -83% 序列化 / -46% 字节) | 这个文件有人眼读吗? |
| 拿**退出码 / CI 绿**当「完成」 | E0/E1 冒充 E4 | 目标环境的终态验过吗? |
| 两个数字**相减**得出结论 | 分母可能不是同一个池 | 两边按哪个键对齐? |
| 新加了 gate/门,没人验证它**真在跑** | 可能在 ZERO workflows 里空转 | CI 里 grep 得到这一步吗? |
| 「只需要接线就好了」 | 过度声称高发区 | join 键存在吗?先只读验 |
| 单轮 LLM 测试通过 | 非确定性,单轮可能是运气 | 连跑 ≥3 轮一致吗? |
| 部署脚本 exit 0 | 不等于容器在跑新代码 | 容器内 grep 对 SHA 了吗? |
| **改一个设置,没检查它会不会连带改别的** | 设置之间有隐式耦合(实测:`journal_mode=WAL` 会把默认的 `synchronous` 从 FULL 降到 NORMAL) | 改前改后各 dump 一次全部相关 PRAGMA/配置 |
| **探针里带了参数,却拿输出当"生产值"** | 观测工具污染观测结果(实测:探针写 `timeout=2` 导致读出 `busy_timeout=2000`,与生产无关) | 探针有没有覆盖被观测的量? |

## L3 · 证据阶梯

结论强度必须 ≤ 证据强度。跨级即为本病。

| 级 | 证据面 | 只能支撑的结论 |
|---|---|---|
| E0 | 命令退出码 0 / 脚本跑完 / 无报错 | 「该命令执行了」 |
| E1 | 单元测试绿 / CI 绿 / gate 绿 | 「被这些用例覆盖的形状没退化」 |
| E2 | metrics / 日志 / dashboard / snapshot | 「观测面此刻这么显示」 |
| E3 | 目标环境终态直查(容器内 SHA、DB `mode=ro` SELECT、持久化 messages) | 「目标环境当前是这个状态」 |
| E4 | 真实入口的真实行为(真机 / public endpoint / 用户可见路径) | 「用户会看到这个」 |
| E5 | 独立复核 + 可证伪 + 可重复 | 「这件事成立」 |

**"修好了 / 已上线 / 没问题 / ready"是 E4-E5 级结论。** 用 E0-E2 支撑它,就是本病。

## 四个形状

### S1 · 弱证据升级(最高频,约 80 条实录)

把 E0/E1 直接当 E4/E5 用。

**静态指纹**:结论里出现「完成 / 修好 / ready / healthy / GO / 已上线」,而证据栏里
只有退出码、测试数、gate 名。

实录:
- 「脚本成功即称发布完成」——没核跨层 lineage / health / 真实场景
- 「候选 survived 或 CI 绿就被写成 ready / human signoff」——把"未被当前证据推翻"
  误写成"已获授权"
- 「TRUSTED metrics 或 WS PASS 就写 release-ready」——未读 direct gate
- 「18/18 输出成功就称所有维护完成」——没核 INDEX 快照、命名迁移、链接同步、幂等重跑
- 「事实看似正确就签发」——把 factual correctness 和 provenance completeness 混为一门

**判据**:测试绿证明的是"这些用例没红",不是"这个能力对"。行为质量、真机可见性、
持久化终态,单元测试**结构上证不了**。

### S2 · 旁证替代主证(约 21 条实录)

主证不可达时,用一个恰好可达的面顶上,并且不标注这个替换。

**静态指纹**:主证获取失败(connection refused / 凭据缺失 / 字面 `${VAR}` 未展开)之后,
结论**仍然产出了**,而不是停在 BLOCKED。

实录:
- 「`psql` 收到字面 `${DB_URL}` 后仍用 metrics、缓存、REST 登录或样例补位」
- 「`127.0.0.1:8001/metrics` connection refused 后仍以 old/latest wrapper 或 benchmark
  做 current release truth」
- 「本地 `.env` 有部分观测凭据,就误以为 BI/member 行为 authority 足够」——把
  observability surface 当 member/BI authority
- 「余额百分比接近 100% 就判断未扣费」——没审账本历史 / plan entitlement / identity mapping

**判据**:**主证不可达 → 结论写 `BLOCKED`,不是换一个证据面继续。** 观测面回答的是
"系统怎么显示",账本回答的是"事实是什么",这两个问题不可互相替代。

### S3 · 局部冒充全量(约 14 条实录)

只覆盖了被点名的部分 / happy path / 单一分母,却给出整体结论。

**静态指纹**:结论是全称的(「整体 / 都 / 全部 / 基本没问题」),而执行段只出现了
用户点名的那几项。

实录:
- 「只核对用户点名的 fix,就给『基本没问题』」——没往 sibling path / 第六问题追
- 「只读前端审查只看 happy path 单题流,就把 retest 重构当通过」——没查重进、断网重试、
  答完再进的恢复语义
- 「把 40/41/60/501/2,112 混为一个『总池』」——没标出交付表面 / 资产池 / 理论池分母
- 「受控浏览器不能完整读取微信软文正文却写成已全量审计」

**判据**:全称结论必须显式声明**分母**和**未覆盖面**。写不出未覆盖面,说明没测绘过
边界,该结论降级为"就点名项而言"。

### S4 · 中途停止(约 24 条实录)

证据齐了,但没走完到可执行的那一步;或者反过来,给了结论没给依据和选项。

**静态指纹**:交付里有大量文件/命令/数字,但没有"所以现在该做什么、谁做、什么算通过"。

实录:
- 「回答只复述文件/工具输出,没有把它们翻译成『现在该怎么决策』」
- 「只做完证据收集,没有把用户要求的固定结构结论交付出来」
- 「战略/产品/架构问题只回一段短 close-out」——founder-level decision support 当成了
  普通执行汇报

**判据**:取证阶段和结论阶段要拆开,但**两个都要交付**。战略类问题按
结论 → 依据 → 选项 → 推荐 → 下一步 → 红线 收束。

## 四条推论(2026-07-26 战役实证追加)

初版四形状是「证据不足以支撑结论」的四种样子。下面四条是同一母病在**更隐蔽位置**的变体,
每条都有实战代价。

### 推论 1 · 多个权威给出矛盾事实时,**不要选一个信**

两位顶尖专家对「生产 `UVICORN_WORKERS` 是几」给出 1 和 2 两个答案。主控独立核后发现:
**两人都只有旁证**(一个读 `Dockerfile` 默认值,一个读某配置),谁都没读生产容器 env。

> 矛盾不是"有一方错",而是"**双方都没到 E3**"。此时正确动作是自己去取主证,
> 不是在两个旁证之间投票。取不到就写 BLOCKED。

### 推论 2 · 你不能用一个被污染的数据源,测量它自己的污染量

要判定「账号数据历史上丢了多少」,查 `users.json` 是**结构上无效**的——
**丢掉的记录不在里面**。必须有独立的事件源(注册日志 / 另一侧的账本)且两侧**能按同一个键对齐**。

> 对齐失败时(两个池分母定义不同、缺共同键),诚实结论是「**无法回溯判定**」,
> 而不是拿两个数相减。相减 = S3 分母混淆。
> 回溯不了就转**前向验证**:修复后加对账,让未来可测。

### 推论 3 · 测试通过 ≠ 测试有判别力

新写的并发测试 5 passed。但**测试自己也需要被证伪**:把代码还原成修复前,
测试必须**变红**,而且红的原因要精确(报「丢更新 期望160实得44」,不是报「文件损坏」)。

> **每个声称"证明了修复有效"的测试,都要双向跑:修复版绿 + 还原版红。**
> 只跑绿的那一半,证明的是"测试能跑",不是"修复有效"。

### 推论 4 · 减法也可能引入并发 bug

`less is more` 默认优先删。但这轮发现:5 处路由的正确性**依赖一个没人写下来的副作用**——
「`async def` 且无 await ⇒ 在事件循环上不可被抢占」= 一把**意外的免费互斥锁**。
删掉 `async` 会把这把锁一起删掉,读-改-写窗口第一次真实存在。

> 删之前问:**这段代码有没有在提供某个没被声明的保证?**
> 并发语义、执行顺序、原子性,常常挂在"看起来只是写法"的东西上。

## 四个动作时点

在这四个时刻**必须**跑一次上面的阶梯对照。其余时候不必。

### T1 · 声称「完成 / 修好 / 已修复」之前

写出三行,写不出就不许说完成:

```text
claim level:        我在声称第几级(E0-E5)
evidence level:     我手上最强的证据是第几级
gap:                差的那几级由什么承担;不承担就降级 claim
```

后端改 Python 未 rebuild、前端未 DevTools 上传 = **未部署**,claim 封顶 E1。

### T2 · 声称「查过了 / 没问题」之前

```text
分母:        我检查的是 N 项里的哪 M 项
未覆盖面:    明确列出没查的
全称资格:    M < N 时,结论只能写"就这 M 项而言"
```

### T3 · 交付结论之前

```text
证据 → 结论的那一跳,是否跨了阶梯?
结论落到动作了吗(谁 / 做什么 / 什么算通过)?
坏消息写了吗(未做的、被阻塞的、我不确定的)?
```

### T4 · 写 subagent prompt 时

把本 skill 的约束**前置注入**,而不是等它犯错再纠正。四类任务的可粘贴片段见
`references/`:

- 审计类 → [inject-audit.md](./references/inject-audit.md)
- 判断类 → [inject-verdict.md](./references/inject-verdict.md)
- 发布类 → [inject-release.md](./references/inject-release.md)
- 取证类 → [inject-forensics.md](./references/inject-forensics.md)

这四份是本 SKILL.md 的**投影,不是第二权威**。判据改动只改本文件,再同步投影。

### 层盲区表(供 Stop Gate「层盲区」一栏查表)

- asyncio / 并发 → [blindspot-asyncio.md](./references/blindspot-asyncio.md)(16 项,2026-07-26 异源+本地双路侦察)

写「层盲区」时**查表,不要现编**。表里没有的层,如实写「该层尚无指纹表」,并作为下一轮
盲区侦察的候选——这比编一句「注意并发安全」有用得多。

## Tripwires(执行中命中即停,不要继续)

禁令是静态的,覆盖不到没想过的岔路。这些是动态自检点:

```text
· 主证不可达,而我正准备换一个证据面继续  → 停,写 BLOCKED
· 我要新增字段 / router / fallback 才能让它工作  → 停,先过 authority-debugging
· 我需要在两个身份空间之间建映射才能完成  → 停,先只读验 join 可行性
· 我发现的"根因"需要改 3 个以上模块  → 停,根因可能判错了
· 我无法用一条命令复现被报告的现象  → 停,先复现再定位
· 结论里出现全称词,而我只查了被点名的项  → 停,补分母或降级结论
```

实录佐证:2026-07-21 采分点一役,在写第一行代码前派只读 GATE 验 join 可行性,结论
"接不了"——拦下了一次会把 A 题采分点安到 B 题上的内容漂移事故。**那次真正的交付是
两次翻车没有落地成代码。**

## 无法验证的技术结论

当结论依赖本 repo owner 无法独立验证的底层语义(asyncio 调度、锁与事务、GC 时机、
流式协议),不要求"讲懂原理",要求**可观察的证伪条件**:

```text
[结论]                            一句话
[如果这条错了,线上会表现为什么现象]  具体到可观察指标或用户可见行为
[最便宜的证伪实验]                  一条命令或一个指标
```

这把"撞过才知道"的遭遇驱动,换成一个提前布下的观察哨。

## 与其他 skill 的边界

- 「同一业务事实有两个 writer/reader」→ [deeptutor-authority-debugging](../deeptutor-authority-debugging/SKILL.md),不在本 skill。
- 「测试怎么写、怎么先写复现测试」→ [deeptutor-test-verification-gate](../deeptutor-test-verification-gate/SKILL.md)。
- 「发布五层核验的具体命令」→ [deeptutor-release-launch-gate](../deeptutor-release-launch-gate/SKILL.md)。

本 skill 只回答一个问题:**手上这份证据,配不配得上我准备写下的那句话。**
